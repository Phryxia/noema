# 2026-08-16 문장에서 단어 반자동 추출

## 문제

문서 → 문장 추출의 대칭으로 문장 → 단어 추출이 필요했다. 사양이 문장 추출과 거의 같아, 그대로 베끼면
카드 연결 리스트·포커스 이동·Backspace 판정이 두 벌이 된다. 반면 다른 점도 분명했다.
카드가 `textarea`가 아니라 inline `input`이고, 분할 트리거가 3연속 개행이 아니라 Enter이며,
`trim`을 하지 않고, 제출 결과를 단어별로 색칠해 보여줘야 했다.

추출 휴리스틱은 처음부터 어려웠다. 문자 클래스가 바뀔 때 자르되 한자→히라가나만 예외로 붙이고,
전각·반각을 다르게 보고, `々`와 장음표기를 특수 취급하고, 숫자는 `+3.1e-4`처럼 한 덩어리로 남겨야 했다.

저장 쪽에서는 `DocumentToSentence` 하나뿐이던 "단어 관계가 아닌 유형"이 둘이 되면서
`type !== 'DocumentToSentence'`로 흩어져 있던 판정이 전부 틀린 코드가 됐다.

## 해결

- `extraction/extractWords/`: 전처리(개행 삭제, `\t+`→공백 1개) 후 한 번 훑으며 자른다.
  ASCII 숫자 자리에서 sticky 정규식으로 JS 숫자 리터럴을 먼저 먹고, 아니면 `스크립트 + 폭` 클래스를 비교한다.
  스크립트는 `\p{Script=...}`를 목록 순서로 시도하고 지연 생성한 정규식을 캐시한다. 폭은 `Fullwidth/Halfwidth Forms` 블록 소속으로 정한다.
  이 블록이 정확히 "폭 변형 짝이 있는 문자"라 `０0` 분리와 반각 가나 분리가 한 규칙에서 나온다.
  소수점 뒤 숫자를 요구하는 것만 사양에서 의도적으로 벗어났다. `3.`을 삼키면 문장 끝 마침표가 숫자에 붙는다.
- 공용화를 먼저 하고 새 기능을 얹었다. `sentenceCardList.ts` → `cardList.ts`(타입 `Card`/`CardList`),
  `useSentenceCards` → 요소 타입 제네릭 + 도착 캐럿 주입의 `useCards`, 가로 화살표 판정과 Backspace 판정은 `extraction/` 최상위로.
  `useSentenceCards`는 `\n\n\n` 분할만 얹은 얇은 래퍼로 남겼다. 기존 vitest가 회귀 감시자였고 전부 통과했다.
  `caretGeometry`의 픽셀 x 측정은 `input`에 시각 행이 없어 `SentenceCard/`에 그대로 뒀다.
- `WordField`에 `inputRef`/`onKeyDown`/`onKeyUp`/`isInline`을 더했다. `SentenceField`가 `rows`/`textareaRef`를 받은 것과 같은 방식이다.
  `isInline`은 `width: 100%`를 풀고 `field-sizing: content` + `min-width`를 준다. `WhitespaceEcho`가 이미 붙어 있어 공백만 든 카드도 보인다.
- Enter 분할은 조각을 버리지도 `trim`하지도 않는다. 그래서 "맨 뒤에서 Enter → 빈 카드 추가"가 별도 규칙 없이 따라온다.
- `SentenceToWord`는 인덱스를 새로 만들지 않았다. `wordId`(WordExplain용)와 `sentenceId`(D2S용)를 그대로 타므로 `DB_VERSION`은 10 그대로다.
  대신 두 서비스가 인덱스 결과를 `type`으로 거른다. 덤으로 `hasWordReferences`/`replaceWordReferences`가 이 유형을 자동으로 포함해
  추출된 단어를 지우면 대체 단어를 요구하고, 개명하면 관계가 따라온다.
- 흩어진 리터럴 비교는 `NonWordRelationTypes` 집합을 보는 `checkIsWordRelation` 하나로 모으고 `deleteRelation`도 그것을 쓰게 했다.
- `extraction` 대표 표현 토큰을 `{ child, parent }`로 일반화해 문장 추출(문장, 문서)과 단어 추출(단어, 문장)이 7:3 영역을 나눠 쓴다.
  `D2sTable` → `PairTable`(열 주입), `D2sRelationPage` → `PairRelationPage`(라벨된 참조 줄 주입)로 일반화했다.
- 결과 모달의 행 색은 `QnaTable.module.css`에 갇혀 있던 톤 3줄을 `shared/RowTone.module.css`로 빼서 나눠 쓴다.
  라벨은 `relation/batch/getOutcomeLabel.ts`로 뽑았다. 다만 `중복`의 뜻은 다르다. 배치 모드는 관계 중복이고 여기서는 단어가 이미 있다는 뜻이다.
  진입 조건이 관계 0건이라 관계 중복은 생길 수 없어, 사용자가 알고 싶은 것은 단어의 신규 여부다(사용자 확답).
- `SentenceWords`는 `isExtracting`을 관계 건수보다 먼저 본다. 제출로 관계가 생기는 순간 편집기와 모달이 언마운트되기 때문이다.

## 남은 것

- `/relation/<id>`에서 이 관계를 수정할 길은 없다. 삭제만 있다.
- 검증: vitest 115개(신규 `extractWords` 13개), tsc, eslint, prettier 통과.
  playwright headless로 추출 결과, 좌우 화살표 이동과 첫/마지막 카드 무동작, Enter 분할과 끝에서의 빈 카드 추가,
  Backspace 병합·삭제, 같은 값 카드의 1회 삽입, 결과 모달의 초록/주황, 닫은 뒤 `연관 단어` 표 전환,
  `/relations`의 `단어 추출` 표현, 단어 삭제 시 대체 다이얼로그와 교체 후 관계 추종을 확인했다.
- 곁다리로 개별 문장 페이지의 React key 중복 경고를 고쳤다. `SentenceWriter`와 `SentenceDocuments`가 둘 다 `key={sentenceId}`였다.
