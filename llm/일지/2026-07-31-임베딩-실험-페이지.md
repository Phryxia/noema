# 2026-07-31 임베딩 실험 페이지

## 문제

[기획](../../기획/탐색-임베딩실험.md)대로 `/lab/embedding`에 탐색과 거의 같은 페이지를 만들되,
출제기를 온라인 베이지안 임베딩 모델로 교체할 수 있어야 했다. 쟁점은 세 가지였다.
탐색 훅(`useExplore`)의 출제·유형·질의 키가 하드코딩돼 있었고,
무관계(0) 신호를 만들 "넘어가기"는 DB에 아무것도 남기지 않아 재학습 시 신호가 소실되며,
매 학습 스텝마다 전체 로그를 재평가하는 궤적 계산이 O(N²)라 UI를 블로킹할 수 있었다.

## 해결

**훅 복제 대신 옵션 주입.** `useExplore(isEnabled, options?)`에
`fixedTypes`(체크박스·localStorage 생략), `pickQuestion`, `queryKey`(react-query 캐시 분리), `onSaved`를 열었다.
기본값이 기존 경로와 동일해 탐색 페이지는 호출부 무변경이다. 실험 페이지는 `useEmbeddingLab`이
선택 모델을 ref로 들고 `pickLabQuestion`(모델 없으면 기존 랜덤 출제 폴백)과 `onSaved`(온라인 학습 + 궤적 추가)를 주입한다.
`ExploreForm`, `AnswerSection` 등 화면 컴포넌트는 전부 그대로 재사용했다.

**넘어가기 대신 무응답 제출.** 이항 공통점/차이점도 `WordsUsage`처럼 빈 문자열 제출을 허용하고
`answer: null`로 정상 적재하도록 스펙을 바꿨다(사용자 확답). `checkIsAnswerReady` 완화와
`createNewRelation`의 `requireTarget` 제거, 타입 nullable화가 전부였다.
qna의 `hydrateQnaEntries`와 `answer` 인덱스는 `WordsUsage`의 null 선례를 그대로 타서 무변경, DB 버전 증가도 없다.

**시간 예산 청크.** `runExperiment`는 스텝 수가 아니라 `performance.now()` 기준 약 12ms를 넘길 때만
`setTimeout(0)`으로 양보해 진행률을 갱신한다. 모델 임베딩은 nodeId 키의 `Map`으로 들고,
전 차원 모델을 localStorage(`lab/embedding/models`)에 유효숫자 6자리로 절사 저장한다.
궤적은 메모리에만 있어 재진입 시 비고, 이후 응답마다 다시 쌓인다.

## 남은 것

관계 로그가 수천 건을 넘어가면 매 스텝 전체 평가가 느려질 수 있다.
그때는 평가 표본 상한(예: 2000쌍 고정 무작위 표본)을 두거나 Web Worker로 옮긴다.
