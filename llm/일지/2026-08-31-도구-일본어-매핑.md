# 2026-08-31 도구 일본어 매핑

## 문제

일본어 단어를 넣을 때마다 다국어 매핑 탭에서 언어 이름 세 개를 손으로 적고, 만들어진 관계 여섯 개 중 절반을 버리고 있었다. 열 구성과 쓸 방향이 매번 같으므로 그 둘을 고정한 탭이 필요했다.

- 헤더 행을 `일본어`, `読み仮名`, `한국어`로 고정한다. 편집할 수 없고 열도 3개로 고정된다.
- 관계를 `일본어->한국어`, `일본어->読み仮名`, `한국어->일본어` 셋으로 줄인다. `読み仮名->일본어`는 만들지 않는다.

## 해결

### 통합 범위

`tools/i18n/`을 `tools/mapping/`으로 옮기고 설정 주입식 `MappingTool` 하나로 합치는 안을 먼저 세웠으나, 사용자가 기존 경로·이름을 그대로 두고 `tools/jp/`만 얹는 쪽을 택했다. 대신 복붙이 남지 않도록 공유 가능한 단위 전부에 선택 인자를 더해 재사용했다.

- `computeMappingTuples(matrix, columnPairs?)`: 열 순서쌍 목록을 받는다. 없으면 종전대로 모든 순서쌍을 j-major·k-inner 순으로 만든다. 이 순서를 지킨 덕에 기존 테스트 5건이 그대로 통과했다.
- `checkMappingReady`, `submitI18nMapping`도 같은 인자를 넘긴다.
- `useI18nMappingTool(options)`: `createInitialMatrix`와 `columnPairs`를 받는다. 일본어 탭이 이 훅을 그대로 쓴다.
- 결국 `tools/jp/`에 남은 것은 상수 두 개, 초기 행렬 생성기, 화면 셸뿐이다.

컴포넌트를 `I18nMappingTool`/`JapaneseMappingTool`로 나눈 덕에 탭 전환 시 React가 언마운트해 행렬 상태가 섞이지 않는다. 한 컴포넌트에 설정만 갈아끼웠다면 같은 자리·같은 타입이라 상태가 살아남아 `key`가 필요했을 지점이다. i18n에서 2열로 만든 행렬이 jp로 넘어오면 세 번째 헤더가 `undefined`가 된다.

### 고정 헤더

`MatrixField`의 prop을 `createHeaderPlaceholder`에서 `header: MatrixHeaderOption`(편집 가능 + placeholder 생성기 / 고정) 하나로 바꿨다. 열 크기 조절 가능 여부를 따로 받지 않고 `header.isEditable`에서 유도한다. 헤더 라벨이 고정이면 새 열의 이름이 없으므로 열 추가가 정의되지 않는다. 두 prop을 두면 불가능한 조합이 타입으로 표현된다.

고정 헤더 셀을 `WordField isEditable={false}`로 그리는 안은 기각했다. readOnly `input`도 `FOCUSABLE_SELECTOR`의 `input:not([disabled])`에 걸려 모달을 닫을 때 `focusFirstElement`가 헤더를 잡고, `focusCell`의 평면 인덱스(`querySelectorAll('input')`)도 어긋난다. input이 아닌 `<strong>`이어야 한다.

`.header input { font-weight: 700 }`은 그대로 뒀다. pico가 `.pico input`에 `font-weight`를 직접 주므로 input은 부모에서 상속받지 못한다. 이 규칙을 `.header`로 옮기면 다국어 매핑의 편집 가능 헤더가 굵기를 잃는다. 정적 라벨용으로 `.headerLabel`을 따로 더해 input과 같은 안쪽 여백·테두리 폭을 줬다. 측정값은 라벨 59px, 입력칸 59.375px로 테두리 반올림 차이만 남는다.

### 커서와 버튼의 하한

`computeMatrixNavigation`에 5번째 인자 `firstRow`(기본 0)를 더해 `moveBackward`·`moveVertical`의 하한으로 썼다. `moveForward`는 상한만 쓰므로 손대지 않았다. 기본값 덕에 기존 호출부와 테스트 17건이 무수정이다. 대안으로 `MatrixField`가 `value.slice(1)`을 넘기고 결과를 `+1` 하는 방법이 있었으나, 오프셋 산술이 테스트 밖에 남아 기각했다.

행 삭제 버튼의 `disabled={rowCount === 1}`은 고정 헤더에서 틀린다. 헤더 행에는 버튼이 없으므로 데이터가 1행만 남아도(`rowCount === 2`) 활성이고, 누르면 헤더만 남는다. `rowCount <= firstEditableRow + 1`로 일반화했다. `aria-label`의 번호도 데이터 행 기준으로 보정했다. `resizeMatrix.ts`는 손대지 않았다. `addRow`가 `matrix[0]`의 열 수를 따르므로 고정 3열에서 그대로 맞는다.

그리드 트랙은 열 조절이 없을 때 후행 `10px min-content`를 빼고, 열 삭제 버튼이 놓이던 두 번째 행 트랙을 `10px`에서 `0`으로 줄였다. 트랙을 그대로 두는 안은 빈 `min-content`가 0이 되어도 옆의 `10px`이 사공간으로 남는다. 선행 트랙 2개는 유지해야 셀의 `+3` 오프셋이 산다.

`MatrixField.tsx`가 이미 170줄·함수 119줄이라 분기를 얹기 전에 `MatrixCell`, `MatrixControls`, `useMatrixNavigation`으로 갈랐다. JSX에서 셀을 컨트롤보다 먼저 렌더하는 순서는 유지해야 한다. 모달을 닫을 때 `focusFirstElement`가 문서 순서상 첫 요소를 잡으므로, 고정 헤더에서 첫 input이 데이터 첫 칸이 되려면 이 순서가 필요하다.

### 탭 판정

`validateSearch`와 `ToolsPage`가 같은 유효값 판정을 중복하므로 `tools/toolsTab.ts`의 `resolveToolsTab`(무효값이면 `order`) 한 곳으로 모으고, `ToolsTab` 타입 정의도 라우트 파일에서 옮겼다. 두 호출부가 모두 "무효면 순서화"를 원해서 타입가드보다 이 형태가 짧다.

### 확인한 것

playwright로 `?tab=jp` 직접 진입, 무효 쿼리의 순서화 낙하, 탭 전환 시 각 탭의 초기 행렬 복귀, 헤더 행으로 ArrowUp·ArrowLeft 진입 불가, 열 조절 버튼 부재, 데이터 1행에서 행 삭제 비활성, 모달을 닫은 뒤 첫 데이터 칸 포커스를 확인했다. 관계 수는 세 칸을 다 채우면 3개, 일본어+한국어만이면 2개, 일본어+`読み仮名`만이면 1개, `読み仮名`만이면 제출 불가다.

## 남은 것

- 고정 헤더 세 단어는 빈 열이어도 매 제출에서 `upsertWord`로 생성된다. 다국어 매핑의 기존 사양("헤더 포함 모든 비어있지 않은 칸")과 같은 동작이라 그대로 뒀다. 좁히려면 `resolveMatrixWords`를 튜플에 등장하는 값 기준으로 바꿔야 하고, 그러면 다국어 매핑의 동작도 함께 바뀐다.
- `duplicate`·`failure`는 여전히 집계에서 빠지고 표시되지 않는다. 다국어 매핑과 같은 한계다.
