# 2026-08-09 연상 문제 유형 신설

## 문제

탐색과 알려주기에 새 유형 연상(`BinaryAssociation`)이 필요했다. 1개의 랜덤 단어에서 연상되는 단어를
답으로 받아 `BinaryRelation`으로 저장해야 하는데, 기존 이항 유형은 두 단어가 모두 문제에서 주어지고
답은 별도의 `answer: WordOrSentence` 필드였다. 연상은 답 자체가 관계의 두 번째 단어라 구조가 다르다.

## 해결

문제는 `{ type: 'BinaryAssociation'; wordId }`(WordExplain형 1단어), 관계는 `answer` 필드 없이
`word1Id`(주어진 단어)·`word2Id`(답한 단어)만 갖게 했다. 답과 단어를 이중 저장하지 않기 위함이다.

- **DB 무변경**: `word1Id`/`word2Id` 인덱스가 이미 있고 IndexedDB는 해당 Key Path를 가진 레코드만
  인덱스에 담으므로, 스키마/버전 변경 없이 참조 교체·삭제 게이트가 그대로 동작한다.
- **핵심 재사용**: `getRelationAnswer`가 연상에 대해 `{ type: 'word', id: word2Id }`를 돌려주게 한
  것 하나로, 편집 스냅샷(`loadRelationSnapshot`)·수정 저장(`updateRelation`의 `resolveTarget` →
  `createNewRelation` 재구성)·QnA 표시가 무수정으로 동작했다. `hydrateQnaEntries`의 `buildAnswer`만
  `relation.answer` 직접 접근을 `getRelationAnswer`로 교체.
- **함정 두 곳**: `pickQuestion`의 `pickWordCount`/`createNewQuestion`은 `default`가 2단어 형태를
  만들어 명시 분기가 필수였고, `getQuestionWordIds`의 default(`[word1Id, word2Id]`)를 그대로 두면
  답 단어가 대상 단어로 새어 편집 페이지에 2칸이 생기고 두 번째 칸 수정이 조용히 버려진다.
- 답은 단어 전용(`WordOnlyModes` 신설, 모드 1개면 선택 UI 자동 숨김)이고 무응답은 불허한다.
  `word2Id`가 필수이기 때문이며, 회피는 탐색의 건너뛰기가 담당한다.
- 유형 노출(`QuestionTypeSpecs`의 `{ type, label: '연상' }`)을 마지막에 저장해 HMR 중간 상태에서
  미완성 유형이 출제되지 않게 했다.
