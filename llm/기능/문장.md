# 문장

1개 이상의 단어로 분해 가능한 긴 문자열. 대시보드의 문장 입력기, `/sentence/$sentenceId` 개별 문장 페이지, 최근 문장 순환 큐.

## 코드

- 디렉토리: `packages/client/src/sentence/`
- 타입: `sentence/types.ts`(`Sentence`, `RecentSentence`), 상수: `sentence/consts.ts`(`RECENT_SENTENCES_SIZE`)
- 서비스: `sentence/sentence.service.ts`(`createSentence`, `updateSentence`, `deleteSentence`, `getSentence`, `getRecentSentences`), 트랜잭션 스코프 삽입: `sentence/sentenceTx.ts`(`addSentences`), 배치 해석: `sentence/resolveSentenceMap.ts`
- 컴포넌트: `SentenceField`(입력 원자), `SentenceWriter`(생성·수정 폼, `sentence` prop 유무로 모드), `RecentSentences`
- 페이지: `routes/sentence.$sentenceId.tsx`(+ `d2s/SentenceDocuments`, `s2w/SentenceWords`, `tag/TagEditor`)
- 무효화: `sentence/utils.ts`(`invalidateSentenceQueries`)

## 사양

- 저장: `sentences`(Key Path `sentenceId`, 자동 증가). `value`, `createdAt`, 수정된 적이 있을 때만 `modifiedAt`, 비어 있지 않을 때만 `source`. 최근 문장은 `recentSentences` 순환 큐 4칸(`value` 전체, `source` 없음).
- `value`를 수정해도 `sentenceId`는 불변이라 참조하는 관계는 유효하다. 순환 큐는 사본이므로 수정 시 칸의 `value`를 함께 고치고 삭제 시 `null`로 만든다.
- `SentenceWriter`: `textarea` + 출처 입력기 + 저장 버튼. 버튼 또는 `Ctrl+Enter`로 저장. 스페이스·탭이 눈에 보인다(공백 에코, 탭은 `→`). `Tab`은 탭 문자 삽입, `Shift+Tab`은 가로채지 않는다. 높이 조절 가능, 최소 256px. 본문 아래 태그 입력기가 붙고 저장 버튼이 본문과 태그를 함께 제출한다([태그](./태그.md)).
- 개별 문장 페이지: 본문, `MetaFields`(`sentenceId`, `createdAt`, `modifiedAt`), 태그 입력기, `연결된 문서`(`SentenceDocuments`, 비어 있으면 숨김, [문장-추출](./문장-추출.md)), `연관 단어`(`SentenceWords`, 0건이면 `단어 추출` 버튼, [단어-추출](./단어-추출.md)). 태그 관계는 이 표들에 나오지 않는다.
- 수정 버튼은 본문·출처·태그 중 수정 사항이 있을 때만 활성. 관계 영향 질의 후 반영하되 태그만 바뀐 저장은 질의 없이 반영하고 본문 update를 건너뛴다(`modifiedAt` 불변). 삭제는 반영 후 메인으로 이동. 미저장 수정 이탈 질의 적용([입력기](./입력기.md)).
- 탐색·알려주기가 답으로 만든 문장은 `source`에 `Harvest via NOEMA system exploration, rid=<relationId>` 또는 `Taught via NOEMA system teaching, rid=<relationId>`를 갖는다(`explore/createSource.ts`, `relation/consts.ts`). 추출된 문장은 `Extracted via NOEMA system extraction, did=<documentId>`(`d2s/consts.ts`).

## 결정 근거와 제약

- `source`가 비면 키 자체를 두지 않는다. `source: undefined`로 넣으면 IDB에 키가 남는다. 문서와 같은 규약이며 `updateSentence`가 `delete sentence.source`를 한다.
- `RecentSentence`가 `source`를 갖지 않는 이유: 최근 목록은 본문만 보여주므로 사본을 늘리지 않는다. `Omit<Sentence, 'modifiedAt' | 'source'>`.
- `getSentence`는 정수가 아닌 id에 `null`을 준다. URL이 망가지면 `get(NaN)`이 `DataError`로 죽는다.
- 최근 목록의 한 줄 미리보기는 JS로 자르지 않고 `text-overflow: ellipsis`다. 잘리는 글자 수가 폭에 따라 달라지는 편이 자연스럽다.
- 관계 수정 시 문장 답을 고치면 내용이 같을 때만 기존 id를 쓰고 달라지면 새 문장을 만든다. 밀려난 문장의 `source`를 물려받고 지우지 않는다([관계](./관계.md)).
- `Tab` 가로채기는 처음에 접근성 때문에 하지 않았으나 저장이 `Ctrl+Enter`라 다음 요소로 갈 `Tab`이 필요 없다는 사용자 판단으로 뒤집혔다.

## 알려진 함정

- 공백 에코 오버레이 정합(스크롤바, `tab-size`, pico `margin-bottom`), `execCommand('insertText')`: [UI개발참고](../참고/UI개발참고.md#레이아웃-함정), [입력-포커스참고](../참고/입력-포커스참고.md#키-이벤트).
- 한 페이지에서 `SentenceWriter`와 `SentenceDocuments`가 같은 `key={sentenceId}`를 쓰면 React key 경고가 난다.
