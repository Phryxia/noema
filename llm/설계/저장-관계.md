# 관계의 경우

- 상위문서: [타입별 Store](./저장-스토어.md)

관계의 Flat한 Indexed 저장소가 필요하다.
Store 이름은 `relations`. Key Path는 `relationId`를 가지며 자동 증가한다.

```ts
interface Relation {
  // 고유값. 삽입 시에는 비워두고 add하면 채워진다.
  relationId: number
  // TrieNodeId
  labelNodeId: number
  from: RelationTarget
  to: RelationTarget
  createdAt: Date
  modifiedAt?: Date
}

interface RelationTarget {
  type: 'word' | 'sentence' | 'document' | 'relation'
  // type이 'word'면 TrieNode의 nodeId, 'sentence'면 sentenceId,
  // 'document'면 documentId, 'relation'이면 relationId
  id: number
}
```

- `labelNodeId`, `from`, `to`가 모두 같은 관계가 둘 이상 있어도 된다. `relationId`로 구분되므로 내용적 중복은 허용한다.
- 어떤 항목을 삭제하면, 그것을 `labelNodeId`나 `from` 또는 `to`로 참조하는 모든 관계를 삭제한다. 인덱스가 없으므로 `relations` 전수 스캔으로 찾는다.
- 관계를 삭제하면 그 관계를 참조하던 관계도 삭제되므로, 삭제는 연쇄적으로 전파된다.
