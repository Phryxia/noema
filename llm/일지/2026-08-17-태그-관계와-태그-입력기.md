# 2026-08-17 태그 관계와 태그 입력기

## 문제

문장/문서에 단어를 붙이는 `Tag` 관계가 필요했다. 요구는 (1) 문장·문서 입력기 본문 바로 아래 `tags:` 인라인 라벨과 단어 카드 편집기,
(2) 편집 중엔 DB 무변경이고 저장 버튼을 눌렀을 때만 이전/새 스냅샷 차이만큼 관계 추가·삭제, (3) 결과 팝업, (4) 관계 표엔 미노출·`/relations`엔 노출, (5) `[문장/문서 30% 고정] ~ [단어]` 대표 표현.

어려운 곳은 카드 상태(`useCards`의 불변 연결 리스트, 카드 ID로 포커스 관리)를 폼 draft와 어떻게 잇느냐였다.
draft에 카드 리스트를 넣으면 dirty 비교와 리셋이 복잡해지고, 카드를 `string[]`로 완전 제어하면 카드 ID가 사라진다.

## 해결

- **저장**: `type: 'Tag'` 하나에 `sentenceId` 또는 `documentId`. `SentenceToWord` 때 정한 "기존 인덱스 공유 + 조회 쪽 `type` 필터" 규약을 그대로 써서 `DB_VERSION` 상승이 없다.
  `submitTags(target, previous, values)`가 값(문자열) 기준 집합 차이로 `added`/`removed`를 구해 한 트랜잭션에서 처리한다.
  삭제된 단어의 entry는 값이 `''`라 자동으로 `removed`가 되어, "삭제된 단어 카드는 없는 것처럼 취급하고 제출 시 지운다"가 공짜로 성립했다.
- **카드 ↔ draft**: `TagEditor`가 `useCards`를 소유하고, `useEffect(() => onChange(normalize(cards)), [cards, onChange])`로 정규화된 `string[]`만 부모 draft에 올린다.
  루프를 막으려고 `useCards`의 `cards`를 `useMemo`로 참조 안정화했고(이전엔 매 렌더 새 배열), 부모의 `onChange`는 `useCallback` + 함수형 `setDraft`다.
  `useWriterForm`의 `setDraft`를 `Dispatch<SetStateAction>`으로 넓히고 `checkIsDirty`가 배열을 원소별로 비교하게 했다.
  신규 작성 성공 시 draft 리셋과 함께 `resetKey`를 올려 `<TagEditor key={resetKey}>`가 카드 상태를 다시 만든다. 수정 페이지에선 키가 안 바뀌어 카드가 유지된다.
- **정규화 위치**: 처음엔 카드 값을 그대로 draft에 넣었더니 뒤에 남은 빈 카드 때문에 저장 후에도 dirty가 풀리지 않았다.
  `normalizeTagValues`(빈 값·중복 제거)를 `TagEditor.onChange`, 초기값(`createInitialTagValues`), `submitTags` 세 곳이 같이 써서 비교 기준을 하나로 맞췄다.
- **본문 무변경 저장**: `saveSentence`/`saveDocument`가 `checkIsBodyChanged`로 본문·출처가 그대로면 update를 건너뛴다(`modifiedAt` 안 건드림).
  `useWriterForm.confirmSave`에 draft를 넘겨 태그만 바뀐 저장은 관계 영향 질의를 띄우지 않는다. `onSaved(result)`로 저장 결과(태그 결과)를 입력기가 받아 팝업을 띄운다.
- **팝업**: `WordExtractionDialog`가 단어/결과/색 표였고 태그도 같은 모양이라 `shared/ResultDialog`(`title`, `rows: {value,label,tone}[]`)로 일반화했다. 결과가 0건이면 안 띄운다.
- **대표 표현**: 새 토큰 `tag { target, word }`. `extraction` 토큰을 재활용하지 않은 이유는 배치가 다르기 때문(30% 고정 대상 + `~` + 단어 vs 70% 자식 + `from` 30% 부모).
- **개별 관계**: `TagRelationPage`가 `PairRelationPage`를 재사용, `loadRelationSnapshot`에 `kind: 'tag'`.
- **개별 단어 화면**: 처음 구현에서 빠뜨려 지적받았다. 단어 관계 표(`QnaTable`)는 문제 기반이라 태그를 끼울 수 없어,
  `wordId` 인덱스 조회(`getTagRelationsByWord`) + `PairTable` 기반 `TagTable`로 `태그된 문장/문서` 구역(`WordTags`)을 따로 뒀다.
  단어 개명은 `wordId`가 같아 그대로 따라오고, 대체·삭제는 `invalidateWordAndQnaQueries`에 태그 무효화를 더해 갱신한다.
  같은 이유로 빠져 있던 `SentenceToWord`도 `단어를 추출한 문장` 구역(`WordSentences`, `S2wTable` 재사용)으로 같이 붙였다.
