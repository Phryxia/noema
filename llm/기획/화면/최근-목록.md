# 최근 목록

- 상위문서: [페이지 사양](../화면-페이지.md)
- 라우트: `/recent/words`, `/recent/sentences`, `/recent/documents`
- 진입 경로: [대시보드](./대시보드.md)의 `최근에 추가된 단어`, `최근에 추가된 문장`, `최근에 추가된 문서` 헤더 링크

세 페이지는 다루는 데이터만 다르고 구성이 같다. 이하 서술에서 **항목**은 그 페이지가 다루는 단어, 문장, 문서를 뜻한다.

대시보드의 최근 목록은 순환 큐에 미리 써둔 사본을 읽지만, 이 페이지는 `wordNodes`/`sentences`/`documents` 원본을 직접 조회한다.

# 단어의 경우

단어는 Trie로 저장되어 있어 둘이 다르다.

- 커서가 주는 것은 단어의 마지막 글자에 해당하는 노드 하나뿐이다. `parentNodeId`를 루트까지 거슬러 올라 `value`를 모아야 단어 문자열이 된다.
  한 페이지의 항목을 각각 거슬러 오르되, 이미 복원한 노드의 문자열을 기억해두고 재사용한다. 접두사를 공유하는 단어끼리 그만큼 덜 읽는다.
- 항목의 링크는 ID가 아니라 복원한 문자열로 `/word/[:word]`에 간다.
- 단어에는 출처가 없으므로 표에서 출처 열을 빼고 내용과 날짜 둘만 둔다.

# 조회 범위

상단에 시작 날짜와 종료 날짜 입력이 있다. 둘 다 `datetime-local`이며 분 단위까지 받는다.

- 종료 날짜의 기본값은 페이지에 들어온 시각이다.
- 시작 날짜는 선택이며 기본값은 없다. 비어 있으면 종료 날짜 이전 전체가 대상이다.
- 값을 고쳐도 곧바로 조회하지 않는다. 옆의 `검색` 버튼을 눌러야 적용된다.
- 적용하면 탐사 상태가 초기화되어 1페이지부터 다시 시작한다.

경계는 양끝을 포함한다. 입력이 분 단위이므로 종료 날짜는 그 분의 끝(`59.999`초)까지 늘려 잡는다.
그러지 않으면 방금 추가한 항목이 같은 분인데도 빠지는 일이 생긴다. 시작 날짜는 그 분의 `0`초 그대로다.

시작 날짜가 종료 날짜보다 뒤면 조회하지 않고 그 사실을 표시한다.

# 표

한 페이지에 최대 10건, `createdAt` 내림차순이다. 열은 셋이며, 단어 페이지만 출처를 뺀 둘이다.

| 열   | 내용                                                                    |
| ---- | ----------------------------------------------------------------------- |
| 내용 | `value`의 앞 48자. 잘렸으면 끝에 줄임표를 붙인다                        |
| 출처 | `source`의 앞 16자. 없으면 공란                                         |
| 날짜 | `createdAt`을 `YY-MM-DD HH:mm`으로. 24시간제이며 각 자리는 항상 두 자리 |

폭이 좁아 한 줄에 다 못 담으면 다음 줄로 넘기지 않고 줄임표로 자른다. 날짜는 자르지 않으며, 내용과 출처가 대신 줄어든다.

내용 칸은 링크이며, 누르면 해당 항목의 개별 페이지로 간다.
조회 결과가 없으면 표 대신 비어 있다는 문구를 보인다.

# 페이지 네비게이터

Indexed DB는 커서만 제공하므로 임의의 페이지로 건너뛸 수 없다. 페이지는 앞에서부터 하나씩 **탐사**된다.

- 1페이지는 종료 날짜에서 시작해 10건을 읽는다.
- `>`를 누르면 마지막으로 읽은 위치의 다음부터 10건을 읽고, 그 페이지 번호가 탐사 목록에 더해진다.
- 따라서 탐사된 페이지는 항상 1부터 어떤 번호까지 연속이다.

## 노출 규칙

노출되는 번호는 현재 페이지 기준 위아래 2개, 즉 최대 5개다. 탐사되지 않은 번호는 내보내지 않으므로 경계에서는 그보다 적게 나온다.

- 앞쪽에 가려진 번호가 있으면 맨 앞에 `...`을 둔다.
- 뒤쪽에 가려진 번호가 있거나, 아직 미탐사 구간이 남아 있으면 맨 뒤에 `...`을 둔다.
- 커서가 끝에 닿아 더 읽을 것이 없다고 확인되면 뒤쪽 `...`이 사라진다.

`...`은 버튼도 링크도 아니다. 아직 탐사하지 않았거나 창 밖으로 밀려났다는 표시일 뿐이다.

예를 들어 탐사된 페이지가 1~8이고 끝에 닿지 않은 상태에서 현재 페이지가 7이면 `...`, `5`, `6`, `7`, `8`, `...`이 된다.
처음 들어왔을 때는 `<<`, `<`, `1`, `...`, `>`다.

## 버튼

- `<<`: 1페이지로 간다. 현재 페이지가 1이면 비활성.
- `<`: 이전 페이지로 간다. 현재 페이지가 1이면 비활성.
- `>`: 다음 페이지로 간다. 현재 페이지가 마지막이고 커서가 끝에 닿았으면 비활성.

마지막으로 건너뛰는 `>>`는 두지 않는다. 끝이 어디인지 미리 알 수 없기 때문이다.

버튼은 필요한 만큼만 차지하고 가로 중앙에 모인다. 컨테이너 폭에 맞춰 늘어나거나 양끝으로 벌어지지 않는다.

# 캐싱

Tanstack Query로 페이지 단위 캐싱을 한다. 키는 `[접두사, 시작 시각, 종료 시각, 페이지 번호]`다.

- 시작 시각과 종료 시각은 유닉스 시각(밀리초)이며, 시작이 없으면 `0`으로 폴백한다.
- 읽은 페이지는 5분간 캐싱한다(`PAGE_CACHE_MS`). 5분 내에 이미 탐사한 페이지로 되돌아가면 다시 조회하지 않는다.
- 페이지를 떠나도 캐시를 지우지 않고 만료에 맡긴다. 다만 재진입 시 종료 시각 기본값이 진입 시각이라 키가 달라지므로, 보통 새로 조회된다.
  같은 범위를 명시적으로 다시 검색하면 5분 캐시를 활용한다.
- [관계 검색](./관계-검색.md)의 검색 결과 캐싱도 같은 `PAGE_CACHE_MS`를 쓴다.

캐시된 페이지 데이터는 항목 배열과 함께 **다음 커서**를 갖는다. 다음 커서는 11번째 항목의 위치이며, 11번째가 없으면 없다. 없다는 것이 곧 끝에 닿았다는 뜻이다.

페이지 `n`을 읽으려면 페이지 `n-1`의 다음 커서가 필요하다. 캐시에 없으면 그 앞 페이지를 먼저 읽어 거슬러 올라간다.
