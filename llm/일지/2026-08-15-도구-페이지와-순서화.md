# 2026-08-15 도구 페이지와 순서화

## 문제

단어 리스트를 순서대로 잇는 관계 짓기 `(w_i, w_{i+1}, 다음)`을 한 번에 넣고 싶었다. 배치 모드의 삽입·중복 판정·결과 표·토스트가
그대로 필요했지만 `submitBatchRelations` 안에 비공개 함수로 갇혀 있었고, `useBatchRelationEditor`는 `RelationEditor`에 묶여 있었다.
동적 단어 칸(`SubjectWordFields`, `isCountAdjustable`) 바로 아래에 제출 버튼을 두자, 마지막 칸에서 버튼을 클릭하면 아무 일도 없었다.
mousedown으로 칸이 blur되며 새 칸이 flushSync로 끼어들어 버튼이 아래로 밀리고, mouseup이 버튼 밖에서 일어나 click이 성립하지 않았다.
제출 성공 후 칸을 2개로 되돌려도 3개가 남는 문제도 있었다. 초기화 뒤 첫 칸에 포커스하면 마지막 칸의 blur가 이전 `words` 클로저로 빈 칸을 하나 더 붙였다.

## 해결

- `relation/batch/resolveWords`, `submitNamedAssociations`(순차 삽입과 전부 중복 throw 포함)로 뽑고 `submitBatchRelations`는 줄 파싱 → 카르테시안 곱만 남겼다.
  mutation 부분은 `useBatchSubmission(submitEntries, onSaved)`로 뽑아 `useBatchRelationEditor`와 순서화가 같이 쓴다.
- `tools/ordering`: `computeAdjacentPairs`로 인접 쌍을 만들고 고정 단어 `다음`을 word3으로 붙여 `submitNamedAssociations`에 넘긴다.
  `useOrderingTool`은 자기 `formRef`와 `words`만 든다. 페이지는 `routes/tools.tsx` → `tools/ToolsPage` → `OrderingTool` 구역이다.
- 제출 버튼의 `onMouseDown`에서 `preventDefault`로 포커스 탈취를 막았다. 칸이 늘지 않으니 click이 버튼 위에서 끝난다.
- 초기화는 `focusFirstElement` 먼저, `setWords(EmptyWords)` 나중이다. blur의 append가 먼저 flush된 뒤 빈 2칸으로 덮인다.
- 검증: vitest 70개, tsc, eslint 통과. playwright headless로 `/tools`에서 Enter로 칸 추가·빈 칸 백스페이스 삭제, 제출 후 `성공` 2행과 토스트,
  2칸 초기화와 첫 칸 포커스, 재제출 시 `모든 관계가 이미 있습니다`, `/word/alpha`의 연관 관계, `/relation/new` 배치 모드 정상 동작을 확인했다.
