# 2026-08-08 PWA 지원

## 문제

클라이언트는 네트워크 요청이 0건이고 모든 데이터가 Indexed DB에 있어 데이터는 이미 오프라인인데,
앱 셸(HTML/JS/CSS)만 매번 네트워크에서 받아 오프라인 실행과 홈 화면 설치가 불가능했다.

## 해결

`vite-plugin-pwa@1.3.0`(vite 8 peer 공식 지원)으로 manifest + service worker 프리캐시를 추가.
네트워크 요청이 없으므로 런타임 캐싱 전략은 만들지 않았다.

- **배포 무영향이 핵심 제약**: 실측 결과 `noema.moe`는 DNS 미등록(NXDOMAIN),
  `phryxia.github.io/noema/`도 404였다. `base: '/'`로 바꾸면 하위 경로 서빙이 깨지므로
  `base: './'`를 유지하고 manifest의 `start_url`/`scope`/`icons`를 전부 상대경로(`'./'`)로 지정.
  manifest 스펙상 상대 경로는 manifest 파일 URL 기준으로 해석되어, 하위 경로 배포든 나중의
  커스텀 도메인 루트든 수정 없이 동작한다. workflow, `build-gh-page`, `.nojekyll`은 손대지 않았다.
- **404.html SPA fallback은 의도적으로 제외**: 상대 base에서는 딥링크로 서빙된 fallback 문서의
  상대 자산 경로가 깨진다. 딥링크 직접 진입 404는 종전과 동일(악화 없음). 도메인 확정 후 별도 작업.
- **업데이트**: `registerType: 'autoUpdate'` + `main.tsx`의 `registerSW({ immediate: true })`
  (virtual:pwa-register). 새 버전 감지 시 무음 교체 후 리로드. 타입은 `vite-env.d.ts`에
  `vite-plugin-pwa/client` 레퍼런스 추가. dev에서는 SW 비활성(기본값)이라 HMR과 간섭 없음.
- **프리캐시**: `globPatterns`에 ico/png/svg/webmanifest를 추가해 autoCodeSplitting의 lazy 청크
  포함 71개 항목(668KiB)을 프리캐시. 최대 청크 249KB로 기본 한도 2MB에 여유.
- **검증**: `build`와 `build-gh-page`(docs/ 출력) 모두 정상, `vite preview`에서 sw.js·manifest
  200 확인, dist manifest의 `start_url`/`scope`가 `'./'`로 유지됨을 확인.

## 남은 것

- 플레이스홀더 아이콘을 실제 아이콘으로 교체. 원본은 `public/favicon.svg`(별자리 눈: 노드·간선이
  눈 모양을 이루고 동공이 중심 노드, 심우주 배경 + 잔별)이고, playwright chromium 렌더링으로
  PNG 4종(`pwa-192x192`, `pwa-512x512`, `pwa-maskable-512x512`, `apple-touch-icon`)과
  PNG 내장 ICO(`favicon.ico`)를 생성했다. 교체 시 같은 파일명으로 덮어쓰면 된다.
  콘텐츠는 중앙 80% 안에 있어 maskable과 일반이 같은 디자인을 공유한다.
- 도메인 확정 후 딥링크 fallback(404.html) 재검토.
- plan.md의 "데이터 영속성 정하기"와 시너지: PWA 설치 시 `navigator.storage.persist()` 승인
  확률이 올라간다.
