# 관계 배치 삽입

관계 짓기(`NamedAssociation`)를 여러 조합 한 번에 넣는 공용 경로. 알려주기의 `배치 모드`와 [도구](./도구.md)의 순서화가 공유한다. 단일 제출은 [관계](./관계.md).

## 코드

- 디렉토리: `packages/client/src/relation/batch/`
- 공용 절차: `resolveWords.ts`(집합별 단어 선확보), `submitNamedAssociation.ts`(단일 튜플 삽입: 중복 조회 + 결과 엔트리), `submitNamedAssociations.ts`(순차 삽입, 전부 중복 throw), `useBatchSubmission.ts`(mutation + `onSaved`)
- 배치 모드 전용: `parseBatchLines.ts`(+test), `submitBatchRelations.ts`(줄 파싱 -> `utils/computeCartesianProduct.ts`), `useBatchRelationEditor.ts`, `BatchWordFields.tsx`
- 결과: `types.ts`(`BatchOutcome`, `BatchResultEntry`), `getOutcomeLabel.ts`(`OutcomeTones`), `BatchResultTable.tsx`(`qna/QnaTable`의 `noteColumn`/`getRowTone` 주입)
- 중복 사전 조회: `relation/findDuplicateTernaryRelationId.ts`

## 사양

- 알려주기에서 유형이 관계 짓기일 때만 라디오 아래 `배치 모드` 스위치가 보인다. 다른 유형이면 사라지고 단일 모드로 동작하며 관계 짓기로 돌아오면 상태가 유지된다. localStorage에는 저장하지 않는다.
- 켜면 단어 칸 세 개가 `SentenceField` 세 개로 바뀐다(공백 에코, Ctrl+Enter 제출). 배치는 `단어 1 ── 관계 ──▶ 단어 2` 그대로, 주사위 없음, 참고사항 숨김.
- 각 textarea는 `\r?\n`으로 나누고 길이 0인 줄만 버린다. trim 없음. 같은 textarea 안의 같은 줄은 한 번만(집합).
- 세 집합의 카르테시안 곱을 word1 바깥, word2 중간, word3 안쪽 순으로 순회하며 한 조합씩 순차 삽입한다. 단어는 조합마다 만들지 않고 집합별로 한 번씩 `createWord`로 먼저 확보한다. 조합마다 `findDuplicateTernaryRelationId`로 중복이면 삽입하지 않는다. comment 없음.
- 결과 표: 유형/문제/응답/`결과`/날짜. `결과`는 `성공`/`중복`/`실패: 이유`, 행 색은 초록/주황/빨강([UI개발참고](../참고/UI개발참고.md#관용-마크업)). 페이징 없음. 성공·중복 행을 누르면 그 관계(중복은 기존 관계)로 간다. 실패 행은 `id: null`이라 이동 없음.
- 전부 중복이면 표 없이 `모든 관계가 이미 있습니다` error 토스트. 성공이 하나라도 있으면 `관계 N개를 저장했습니다` 토스트와 함께 입력을 비우고 첫 칸에 포커스. 성공이 없으면 입력 유지.

## 결정 근거와 제약

- 스위치를 폼 밖(`RelationPage`)에 둔 이유: 단일 모드의 `focusFirstElement`가 스위치를 잡지 않게.
- `QnaTable`을 제네릭(`QnaRowEntry`, `id: number | null`)으로 일반화해 표를 복제하지 않았다.
- `submitAnswer`가 `relationId`를 돌려주는 이유: 결과 행이 관계 페이지로 가야 한다.
- 전부 중복을 `throw`로 처리하는 이유: 전역 mutation 토스트 경로를 그대로 탄다([라우팅-쿼리참고](../참고/라우팅-쿼리참고.md#토스트)).

## 알려진 함정

- 제출 버튼이 동적 칸 바로 아래에 있으면 mousedown blur가 칸을 추가해 버튼이 밀린다. `onMouseDown preventDefault`. [입력-포커스참고](../참고/입력-포커스참고.md#클릭-소실-mousedown과-blur)
