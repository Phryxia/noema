# 단어 추출

- 상위문서: [페이지](../화면-페이지.md)의 _개별 문장_ 항
- 저장 규약은 [문장-단어 관계 Store](../../설계/저장-관계-문장단어.md)에 있다.
- 구현은 `packages/client/src/extraction/`(추출·카드)과 `packages/client/src/s2w/`(관계 조회·표)에 있다.
- 형제 기능인 [문장 추출](./문장-추출.md)과 카드 상태·포커스 이동 코드를 공유한다. 다른 점만 아래에 적는다.

문장 본문을 단어 카드로 잘라 사람이 다듬은 뒤 한 번에 제출한다. 제출하면 단어들이 삽입되고
(문장, 단어) 1쌍당 1개의 `SentenceToWord` 관계가 만들어진다.

## 진입

- 개별 문장 페이지의 `연관 단어` 구역은 이 문장을 가리키는 `SentenceToWord` 관계가 0건일 때만 `단어 추출` 버튼을 보인다.
- 버튼을 누르면 같은 구역이 `단어 추출` 편집기로 바뀐다.
- 구역은 `isExtracting`을 관계 건수보다 **먼저** 본다. 제출 성공으로 관계가 생기는 순간 편집기와 결과 모달이 언마운트되면 안 되기 때문이다.
  모달을 닫아야 편집기가 사라지고 구역이 표로 바뀐다.
- 제출하지 않고 이탈하면 모든 수정은 사라진다. 이탈 질의도 없다.

## 최초 분할

`extractWords(text)`. 전처리 후 왼쪽부터 한 번 훑으며 자른다.

### 전처리

1. `\r\n?`과 `\n`을 **삭제**한다. 개행만은 내용 보존의 예외다.
2. 1개 이상 연속한 탭을 공백 1개로 바꾼다.

공백은 그대로 둔다. 그 밖의 문자는 하나도 잃지 않으며, 잘린 조각을 지울지는 사용자가 정한다.

### 숫자

ASCII 숫자로 시작하는 자리에서 자바스크립트 숫자 리터럴을 먼저 시도하고, 맞으면 그 전체가 **앞뒤로 잘린 독립 조각**이다.
`0x`/`0b`/`0o` 진법과 `[0-9]+(.[0-9]+)?([eE][+-]?[0-9]+)?`를 인정한다. 선행 부호는 넣지 않는다(`+3.1e-4` → `+` / `3.1e-4`).

- 소수점 뒤에 숫자가 없으면 점을 넣지 않는다. `3.`까지 삼키면 문장 끝 마침표가 숫자에 붙는다. 사용자 사양(`JS가 인식하는 형식`)에서 의도적으로 벗어난 유일한 지점이다.
- BigInt 접미사 `n`과 자릿수 구분자 `_`는 다루지 않는다.
- 전각 숫자(`０`)는 ASCII가 아니라 이 규칙에 걸리지 않고 아래의 클래스 규칙을 탄다. 그래서 `０0` → `０` / `0`이 된다.

### 문자 클래스

클래스는 `스크립트 + 폭` 쌍이고, 이웃한 두 문자의 클래스가 다르면 자른다.

- 스크립트: `\p{Script=...}`를 목록 순서대로 시도한다(`Latin`, `Han`, `Hangul`, `Hiragana`, `Katakana`, `Cyrillic`, `Greek` 등).
  어디에도 안 걸리면 `\p{L}`은 `letter`, `\p{N}`은 `number`, 나머지는 전부 `symbol` 한 덩어리다.
  그래서 `─┴┳`처럼 생김새가 다른 기호도 한 단어로 남고, `[*`나 `](`도 붙는다.
- 폭: 유니코드 `Fullwidth/Halfwidth Forms` 블록(U+FF01–FF60, U+FFE0–FFE6은 전각 / U+FF61–FFDC, U+FFE8–FFEE는 반각)에 있으면 그 값, 아니면 중립이다.
  이 블록이 정확히 "폭 변형 짝이 있는 문자"의 집합이라 전각/반각 구분과 반각 가나 분리가 한 규칙으로 해결된다.
- 공백(`\s`)은 폭 없는 `space` 한 클래스다. 연속한 공백은 한 조각으로 뭉친다.

예외 규칙은 셋이다.

- **한자 → 히라가나는 자르지 않는다.** 이때 조각의 현재 클래스가 히라가나로 갱신되므로 그 뒤의 한자에서 다시 잘린다.
  히라가나 → 한자는 자른다. 방향이 있는 유일한 규칙이다.
- `々`(U+3005)는 앞 문자의 클래스를 그대로 이어받는다. 맨 앞이면 `symbol`.
- 장음표기 `ー`(U+30FC)와 `ｰ`(U+FF70)는 언제나 카타카나다. 그래서 `らーめん`은 `ら` / `ー` / `めん`으로 잘린다(사양 그대로).

### 예시

| 입력 | 결과 |
| --- | --- |
| `Bad Ass` | `Bad` / `(공백)` / `Ass` |
| `Caffè-tic` | `Caffè` / `-` / `tic` |
| `話す事言うべき` | `話す` / `事言うべき` |
| `'''너는''' \t왜 그렇게` | `'''` / `너는` / `'''` / `(공백2)` / `왜` / `(공백)` / `그렇게` |
| `[*이상한* 마크다운](foo)` | `[*` / `이상한` / `*` / `(공백)` / `마크다운` / `](` / `foo` / `)` |
| `０0` | `０` / `0` |
| `─┴┳` | `─┴┳` |
| `a3c` | `a` / `3` / `c` |
| `+3.1e-4` | `+` / `3.1e-4` |

## 단어 카드

- 헤더 아래에 병합/분할/삭제/이동 조작법을 `small`로 네 줄 적는다.
- 카드 하나가 단어 하나. `WordField`를 `isInline`으로 그려 `input`이 flex로 줄바꿈되며 옆으로 나열된다.
  폭은 CSS `field-sizing: content`로 내용에 맞고 `min-width`가 있어 빈 카드도 눌린다. 대시보드 단어 입력기와 공백 시각화가 같아 공백만 든 카드도 보인다.
- 맨 아래에 `제출` 버튼. 비지 않은 카드가 하나라도 있어야 활성이다. **`trim`하지 않는다**(공백만 든 카드도 제출 대상).

### 상태

문장 추출과 같은 불변 연결 리스트(`cardList.ts`)와 같은 훅(`useCards`)을 쓴다.
`useCards`는 요소 타입 제네릭이며 도착 캐럿 계산을 주입받는다. 단어 카드는 `input`이라 `computeHorizontalCaret`(다음이면 0, 이전이면 값 끝)이면 충분하다.

### 분할

- 캐럿 자리에서 Enter를 누르면 그 자리로 값을 양분해 뒤 조각을 새 카드로 끼운다. 뒤 조각 맨 앞으로 포커스.
- 조각을 버리지도 `trim`하지도 않으므로, 값이 있는 카드의 맨 뒤에서 Enter를 치면 빈 카드가 뒤에 붙는다. 사양의 두 줄이 한 규칙에서 나온다.
- 선택 영역이 있으면 그 영역은 사라진다(앞 조각은 `selectionStart`까지, 뒤 조각은 `selectionEnd`부터).
- keydown에서 `preventDefault` 후 처리한다. IME 조합 중(`isComposing`)이면 무시하므로 한글 조합 확정 Enter는 카드를 쪼개지 않는다.

### 병합·삭제·이동

문장 추출과 판정도 시점도 같다(`computePendingBackspace`를 공유, keydown 판정 → keyup 실행).

- 비지 않은 카드의 맨 앞에서 Backspace를 떼면 앞 카드에 **구분자 없이** 붙는다.
- 빈 카드에서 Backspace를 떼면 지운다.
- 이동은 좌우만 쓴다. 캐럿이 끝에서 ArrowRight면 다음 카드 맨 앞, 0에서 ArrowLeft면 이전 카드 맨 끝.
  위/아래는 별도 동작을 정의하지 않고 브라우저에 맡긴다. `input`에는 시각 행이 없어 `caretGeometry`의 픽셀 x 측정이 필요 없다.
- 좌우 판정(`computeHorizontalNavigation`)은 문장 카드와 공유한다. 문장 카드는 여기에 상하 행 판정을 얹는다.

## 제출

- 빈 카드는 조용히 버린다. 남은 값은 **`trim`하지 않고** 원문 그대로 단어가 된다.
- 같은 값의 카드가 여러 개여도 삽입은 1회만 시도한다. UI에서 합치지 않으므로 카드는 그대로 남는다.
- 단어와 관계는 하나의 `readwrite` 트랜잭션에서 만들어지며 `createdAt`은 클릭 시점 하나를 모두가 공유한다.
- 성공 시 `단어 n개를 연결했습니다` 토스트(n은 관계가 생긴 수), 관계·단어·통계 쿼리 무효화.

### 결과 모달

제출이 끝나면 `dialog`로 단어별 결과를 보인다. `단어` / `결과` 두 열이고 행 색은 관계 짓기 배치 모드와 같다(`shared/RowTone.module.css`).

| 결과 | 색 | 뜻 |
| --- | --- | --- |
| 성공 | 초록 | 단어를 새로 만들고 관계도 만들었다 |
| 중복 | 주황 | 단어가 이미 Trie에 있어 기존 `nodeId`를 재사용했다. **관계는 만들어졌다** |
| 실패 | 빨강 | 단어 삽입이 예외를 던져 관계를 만들지 않았다 |

배치 모드의 `중복`은 "관계가 이미 있다"는 뜻이라 의미가 다르다. 진입 조건이 관계 0건이므로 여기서 관계 중복은 생길 수 없어, 사용자가 알고 싶은 것은 단어의 신규 여부다.
라벨 문자열과 색 대응은 `relation/batch/getOutcomeLabel.ts`를 그대로 쓴다.

`닫기`를 누르면 편집기가 사라지고 구역이 `연관 단어` 표가 된다.
