# 2026-08-20 관계 유형 필터 `포함 유형`

## 문제

`/relations` 히스토리 표와 `q` 검색 결과, 개별 단어의 `연관 관계` 표에 유형으로 좁힐 수단이 없었다.
요구는 유형 합집합 필터를 인라인 `select` 뱃지(삭제 버튼 포함)로 두고, `/relations`에서는 URL에 남기되 `/word`에서는 URL을 쓰지 않는 것.
사용자 확정: 뱃지는 초안이며 `찾기`/`검색` 버튼으로 적용, 필터 행은 `q` 검색 중에도 보이고 검색 결과에도 걸리며, 고른 유형은 다른 `select`에 미노출.

## 해결

- **커서 필터**: `relations`에 `type` 인덱스가 없고 `advance((n-1)*10)`은 행 수 = 인덱스 수를 전제한다.
  `RecentFilter<TRow> = {key, accept}`를 `getRecentPage` 네 번째 인자로 받고, 필터가 있으면 `checkNeedsJump`가 offset 점프를 거부해 커서를 처음부터 걷는다.
  판정은 순수 함수 `createRowJudge(start, accept)`가 `'skip' | 'collect' | 'stop'`으로 돌려주며, offset만큼 통과 행을 건너뛰고 11번째 통과 행에서 멈춘다.
  `readPage`는 `toEntry` 후 판정만 하므로 필터 없을 때 동작이 그대로다. DB 버전·인덱스 무변경.
- **키 분리**: 쿼리 키는 필터 키가 있을 때만 5번째 원소를 붙여 무필터 4-튜플과 `[relationPages]` 접두사 무효화를 보존했다.
  `useExploredRange`에는 `rangeKey|filterKey`를 넘기되 `RecentListSection`의 `key={rangeKey}`는 그대로 둬서, 날짜 초안을 고친 채 `찾기`로 유형만 바꿔도 입력칸이 리마운트되지 않는다.
- **URL 쓰기**: `useRangePageParams(extraSearch)`가 `search()`에서 `...extraSearch`를 함께 쓴다. `RecentListSection` → `useRecentPages` → 훅으로 같은 이름을 통과시켰다.
  `types`는 `,`로 이은 문자열로 둔다. 배열이면 TanStack Router가 JSON 인코딩(`%5B%22..%22%5D`)해서 읽기 어렵다.
  `parseRelationTypes`는 알려진 유형만 남기고 순서 유지 dedupe, `serializeRelationTypes`는 빈 배열을 `undefined`로 돌려 키를 지운다.
- **초안**: `useRelationTypeDraft(applied, appliedKey)`가 `useEffect(setDraft, [appliedKey])`로 뒤로가기 동기화(`QnaSearchForm`의 `useEffect(setInput, [query])` 관례).
  `찾기`는 `isChanged`일 때만 `page`를 지운다.
- **검색 결과**: 캐시는 검색어별 그대로 두고 훅에서 `useMemo`로 유형을 거른다. 페이징 초기화는 `PagedSection`의 `key` 리마운트 대신 새 `resetKey`로 했다.
  `useExploredPagination(totalPages, resetKey)`가 `useExploredRange`식 렌더 중 상태 조정으로 1페이지로 돌아간다.
- **`TypeFilterField`**: `shared/TypeFilterField`. `fieldset[role=group]`에 `select` + `x` 버튼을 붙여 뱃지 모양을 내고, 맨 끝 `유형 추가` `select`는 남은 옵션이 없으면 숨긴다.
  값은 `options.find`로 찾아 `as T` 캐스팅 없이 처리. `/word`는 `PagedSection`에 새 `header` prop으로 끼워 넣어 모두 걸러져도 필터 행이 남는다.

## 겪은 것

뱃지 `select`에서 유형을 바꾸거나 추가하면 포커스가 `body`로 빠졌다. 뱃지 `key`가 유형값이라 값이 바뀌면 리마운트됐고,
추가용 `select`는 키가 없어 앞에 뱃지가 끼어들면 index 키가 밀려 리마운트됐다. 뱃지는 `key={index}`, 라벨과 추가용 `select`에 고정 키를 줘서 해결했다.

## 검증

vitest 131개(`relationTypeParams` 6개, `createRowJudge` 5개 신규), tsc, eslint, prettier 통과.
playwright 영속 프로필로 dev 서버에 붙어 `corpus.json`(버전 10으로 고치고 `DocumentToSentence` 20건·`Tag` 5건 추가)을 가져온 뒤 확인했다.

- 뱃지 2개 + `검색` → `?types=WordExplain%2CWordsUsage`, 두 유형만 10행. `>` → `page=2`, ID 링크 진입 후 뒤로가기 → 유형·페이지 유지
- `?types=WordExplain,WordsUsage&page=3` 다이렉트 진입 → `<< < ... 3 ... >`, 첫 행 ID가 `<`·`>`로 되돌아온 순차 조회와 같음(2161). `page=11`은 5행·`>` 비활성
- `?types=Tag,DocumentToSentence&page=3` → 5행 모두 문장 추출. `?types=xyz,WordExplain` → 단어 설명만, URL 그대로. `?types=` → 필터 없음
- `q=興味`: 무필터 2행, `types=BinaryCommon`·`types=Tag` → `일치하는 내용이 없습니다.`. `찾기`는 유형 불변이면 `page=4` 유지, 바뀌면 제거. 입력 비워 취소 → `types` 유지
- 날짜 초안 `2026-07-01T00:00` 입력 후 유형 바꿔 `찾기` → 입력칸 값 유지. 뱃지 전부 `x` 후 `검색` → `types` 사라짐. 13개 다 고르면 추가 `select` 없음
- `/word/興味`: `BinarySimilarity` 고르면 2행·1페이지, 다른 유형으로 바꾸면 `연관된 관계가 없습니다.` 위에 필터 행 유지, 추가·교체 후 포커스가 해당 `select`에 남음, URL 무변경
