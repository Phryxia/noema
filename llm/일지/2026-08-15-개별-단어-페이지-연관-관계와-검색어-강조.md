# 2026-08-15 개별 단어 페이지 연관 관계와 검색어 강조

## 문제

단어가 어떤 관계에 참여하는지 보려면 `/qna`에서 직접 검색해야 했다. 검색 결과 표도 어느 칸이
검색어와 일치했는지 드러나지 않아, 특히 부분 일치 섹션에서 일치 위치를 눈으로 찾아야 했다.

## 해결

- `word/WordRelations`: `searchExactQnaEntries(word)`를 `[wordRelations, 단어]` 키, 10분
  `staleTime`/`gcTime`(`WORD_RELATIONS_CACHE_MS`)으로 조회하고 `QnaSearchSection`을 그대로 그린다.
  `QnaSearchSection`에 `emptyMessage`를 두어 비었을 때 제목과 안내문을 남긴다.
  단어 페이지에서는 `key={word}`로 개명 이동 시 페이징 상태를 초기화한다.
- 강조는 `shared/HighlightedText`가 `text.split(keyword)`로 조각내어 사이마다 `<mark>`를 끼운다.
  `QnaTable` → `QnaRow` → 셀 → `WordLink`/`ResolvedTextLink`로 `keyword`를 내려보내며,
  히스토리 표는 prop을 넘기지 않으므로 그대로다. 판정과 같은 `includes` 기준이라 정확히 일치는 값 전체,
  부분 일치는 해당 부분만 강조된다. 문장은 `createPreview`로 자른 뒤에 적용한다.
- 무효화: `invalidateWordAndQnaQueries`, `invalidateRelationQueries`에 `wordRelations` 키를 추가했다.
- 검증: tsc, eslint, vitest 61개 통과. playwright headless로 `corpus.json`을 설정 페이지에서
  가져온 뒤 `/qna?q=興味`(정확), `/qna?q=興`(부분, `<mark>興</mark>味`), `/word/興味`(연관 관계 2행,
  네비게이터), 히스토리 표에 `mark` 0개, 없는 단어 안내를 확인했다.
