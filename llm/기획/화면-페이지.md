# 개요

페이지의 라우트와 구성을 서술한다.

- 상위문서: [화면](./화면.md)
- 페이지가 배치하는 컴포넌트의 동작은 [재사용 컴포넌트](./화면-컴포넌트.md)에 있다.
- 페이지가 읽고 쓰는 데이터의 스키마는 [타입별 Store](../설계/저장-스토어.md)에 있다.

# 공통 규칙

이 구획의 2-depth 헤더의 내용은 하단의 페이지별 기획에서 각 호를 언급할 때 적용된다.

## 미저장 수정 이탈 질의

- 값은 수정돼 있는데 수정 버튼을 누르지 않은 상태로 이탈을 시도할 경우
  - 표준 프롬프트 화면으로 `수정된 내용을 저장할까요?` 물어보며 확인
  - confirm인 경우 수정 반영. 해당 페이지에 _관계 영향 질의_가 있으면 그 질의를 먼저 통과해야 한다
  - cancel인 경우 수정 없이 그대로 이탈

## 관계 영향 질의

- 수정 대상을 참조하는 관계가 1건 이상이면, 수정 반영 직전에
  표준 confirm으로 `연결된 n건의 관계도 수정됩니다. 계속하시겠습니까?` 물어보며 확인
  - `n`은 참조하는 관계의 중복 없는 개수 (한 관계가 문제와 답으로 이중 참조해도 1건)
  - cancel인 경우 아무것도 바꾸지 않는다
- 참조하는 관계가 없으면 묻지 않는다
- 개별 관계 페이지의 수정에는 적용되지 않는다. 그쪽은 그 관계의 참조만 바꾸기 때문이다

## 관계 목록

- 라우트: `/qna`
- 공통 헤더의 `관계` 링크로 들어간다.
- 탐색에서 출제된 문제와 응답을 `relations` 기준으로 표로 보여준다. 관계 없는 문제 잔재는 나타나지 않는다.
- 열은 유형 / 문제 / 응답 / 참고 / 날짜
  - 문제: 대상 단어들, 각각 개별 단어 페이지로 링크
  - 응답: 유형에 따라 답안(단어/문장 링크), 유사도 라벨, 선택된 단어, 회피(`WordsUsage`의 `null` 답)
  - 참고: `comment`가 있으면 단어/문장 링크
  - 삭제된 대상은 링크 없이 `(삭제됨)`으로 표시
- 행의 링크가 아닌 곳을 누르면 그 관계의 _개별 관계_ 페이지로 이동한다.
  단어/문장 링크는 자기 목적지로 가야 하므로 행 이동을 가로챈다.
- 기간 검색 폼, 페이지 네비게이터, 캐싱 규약은 _최근 목록_과 같다.
- 제목 아래에 문자열 검색 폼이 있다. 사양은 [관계 검색](./화면/관계-검색.md)에 있다.

## 개별 관계

- 라우트: `/relation/[:relationId]`
- _관계 목록_의 행으로 들어간다.
- [알려주기](./화면/알려주기.md)와 같은 구성을 그린다. 지시문, 대상 단어 칸, 답안란, 참고사항의 동작이 모두 같다.
- 유형 라디오는 그대로 보이되 비활성이다. 유형이 바뀌면 다른 관계가 되기 때문이다.
- `MetaFields`로 `relationId`, `questionId`, `createdAt`, `modifiedAt` 표시
- 수정 버튼
  - 알려주기의 제출 버튼과 같은 조건에서 활성화되며 라벨만 `수정`이다
  - 누를 시 수정 반영. 입력은 비우지 않고 그대로 둔다
- 삭제 버튼
  - 누를 시 삭제 반영 기다린 후 관계 목록으로 이동
  - 관계를 낳은 문제도 함께 지운다. 대상 단어와 답안/참고사항의 단어·문장은 지우지 않는다
- 없는 `relationId`면 `존재하지 않는 관계: <relationId>`를 표시한다.
- 저장 규약은 [탐색 Store](../설계/저장-탐색.md)의 수정/삭제 절차에 있다.

## 설정

- 라우트: `/settings`
- 공통 헤더의 `설정` 링크로 들어간다.
- 데이터 백업 구역
  - `내보내기`: 전체 DB를 JSON 파일 하나로 내려받는다. 파일명은 `noema-backup-<연월일시분>.json`
  - `가져오기`: 파일을 고르면 표준 프롬프트로 확인을 받고, 기존 내용을 무시한 채 파일의 내용으로 덮어쓴다
  - 두 버튼 아래에 성공 문구 또는 실패 사유를 표시한다
  - 작업 중에는 두 버튼 모두 비활성화한다
- 파일 형식과 덮어쓰기 규약은 [저장 공통 규약](./저장-공통.md)에 있다.

## 개별 단어

- 라우트: `/word/[:word]`
- `WordEditor`에 해당 단어 입력돼 있음
- `MetaFields`로 `nodeId`, `parentNodeId`, `createdAt`, `modifiedAt` 표시
- 수정 버튼
  - 폼의 수정 사항이 있을 때만 활성화
  - 누를 시 _관계 영향 질의_ 후 수정 반영, 결과 단어의 페이지로 이동 (수정 시 `nodeId`가 바뀐다)
  - 수정은 전역 개명이다. 이 단어를 참조하는 모든 관계가 새 단어를 가리키게 된다
  - 수정 결과가 이미 있는 단어면 표준 confirm으로 병합 여부 확인. 거부 시 아무것도 바꾸지 않음
- 삭제 버튼
  - 참조하는 관계가 없으면 삭제 후 메인 페이지로 이동
  - 참조하는 관계가 있으면 `WordReplaceDialog`로 삭제 취소 또는 대체 단어 입력을 받음
  - 최근에 추가된 단어에 해당 단어 있으면 삭제
- _미저장 수정 이탈 질의_ 적용
- `WordEditor` 아래에 `연관 관계` 구역(`WordRelations`)
  - [관계 검색](./화면/관계-검색.md)에서 이 단어로 검색했을 때의 `정확히 일치` 결과와 판정·정렬·표·페이지 네비게이터·하이라이트가 모두 같다.
  - 비어 있으면 제목 아래 `연관된 관계가 없습니다.`를 표시한다.
  - 단어별로 10분간 캐싱한다(`WORD_RELATIONS_CACHE_MS`, 키 `[wordRelations, 단어]`).
    단어·관계의 생성/수정/삭제 시 무효화한다(`invalidateWordAndQnaQueries`, `invalidateRelationQueries`).

## 개별 문장

- 문장 내용 표시
- `MetaFields`로 `sentenceId`, `createdAt`, `modifiedAt` 표시
- 수정 버튼
  - 폼의 수정 사항이 있을 때만 활성화
  - 누를 시 _관계 영향 질의_ 후 수정 반영
- 삭제 버튼
  - 누를 시 삭제 반영 기다린 후 메인 페이지로 이동
- _미저장 수정 이탈 질의_ 적용

## 개별 문서

- 라우트: `/document/[:documentId]`
- 문서 내용 표시
- `MetaFields`로 `documentId`, `createdAt`, `modifiedAt` 표시
- 수정 버튼
  - 누를 시 수정 반영
  - 관계가 문서를 참조하는 경로는 없으므로 _관계 영향 질의_는 적용되지 않는다
- 삭제 버튼
  - 누를 시 삭제 반영 기다린 후 메인 페이지로 이동
- _미저장 수정 이탈 질의_ 적용
