# 라우팅과 쿼리 참고

TanStack Router, TanStack Query, 토스트, localStorage, PWA, 배포 경로를 만지기 전에 읽는 문서다. 각 항목은 규칙, 증상, 해결, 출처(일지) 순이다.

# TanStack Router

- **`useSearch({ strict: false })`는 라우트의 `validateSearch`를 거친 값이 아니라 `location.search` 원본을 돌려준다.** `?page=1.5`가 그대로 들어와 1.5페이지가 조회됐고, `?to=`(빈 문자열)이 `new Date('')`로 흘러 결과가 통째로 비었다. 여러 라우트에서 쓰이는 훅은 읽은 값을 다시 파서(`recent/parseRangePageParams.ts`)에 통과시킨다. `validateSearch`는 네비게이션 때 키가 잘리지 않게 하는 역할로만 남는다. strict한 `getRouteApi(...).useSearch()`도 무효 쿼리로 직접 진입하면 원본 값이 그대로 온다(`?tab=garbage`가 `'garbage'`로 유입). `validateSearch`만 믿지 말고 읽는 쪽에서 유효값 비교로 재검증한다(`tools/ToolsPage.tsx`).
- **search 갱신은 `navigate({ to: '.', search: (prev) => ... })` 함수형으로 쓴다.** `to`가 없으면 대상 search 타입이 `never`로 잡혀 컴파일되지 않고, 함수형이라 다른 키(`q`)가 자동 보존된다. 키를 지우려면 `undefined`를 준다.
- **query string 배열은 `,`로 이은 문자열로 둔다.** 배열이면 JSON 인코딩(`%5B%22..%22%5D`)되어 읽기 어렵다(`relations/relationTypeParams.ts`).
- **잘못된 값은 기본값으로 동작하되 URL에 되쓰지 않는다.** 기본값을 URL에 쓰면 캐시 키와 뒤로가기 동작이 흔들린다.
- **라우트 파일을 지우거나 더하면 `routeTree.gen.ts`는 vite 플러그인이 재생성한다.** 개발서버가 꺼져 있으면 `npx vite build`를 한 번 돌린 뒤 `tsc`를 돌린다.
- **`basepath: import.meta.env.BASE_URL`이 라우터 기준 경로다.** gh-page는 `--base=/noema/`로 빌드하고 `404.html`을 `index.html` 사본으로 둬 딥링크 새로고침을 받는다.

# TanStack Query

- **무효화는 모듈별 `invalidateXxxQueries(queryClient)`(`*/utils.ts`)를 통해서만 한다.** 단어는 `invalidateWordQueries`/`invalidateWordAndQnaQueries`, 관계는 `invalidateRelationQueries`, 그 외 `Sentence`/`Document`/`D2s`/`S2w`/`Tag`/`Statistic`. 새 쿼리 키를 만들면 이 함수에 넣는다. `WORD_NODE_ID_QUERY_KEY`가 어디서도 무효화되지 않아 삭제한 단어를 다시 저장하지 못한 전례, `RECENT_*_PAGES_QUERY_KEY` 셋이 5분 캐시로 바뀌면서 무효화에 빠져 `/recent/*`가 같은 분 안에 재진입하면 옛 값을 보인 전례가 있다.
- **파생값의 무효화는 원천을 바꾸는 쪽에 둔다.** 문서 제목은 `DocumentTitle` 관계와 문장에서 해석되므로 `invalidateRelationQueries`가 `invalidateDocumentQueries`를 포함한다. 문장 페이지에서 제목 문장을 고치거나 관계 페이지에서 제목 관계를 지워도 문서 노출이 갱신되는 근거다.
- **`staleTime`을 준 쿼리만 무효화 누락이 증상으로 드러난다.** 기본 `staleTime: 0`인 대시보드 순환 큐 쿼리는 마운트마다 다시 읽어 누락이 가려진다. 5분 캐시 쿼리(`PAGE_CACHE_MS`)를 만들면 무효화 경로를 반드시 함께 만든다.
- **백업 가져오기 뒤에는 `queryClient.invalidateQueries()`를 필터 없이 부른다.**
- **캐시 시간 상수**: 최근 목록과 관계 검색은 `recent/consts.ts`의 `PAGE_CACHE_MS`(5분), 개별 단어의 연관 관계는 `word/consts.ts`의 `WORD_RELATIONS_CACHE_MS`(10분). 탐색 문제는 `staleTime: Infinity, gcTime: 0`이다.
- **페이지 캐시 키는 `[접두사, 시작, 종료, 페이지]`에 필터가 있을 때만 5번째 원소를 붙인다.** 무필터 4-튜플과 접두사 무효화를 보존하기 위해서다(`recent/ensureRecentPage.ts`).
- **`refetch()`는 그 시점의 `queryFn`을 즉시 실행하므로 직전 `setState` 값을 보지 못한다.** 출제 조건처럼 "갱신 후 바로 다시 뽑기"는 `useRef`에 두고 `ref.current` 갱신 직후 `refetch()`한다(`useExplore`의 `appliedTypes`).
- **`to` 기본값처럼 매 렌더 바뀌는 값은 `useState(() => ...)`로 마운트당 한 번 고정한다.** 매 렌더 `new Date()`면 캐시 키가 흔들린다.
- **`queryFn`은 `undefined`를 돌려줄 수 없다.** 없음은 `null`이다.
- **저장 계층 쿼리는 `retry: false`와 에러 문구를 둔다.** [저장개발참고](./저장개발참고.md#마이그레이션).

# 토스트

- `main.tsx`의 `MutationCache.onError`가 모든 mutation 실패를 error 토스트로, `onSuccess`는 `mutation.meta.successMessage`가 선언된 것만 success 토스트로 띄운다. 저장·삭제성 mutation에는 `meta`를 주고, 비저장성(랜덤 뽑기 등)은 무음이다. `meta` 타입은 `toast/types.ts`의 `Register.mutationMeta` 선언 병합으로 강제된다.
- 발신은 `toast/toast.ts`가 `window.dispatchEvent(CustomEvent)`로, 수신은 `ToastStack`이 한다. 발신 지점이 React 트리 바깥이라 Context를 쓸 수 없다.
- 상수는 `toast/consts.ts`(5초 잔류, 최대 3개, 오래된 순 위에서 아래, 초과 시 최오래 제거).
- **사용자에게 보일 실패는 mutation 안에서 한국어 메시지로 `throw`한다.** 전역 `onError`가 그대로 띄우고, mutation 실패라 성공 토스트도 폼 리셋도 일어나지 않는다(`이미 있는 관계입니다`, `모든 관계가 이미 있습니다`).
- 컴포넌트에서 직접 성공/실패 문구를 그리지 않는다. 토스트 루트는 `pico` 클래스를 문자열로 병기해야 pico 변수와 `article` 스타일을 받는다.
- 알려진 부정확: `WordEditor`의 병합 확인창에서 취소해도 mutation이 성공으로 끝나 수정 토스트가 뜬다.

# localStorage

| 키 | 위치 | 내용 |
| --- | --- | --- |
| `explore/checkedTypes` | `explore/consts.ts`, `useExplore.ts` | 탐색 유형 체크 상태. 복원 시 알려진 유형과 교집합, 파싱 실패면 전체 선택 |
| `explore/usageWordCount` | `explore/usageWordCountStorage.ts` | 예문 만들기 단어 수 |
| `teach/type` | `relation/consts.ts`의 `TEACH_TYPE_STORAGE_KEY`, `relation/typeStorage.ts` | 알려주기 마지막 유형. 키 이름은 사용자 저장값이라 `teach`에서 바꾸지 않는다 |

- 복원 값은 반드시 현재 유효 목록(`WordRelationTypes`)으로 거른다. 제거된 유형이나 쓰레기 값이 유입되지 않게 한다.
- 기능을 지워 키가 폐기되면 `storage/clearLegacyStorage.ts`의 접두 목록에 넣는다. `main.tsx` 기동 시 지운다.
- 새 유형을 더하면 기존 사용자에게는 체크가 꺼진 채 보인다. 교집합 복원의 의도된 결과다.

# PWA와 배포

- `packages/client/vite.config.ts`의 `VitePWA({ registerType: 'autoUpdate', workbox: { globPatterns, navigateFallback: 'index.html' } })`와 `main.tsx`의 `registerSW({ immediate: true })`. 새 버전 감지 시 무음 교체 후 리로드. 네트워크 요청이 없어 런타임 캐싱 전략은 없다. dev에서는 SW가 비활성이라 HMR과 간섭하지 않는다.
- **오프라인에서 깊이 2 이상 경로 새로고침**: SW가 `index.html`을 서빙하면 상대 자산 경로가 문서 URL 기준으로 풀려 실패한다. `packages/client/index.html`의 인라인 스크립트가 `navigator.serviceWorker.controller.scriptURL`에서 앱 루트를 계산해 `<base>`를 주입한다. Chromium preload scanner의 투기적 요청 실패 로그는 무해하다.
- 배포는 `.github/workflows`가 `npm run build-gh-page`(`--base=/noema/ --outDir docs`)로 `docs/`를 만들고 `404.html`을 복사한다. 커스텀 도메인 루트로 옮기면 `--base=/`만 바꾼다. manifest의 `start_url`/`scope`는 `./`로 두어 어느 base든 동작한다.
- 설치형 앱에서 SW가 구버전 셸을 서빙하는 동안 DB 버전이 올라가면 `onblocked`/`onversionchange` 경로를 탄다. [저장개발참고](./저장개발참고.md#마이그레이션).
