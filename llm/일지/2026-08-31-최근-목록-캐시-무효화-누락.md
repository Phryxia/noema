# 2026-08-31 최근 목록 캐시 무효화 누락

## 문제

개별 문서 페이지에서 제목을 고친 뒤 `최근에 추가된 문서`로 가면 옛 제목이 보였다. 사용자가 단어·문장에도 같은 일이 있을 것이라 짐작해 함께 확인을 요청했다.

playwright로 재현했다(수정 전).

- 문서: `/recent/documents`를 본 뒤 문서 페이지에서 제목을 `doc-x`로 수정. 홈의 최근 문서는 `doc-x`, `/recent/documents`는 옛 제목.
- 제목 문장: 새 문서를 만들고 `/recent/documents`·`/recent/sentences`를 본 뒤 `/sentence/$id`에서 제목 문장을 수정. 홈은 문서·문장 모두 새 값, `/recent/sentences`와 `/recent/documents`는 옛 값.
- 단어: `/recent/words`를 본 뒤 단어를 개명. 홈은 새 값, `/recent/words`는 옛 문자열과 옛 `/word/<값>` 링크.

원인은 두 가지였다.

1. `/recent/*` 페이지 쿼리(`RECENT_WORD_PAGES_QUERY_KEY`, `RECENT_SENTENCE_PAGES_QUERY_KEY`, `RECENT_DOCUMENT_PAGES_QUERY_KEY`)는 `useRecentPages`가 `staleTime`·`gcTime` 5분으로 캐시하는데, 어떤 `invalidateXxxQueries`에도 들어 있지 않았다. 2026-08-15에 캐시를 무한+언마운트 삭제에서 5분으로 바꾸면서 관계 검색(`QNA_SEARCH_QUERY_KEY`)은 무효화에 넣고 최근 목록 셋은 빠뜨렸다. 언마운트 삭제 시절에는 재진입이 항상 새로 읽었으므로 그때는 문제가 없었다.
2. 문서 제목은 `DocumentTitle` 관계와 문장에서 해석되는 파생값인데, 문장·관계 쪽 무효화(`invalidateRelationQueries`)가 문서 쿼리를 건드리지 않았다.

재현 조건이 헷갈린다. 캐시 키의 `to` 기본값이 진입 시각의 분 끝이라 같은 분 안에 재진입해야 같은 키를 맞고, 분이 바뀌면 키가 달라져 새로 읽어 정상처럼 보인다. 홈의 순환 큐 쿼리는 `staleTime` 기본값 0이라 마운트마다 다시 읽으므로 홈은 늘 맞았다. 사용자가 본 것은 홈이 아니라 `/recent/documents`(제목이 같은 `최근에 추가된 문서`)였다.

## 해결

- `invalidateWordQueries`·`invalidateSentenceQueries`·`invalidateDocumentQueries`에 각 최근 목록 페이지 키를 넣었다. `recent/consts.ts`는 import가 없는 상수 파일이라 순환이 없고, `word/RecentWordSource.ts`·`document/RecentDocumentSource.ts`가 이미 `recent/`를 참조한다.
- `invalidateRelationQueries`가 `invalidateDocumentQueries`도 부른다. 관계가 바뀌면 단어·문장·태그·S2W·D2S 캐시를 비운다는 기존 규칙에 문서(제목)를 더한 것이다. `document/utils.ts`는 `document/consts`·`recent/consts`·`statistic/utils`만 import하므로 런타임 순환이 없다. 이로써 `SentenceWriter`의 제목 문장 수정·삭제, `useRelationEditor`의 `DocumentTitle` 관계 삭제가 문서 제목 노출을 갱신한다.
- `DocumentWriter`의 `invalidateQueries`는 `SentenceWriter`와 같이 `invalidateRelationQueries` 하나로 줄였다.

기각한 대안: 최근 목록의 `staleTime`을 0으로 낮추기. 페이지 `n`이 캐시된 `n-1`의 커서에서 이어 읽는 구조와 뒤로가기 복원이 캐시에 기대므로, 캐시를 줄이는 대신 변경 시점에 비우는 쪽이 맞다. 관계 목록(`RELATION_PAGES_QUERY_KEY`)이 이미 그렇게 한다.

검증: tsc·eslint·prettier·vitest(126건) 통과. playwright로 위 세 시나리오와 제목 문장 삭제 후 `(제목 없음)`을 수정 후 다시 돌려 홈과 `/recent/*` 모두 새 값을 확인했다. 스크립트는 저장소에 두지 않았다.

## 남은 것

- `invalidateRelationQueries`가 부르는 `invalidateStatisticQueries`가 단어·문장·문서 경유로 세 번 불린다. 멱등이라 두었다.
