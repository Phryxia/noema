# 문장 추출

문서 본문을 문장 카드로 잘라 사람이 다듬은 뒤 한 번에 제출한다. 문장들이 삽입되고 (문서, 문장) 쌍마다 `DocumentToSentence` 관계가 생긴다. 개별 문서 페이지의 `연결된 문장` 구역에서 시작한다. 단어 추출과 카드 편집기를 공유한다([단어-추출](./단어-추출.md)).

## 코드

- 디렉토리: `packages/client/src/extraction/`(카드 편집기 공용), `packages/client/src/d2s/`(관계)
- 분할: `extraction/extractSentences.ts`(+test), `splitByTripleNewline.ts`(+test)
- 카드 상태: `extraction/cardList.ts`(+test, 불변 연결 리스트), `useCards.ts`(공용 훅), `useSentenceCards.ts`(`\n\n\n` 분할 래퍼), `computePendingBackspace.ts`, `arrowNavigation.ts`(가로 판정)
- 문장 카드: `extraction/SentenceCard/SentenceCard.tsx`, `arrowNavigation.ts`(+test, 상하 판정), `caretGeometry.ts`(미러 측정), `SentenceExtractor/`
- 제출: `extraction/submitExtraction.ts`, `sentence/sentenceTx.ts`의 `addSentences`
- 관계: `d2s/d2s.service.ts`, `hydrateD2sEntries.ts`, `types.ts`, `consts.ts`(`EXTRACT_SOURCE_PREFIX`), `utils.ts`(`invalidateD2sQueries`)
- 화면: `document/DocumentSentences/DocumentSentences.tsx`(진입·표·편집기 전환), `d2s/SentenceDocuments/`(개별 문장의 `연결된 문서`), `d2s/D2sTable.tsx`·`D2sCells.tsx`(`relation/PairTable` 기반), `d2s/D2sRelationPage/`(`relation/PairRelationPage` 기반)

## 사양

- 진입: `연결된 문장` 구역은 이 문서를 가리키는 관계가 0건일 때만 `문장 추출` 버튼을 보인다. 누르면 같은 구역이 편집기로 바뀌고, 제출로 관계가 생기면 표로 바뀐다. 제출 없이 이탈하면 수정은 사라지며 이탈 질의도 없다.
- 최초 분할(`extractSentences`): `\r\n`/`\r`을 `\n`으로 정규화한 뒤 개행, 또는 부호 `.?!"'` 연속 뒤에 공백 1개 이상이나 문자열 끝이 오는 지점에서 자른다. 각 조각 `trim`, 빈 조각 제거. 부호 뒤에 공백이 없으면(`CLAUDE.md`, `3.14`) 자르지 않는다. 완벽하지 않고 사람이 병합·분할로 고친다.
- 카드: 헤더 아래 조작법 `small` 네 줄. 카드 하나가 문장 하나, `SentenceField` `rows=1`(`compact`), 탭·개행·공백 시각화는 대시보드 입력기와 같다. 높이는 `field-sizing: content`. 카드 사이 버튼 없음. 맨 아래 `제출`(`trim`이 비지 않은 카드가 하나라도 있어야 활성).
- 병합: 비어 있지 않은 카드에서 캐럿 맨 앞·선택 없음으로 Backspace를 뗄 때 앞 카드 뒤에 구분자 없이 붙이고 삭제. 앞 카드 접합점으로 포커스. 첫 카드면 무동작.
- 분할: 값에 `\n\n\n`이 들어오면 경계로 쪼개고 `trim`·빈 조각 제거. 2개 이상이면 첫 조각이 현재 카드, 나머지는 뒤에 새 카드, 두 번째 카드 맨 앞으로 포커스. 1개면 값만 교체. 쪼개는 데 쓴 개행은 남지 않는다.
- 삭제: 빈 카드에서 Backspace를 뗄 때 삭제, 앞 카드 끝(없으면 뒤 카드 앞)으로 포커스. 마지막 글자를 지운 release로는 삭제되지 않는다.
- 이동: 끝에서 → 다음 카드 앞, 0에서 ← 이전 카드 끝, 마지막 시각 행에서 ↓ 다음 카드 첫 행의 같은 x, 첫 행에서 ↑ 이전 카드 마지막 행의 같은 x. 경계 카드면 무동작. 선택 영역·수정 키·IME 중이면 무시.
- 제출: `trim`이 빈 카드 제외, 값은 원문 그대로. `[sentences, recentSentences, relations]` 단일 트랜잭션, `createdAt`은 클릭 시점 하나를 공유. `source`는 `Extracted via NOEMA system extraction, did=<documentId>`. 성공 시 `문장 n개를 저장했습니다` 토스트, 관계·문장·통계 무효화.
- 관계: `{ type: 'DocumentToSentence', documentId, sentenceId, createdAt }`, `comment` 없음, 수정 없음(삭제만). `documentId`/`sentenceId` 인덱스(v10). 문서별 조회는 `documentId` `getAll`이 `relationId` 오름차순 = 삽입 순서 = 문장 순서라 정렬하지 않는다. 문서 수정·삭제는 관계를 건드리지 않고, 문장 수정은 관계 영향 질의 건수에 들어가며, 문장 삭제 후 목록에 `(삭제됨)`.

## 결정 근거와 제약

- 배열 splice가 아니라 불변 연결 리스트인 이유: 문서가 길 수 있다. `id`가 안정적이라 React key와 포커스 대상이 되고 `SentenceCard`는 `memo`다.
- 한 트랜잭션으로 묶이는 이유: 탐색 제출과 달리 다른 트랜잭션 결과를 기다릴 일이 없다. 두 히스토리가 한 `createdAt` 인덱스를 공유하므로 규모가 커지면 `['type', 'createdAt']` 복합 인덱스를 d2s 쪽에 먼저 고려한다.
- 최초 분할 정규식의 공백 필수: `[.?!"']+\s*`로 두었더니 `CLAUDE.md`가 `CLAUDE.`/`md`로 잘렸다. CRLF 정규화가 앞서는 이유는 `.`이 `\r`을 줄바꿈으로 봐서 본문을 통째로 잃었기 때문이다.
- 카드 사이 `병합` 버튼은 두었다가 같은 날 지웠다. 뒤 조각이 비면 새 카드를 만들지 않는 것은 사용자 확답.
- 화살표 이동을 keydown에서 미러 측정으로 하는 이유와 Backspace가 keyup인 이유: [입력-포커스참고](../참고/입력-포커스참고.md#키-이벤트).
- `sentenceId` 인덱스는 `SentenceToWord`·`Tag`와 공유하므로 조회 후 `type` 필터가 필수다([저장개발참고](../참고/저장개발참고.md#인덱스)).
- 단어 참조 교체는 단어 인덱스만 훑으므로 이 유형에 닿지 않는다.
- `연결된 문서` 구역은 비어 있으면 숨긴다. 단어 페이지의 `연관된 관계가 없습니다.`와 다른 선택이다.
