# 2026-08-10 단어·문장 수정 시 관계 영향 confirm

## 문제

관계 페이지에서 관계의 단어를 바꾸려던 사용자가 `병합할까요?` 질의를 받아 승인했고,
그 단어를 참조하는 모든 관계가 바뀌는 사고가 났다. playwright 재현 결과 관계 페이지 자체는
`updateRelation` → `createWord`로 참조만 교체하며 병합을 묻지 않았다. 실제 경로는 단어 페이지의
미저장 수정 + `useWriterForm`의 `useBlocker`였다: 이탈 질의를 승인하면 그 자리에서 전역 개명이
실행되고, 대상 이름이 이미 있으면 병합 질의가 관계 화면으로 전환되는 시점에 떠서
관계 수정의 일부처럼 보였다.

## 해결

- `relation/countReferencingRelations`: 단어/문장을 참조하는 관계 수를 `relations` 인덱스
  `getAllKeys` + `Set`으로 중복 없이 센다 (한 관계가 문제와 답으로 이중 참조해도 1건)
- `relation/confirmRelationImpact`: 1건 이상이면
  `연결된 n건의 관계도 수정됩니다. 계속하시겠습니까?` 표준 confirm
- `useWriterForm`에 `confirmSave` 옵션 추가: 수정 버튼과 blocker의 저장 직전에 통과해야
  저장한다. mutation 시작 전에 거르므로 거부 시 성공 토스트도 뜨지 않는다
- `WordEditor`(항상), `SentenceWriter`(편집 모드에만)에 적용. 병합 질의는 종전대로 단어
  페이지에만 남는다. 문서는 관계가 참조하지 않아 제외
- playwright로 사고 경로(blocker 연쇄) 포함 5개 시나리오를 빈 프로필에서 검증
