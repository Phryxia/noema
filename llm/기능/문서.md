# 문서

1개 이상의 문장이 모인 매우 긴 문자열. 하나의 관심사를 서술하며 구조는 엉망일 수 있다. 대시보드의 문서 입력기, `/document/$documentId` 개별 문서 페이지, 최근 문서 순환 큐.

## 코드

- 디렉토리: `packages/client/src/document/`
- 타입: `document/types.ts`(`Document`, `RecentDocument`), 상수: `document/consts.ts`, 미리보기 길이: `document/document.service.ts`의 `PREVIEW_LENGTH`
- 서비스: `document/document.service.ts`(`createDocument`, `updateDocument`, `deleteDocument`, `getDocument`, `getRecentDocuments`), 배치 해석: `document/resolveDocumentMap.ts`
- 컴포넌트: `DocumentWriter`(생성·수정 폼, 파일 드롭), `RecentDocuments`, `DocumentSentences`([문장-추출](./문장-추출.md))
- 페이지: `routes/document.$documentId.tsx`
- 무효화: `document/utils.ts`(`invalidateDocumentQueries`)

## 사양

- 저장: `documents`(Key Path `documentId`, 자동 증가). 필드 규약은 [문장](./문장.md)과 같다(`source` 선택, `modifiedAt` 조건부). 최근 문서는 `recentDocuments` 순환 큐 4칸에 초입 64자 `preview`를 담는다.
- `DocumentWriter`: `textarea` + 출처 입력기 + 저장 버튼, `Ctrl+Enter` 저장, 최소 256px, 내용에 맞춰 자동 높이(`field-sizing: content`), 수동 조절 가능. 텍스트 파일을 드롭하면 내용이 폼에 들어가고 출처에 파일 이름이 기본값으로 들어간다. 탭은 눈에 보이지 않아도 되지만 `Tab` 가로채기는 문장과 같다. 본문 아래 태그 입력기([태그](./태그.md)).
- 개별 문서 페이지: 본문, `MetaFields`(`documentId`, `createdAt`, `modifiedAt`), 태그 입력기, `연결된 문장`(`DocumentSentences`: 이 문서에서 추출된 `DocumentToSentence` 관계 표, 0건이면 `문장 추출` 버튼, [문장-추출](./문장-추출.md)). 태그 관계는 이 표에 나오지 않는다.
- 수정 버튼은 본문·출처·태그 중 수정 사항이 있을 때만 활성. 관계 영향 질의는 적용하지 않는다. 삭제는 반영 후 메인으로. 미저장 수정 이탈 질의 적용([입력기](./입력기.md)).

## 결정 근거와 제약

- 관계 영향 질의를 두지 않는 이유: 문서를 참조하는 관계는 `DocumentToSentence`와 `Tag`뿐이고 문서 본문 수정이 그 관계의 뜻을 바꾸지 않는다.
- `preview`는 64자로 자르되 마지막이 상위 서로게이트면 한 글자 줄인다(`utils/sliceSafely.ts`). 이모지가 반토막 나는 것을 막는다.
- 공백 에코를 달지 않는 이유: 긴 산문에서 마커는 잡음이고, 기획이 탭을 보여주지 않아도 된다고 했다.
- 파일 드롭은 `dragover`를 `preventDefault`해야 `drop`이 온다. `preventDefault`는 `await`보다 먼저 부른다. 내용은 `file.text()`로 읽는다.
- 타입 이름 `Document`는 DOM 전역과 겹치나 모듈 스코프라 안전하다. `DocumentWriter`의 prop `document`가 전역을 가리지만 그 안에서 전역을 쓸 일이 없다.
- 문서 내 문장 수가 수백이면 `hydrateD2sEntries`가 건당 트랜잭션으로 읽는 비용이 있다. 한 트랜잭션 `getAll`로 바꿀 여지를 남겼다.
