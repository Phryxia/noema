# 2026-08-15 관계 히스토리 검색

## 문제

`/qna`는 시간순 커서 페이징뿐이라 특정 단어·문장이 얽힌 관계를 찾을 수 없었다.
부분문자열 판정은 IndexedDB 인덱스를 탈 수 없고, 정렬 기준(필드 순위, 매치 값 길이)도
저장 순서와 무관해 커서 페이징을 그대로 쓸 수 없었다.

## 해결

전수 조회 후 순수 함수로 판정·정렬하고, 전체 결과를 메모리에서 10건씩 잘라
기존 `computePagination`/`PageNavigator`의 탐사형 UX를 재현했다(`useExploredPagination`).
사양은 [관계 검색 기획](../../기획/화면/관계-검색.md)에 있다.

- 판정 대상 추출(`collectSearchTargets`)은 표시용 헬퍼(`getRelationAnswer`,
  `getQuestionWordIds`)를 쓰지 않고 저장 필드를 직접 매핑했다. BinaryAssociation의
  word2가 표시상 응답이어도 word2 필드로 판정해야 하기 때문이다.
- 정확/부분 두 섹션은 명세대로 서로 독립인 useQuery 2개로, 각자 전수 스캔한다.
  정확 일치한 관계는 부분 섹션에서 통째로 제외해 서로소를 보장한다.
- 검색 폼은 `WordField`+`WordSuggestion`+`useSuggestionFocus` 조합을 재사용하되,
  추천 선택·검색 수행 시 `isSuggestionMuted`로 추천기를 숨기고 입력 변경 시 다시 띄운다.
  ESC는 `WordField`에 `onEscape`를 신설해 IME `isComposing` 가드 뒤에서 처리했다.
- 최근 목록 계열(`useRecentPages`/`ensureRecentPage`)의 캐시를 무한+언마운트 삭제에서
  5분(`PAGE_CACHE_MS`)으로 바꾸고, 검색 결과도 같은 상수로 검색어별 5분 캐싱했다.
  `RecentListPage`에서 `RecentListSection`을 분리해 `/qna`는 검색 중 히스토리를
  언마운트 없이 `hidden`으로 숨겨, 취소 시 보던 페이지가 그대로 남는다.
- 무효화는 `invalidateWordAndQnaQueries`와 `invalidateRelationQueries` 두 경로 모두에
  `QNA_SEARCH_QUERY_KEY`를 추가했다.
- 검증: 순수 함수 vitest 20건 추가(전체 61건 통과), tsc·eslint 통과.
