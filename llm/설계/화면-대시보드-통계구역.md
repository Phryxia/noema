# 총 보유 통계

- 총 보유 단어 수는 [저장-단어](./저장-단어.md) 에서 추적하는 `wordSize` 활용
- 나머지는 Indexed DB의 `count` API 활용
- 갱신시점은 각 단어/문장/문서가 추가되거나 새로 접속 시

# 증가 추이 차트

- Chart.js 사용 (설치됨)
- 변화량/누적량을 매번 DB를 긁어서 계산하지 말고, 단어가 추가될 때 갱신하는 방식을 사용
- 시간 단위 별로 별도 Store 가짐
  - 1시간: `hourDelta`, `hourAcc`
  - 1일: `dayDelta`, `dayAcc`
  - 1주: `weekDelta`, `weekAcc`
- 각 Store는 인덱스 키 `beginDate` 대해, 다음의 레코드의 시간 선형 나열

```ts
interface CountLog {
  /**
   * 집계 개시 시각
   * 1시간 단위이면 00시부터 23시까지 고정적으로 bin을 가짐
   * 1일 단위 역시 날짜의 0시 이상 24시 미만까지를 기준
   * 1주 단위는 일요일이 기준
   * 브라우저가 인식하는 국가의 시간대 기준
   * */
  beginDate: Date
  wordCount: number
  sentenceCount: number
  documentCount: number
}
```

- 각 데이터를 추가하거나 **삭제**하는 시점에 해당되는 `CountLog`가 있으면 mutate, 없으면 insert
  - 이 과정을 동기적으로 기다리지 않음
  - 다만 트랜잭션은 원래 조작의 트랜잭션이 커밋된 직후 **동기적으로** 연다.
    그래야 뒤이어 열리는 조회 트랜잭션이 이 기록보다 늦게 실행되는 것이 보장된다.
- `delta`는 해당 bin의 **순증감**을 누산한다. 추가는 +1, 삭제는 -1이므로 **음수가 될 수 있다**.
- `acc`는 해당 bin에서 마지막으로 관측된 총 보유량을 덮어쓴다. 삭제 직후에도 갱신하므로 총 보유 통계와 어긋나지 않는다.
- 실제로 존재하지 않는 항목을 지우려 한 경우는 기록하지 않는다. 지워진 것이 없으므로 순증감이 0이다.

같은 bin 안에서 3개를 넣고 1개를 지웠으면 `delta`는 2다. 추가 3과 삭제 1을 따로 복원할 수는 없다.
bin의 순증감만으로 추이를 읽는다는 뜻이며, 이것이 Store를 늘리지 않고 삭제를 반영하는 값이다.

## 초기 백필

`DB_VERSION` 1에서 2로 올라갈 때, 통계 Store가 비어 있는데 데이터는 이미 존재하는 상태가 된다.
누적이 0에서 시작해 총 보유 통계와 크게 어긋나므로, 스키마를 만든 직후 같은 `versionchange` 트랜잭션에서 백필한다.

- `wordNodes`(`createdAt`이 있는 노드만), `sentences`, `documents`를 커서로 전수 순회해 `createdAt`을 모은다.
  - `getAll`을 쓰지 않는다. 문서 본문까지 통째로 메모리에 올라온다.
- 시간 단위별로 bin에 개수를 집계해 `delta`를 만들고, 시간순 누적합으로 `acc`를 만든다.
- 레코드가 없는 bin은 쓰지 않는다. 조회 시 결측 bin 규칙이 처리한다.
- 이미 삭제된 항목은 `createdAt`이 남아있지 않으므로 세지 않는다.
  따라서 과거 bin의 `delta`는 당시 실제 증가량보다 작을 수 있다. 반면 `acc`의 마지막 값은 현재 총 보유량과 일치한다.

## 결측 bin 처리

노출 구간의 bin 중 레코드가 없는 것은 모드에 따라 다르게 채운다.

- `delta`: 0. 그 시간대에 아무 변화도 없었다는 뜻이다.
- `acc`: 직전 bin의 값을 이어받는다(계단 유지). 이어받을 값이 없으면 0이다.
  - 노출 구간 시작 이전의 마지막 레코드가 필요하므로, 시작 bin 미만 범위를 역방향 커서로 1건 읽는다.
  - 누적을 0으로 떨어뜨리면 톱니 모양이 되어 누적의 정의에 어긋난다.
    기획의 "없는 값은 0으로 처리"는 데이터가 시작되기 이전 구간에 대한 규정으로 읽는다.

## 차트 구성

종류별로 차트를 하나씩, 총 3개를 한 행에 나란히 둔다. 시간 단위 필터와 모드 필터는 세 차트가 공유한다.
한 차트에 세 종류를 겹치면 단어가 문장·문서보다 훨씬 빨리 늘어 나머지가 바닥에 눌린다.

- 배치는 `flex-wrap`이며 각 차트의 `flex-basis`는 `18rem`이다. 폭이 모자라면 다음 줄로 밀린다.
  `18rem`보다 좁히면 x축 라벨을 알아볼 수 없다.
- 차트의 종횡비는 2다. 세 개가 한 행에 들어오므로 각각은 폭도 높이도 통계 구역 전체를 쓰던 때의 절반 이하다.

계열 구성은 모드에 따라 다르다.

| 모드   | 계열                                     |
| ------ | ---------------------------------------- |
| 변화량 | `증가`(`delta`의 양수부), `삭제`(음수부) |
| 누적   | `보유`(`acc`)                            |

- 변화량 모드에서 `delta`가 음수인 bin은 `증가`가 0, `삭제`가 절댓값이다. 두 계열 모두 0 이상이라 축이 아래로 내려가지 않는다.
- 누적은 총 보유량이라 음수가 없다. 계열이 하나다.
- `증가`와 `보유`는 종류별 색, `삭제`는 세 차트가 같은 붉은색을 쓴다. 차트가 이미 종류로 나뉘어 있어 색으로 종류를 구분할 필요가 없다.
