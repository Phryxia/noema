# 도구

`/tools`. 기존 단어를 조합하거나 복잡한 관계를 한 번에 짓는 기능을 모은 페이지. 공통 헤더의 `도구` 링크로 들어간다. 상단 탭 서브 네비게이터(`ChoiceGroup`)로 도구 하나를 골라 노출하며, 선택은 `?tab=` 쿼리에 실린다.

## 코드

- 디렉토리: `packages/client/src/tools/`
- 페이지: `routes/tools.tsx`(`validateSearch`) -> `tools/ToolsPage.tsx`, 탭 판정 `tools/toolsTab.ts`, 공용: `tools/keepFieldFocus.ts`
- 순서화: `tools/ordering/OrderingTool.tsx`, `useOrderingTool.ts`, `submitOrdering.ts`, `computeAdjacentPairs.ts`(+test), `consts.ts`(`NEXT_RELATION_NAME`, `MIN_ORDERING_WORD_COUNT`)
- 다국어 매핑: `tools/i18n/I18nMappingTool.tsx`, `useI18nMappingTool.ts`, `submitI18nMapping.ts`, `computeMappingTuples.ts`(+test), `checkMappingReady.ts`(+test), `createInitialMatrix.ts`, `MappingResultDialog.tsx`
- 가변행렬 `tools/i18n/MatrixField/`: `MatrixField.tsx`, `MatrixCell.tsx`, `MatrixControls.tsx`, `useMatrixNavigation.ts`, `types.ts`, `computeMatrixNavigation.ts`(+test 2), `resizeMatrix.ts`(+test)
- 일본어 매핑: `tools/jp/JapaneseMappingTool.tsx`, `consts.ts`, `createInitialJapaneseMatrix.ts`. 나머지는 다국어 매핑의 부품을 그대로 쓴다
- 공용 배치 절차와 결과 표: [관계-배치](./관계-배치.md)

## 사양

### 서브 네비게이터

- 탭은 순서화(`order`), 다국어 매핑(`i18n`), 일본어(`jp`) 셋. 선택된 탭의 도구만 렌더한다.
- `?tab=i18n`과 `?tab=jp`가 유효한 쿼리다. 값이 없거나 무효하면 순서화로 동작하고 URL에 쿼리를 되쓰지 않는다. 순서화 선택은 키 제거(`tab: undefined`)다.
- `validateSearch`가 무효 키를 떨어뜨리지만 직접 진입 시 `useSearch`가 원본을 줄 수 있어 `ToolsPage`가 재검증한다. 두 곳이 같은 판정을 하므로 `toolsTab.ts`의 `resolveToolsTab`(무효값이면 `order`) 하나를 쓴다.
- 탭마다 다른 컴포넌트를 렌더하므로 전환 시 언마운트되고 행렬 상태가 섞이지 않는다.

### 순서화

- 단어 리스트 `[w1, ..., wn]`을 받아 인접한 두 단어마다 관계 짓기 `(w_i, w_{i+1}, 다음)`을 만든다. `w_i`가 `word1`, `w_{i+1}`이 `word2`, 관계 이름 `word3`은 고정 단어 `다음`.
- 입력칸은 알려주기 예문 만들기의 동적 칸(`SubjectWordFields`, `isCountAdjustable`)과 같다. 처음 2칸, 세 번째부터 `(optional)`, 주사위 없음.
- 채워진 단어가 2개 이상이어야 제출 가능. 빈 칸은 위치와 무관하게 무시하고 채워진 단어끼리 순서대로 쌍을 만든다. 같은 단어가 겹쳐도 막지 않는다.
- 제출 버튼은 입력칸 바로 아래. 절차·결과 표·토스트는 배치 모드와 같다. 성공이 하나라도 있으면 첫 칸에 포커스한 뒤 칸을 2칸으로 되돌린다.

### 다국어 매핑

- 가변행렬 표(최소 1x1, 초기 2열x3행). 각 열이 같은 언어, 각 행이 같은 의미의 단어다. 첫 행은 언어 이름 행으로 placeholder `언어1`, `언어2`, ...를 갖는다.
- 표 오른쪽 10px에 표 높이만큼의 `+`(열 추가), 아래 10px에 표 폭만큼의 `+`(행 추가), 위 10px에 열마다 `-`(열 삭제), 왼쪽 10px에 행마다 `-`(행 삭제). 남은 행·열이 편집 가능한 것 하나뿐이면 삭제 버튼 비활성.
- 커서 이동: 끝 커서 오른쪽 키는 다음 열 처음(마지막 열이면 다음 행 첫 열), 시작 커서 왼쪽 키는 이전 열 마지막(첫 열이면 이전 행 마지막 열), 위/아래 키는 이웃 행 같은 열의 같은 문자수(부족하면 끝). 단 아래 키는 추천 목록이 떠 있으면 목록 진입이 우선이고, 없을 때만 행 이동이다. Tab은 캐럿과 무관하게 다음 칸 처음. Enter는 아래 이동이되 마지막 행에서는 삼킨다(암묵 제출 방지). 그 외 이동할 칸이 없으면 브라우저 기본 동작. 탭 문자는 붙여넣기를 포함해 입력되지 않는다.
- 데이터 행 셀에는 단어 추천 목록이 뜬다(포커스된 셀만, x 삭제 버튼 없음). 항목 선택 시 셀 값이 그 단어로 치환되고 포커스가 셀로 복귀한다. 헤더 행에는 뜨지 않는다. 목록이 뜬 동안 표 스크롤러의 클리핑이 해제된다(`.scroller:focus-within`).
- 제출 버튼은 개별 문서 페이지처럼 bottom sticky. 데이터가 있는 모든 열의 언어 이름이 채워지고 만들 관계가 1개 이상이어야 활성.
- 제출은 행렬의 모든 비어있지 않은 단어(헤더 포함)를 `upsertWord`로 확보한 뒤, 데이터 행마다 채워진 두 열 `(j, k)`에 대해 `(matrix[i][j], matrix[i][k], matrix[0][k])` 관계 짓기를 만든다. 언어 이름이 빈 열로 향하는 관계는 제외. 같은 값 삼중쌍은 한 번만 시도하고, DB 중복은 건너뛴다.
- 열 쌍 `(j, k)` 목록을 `computeMappingTuples`·`checkMappingReady`·`submitI18nMapping`에 넘길 수 있다. 다국어 매핑은 넘기지 않아 모든 순서쌍을 쓰고, 일본어 매핑이 이 인자로 방향을 좁힌다.
- 완료 시 모달(`MappingResultDialog`)에 신규 단어를 콤마로 나열하고 추가된 관계 수(중복 제외)를 표기한다. 0개여도 모달을 띄우며 배치 모드의 전부-중복 throw 경로를 타지 않는다. 닫으면 행렬이 초기 크기로 리셋(리셋 자체는 제출 직후)되고 첫 편집 칸에 포커스한다.

### 일본어 매핑

- 다국어 매핑과 같은 표·커서 이동·제출 절차를 쓰되 둘을 고정한다. 화면 셸과 상수만 `tools/jp/`에 있고 행렬 입력칸·튜플 계산·제출·훅·결과 모달은 다국어 매핑의 것을 그대로 쓴다.
- 헤더 행이 `일본어`, `読み仮名`, `한국어`로 고정된다. 헤더 칸은 입력칸이 아니라 굵은 라벨이고, 커서도 열 추가·삭제도 헤더 행에 닿지 않는다. 초기 데이터 2행, 행 추가·삭제만 가능하다.
- 만드는 관계는 열 쌍 `[0,2]`, `[0,1]`, `[2,0]` 셋, 곧 `일본어->한국어`, `일본어->読み仮名`, `한국어->일본어`다. `読み仮名->일본어`는 만들지 않는다.
- 채운 칸에 따라 관계 수가 정해진다. 세 칸을 다 채우면 3개, 일본어와 한국어만 채우면 2개, 일본어와 `読み仮名`만 채우면 1개, 일본어 칸이 비면 만들 관계가 없어 제출할 수 없다.
- 고정 헤더 세 단어도 제출 때마다 `upsertWord`로 확보한다. 관계 이름으로 쓰이기 때문이며, 빈 열의 헤더도 마찬가지다.

## 결정 근거와 제약

- 결과를 표+토스트로 보이는 도구는 `submitNamedAssociations`·`useBatchSubmission`·`BatchResultTable`을 재사용한다(순서화). 결과를 모달로 보이는 도구는 `submitNamedAssociation`(단일 튜플)과 `useMutation`을 직접 쓴다(다국어 매핑). 도구 고유 로직(쌍·튜플 만들기, 커서 판정)은 순수 함수로 두어 테스트한다.
- 매핑 계열 도구가 늘 때는 공통 부품에 선택 인자를 더해 재사용하고, 도구마다 다른 것(제목·설명·초기 행렬·헤더 고정 여부·열 쌍)만 새 디렉토리에 둔다. `MatrixField`는 헤더 편집 가능 여부 하나(`header: MatrixHeaderOption`)만 받고 열 크기 조절 가능 여부는 거기서 유도한다. 헤더 라벨이 고정이면 새 열의 이름이 없어 열 추가가 정의되지 않기 때문이다.
- 다국어 매핑의 세부 판단(튜플 사전 dedup, Enter 삼킴, 리셋/포커스 분리 등)은 [일지](../일지/2026-08-31-도구-다국어-매핑과-탭-네비게이터.md)에, 일본어 매핑의 판단(고정 헤더를 input으로 두지 않는 이유, 커서·삭제 버튼의 하한, 그리드 트랙)은 [일지](../일지/2026-08-31-도구-일본어-매핑.md)에 있다.
- 초기화 순서가 포커스 먼저, 상태 리셋 나중인 이유는 [입력-포커스참고](../참고/입력-포커스참고.md#상태-갱신과-포커스-순서).
