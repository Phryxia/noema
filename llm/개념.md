# 개념

노에마(NOEMA)의 동기와 데이터 개념의 정의. 구현 단위별 사양은 `기능/`, 진입 색인은 [README](./README.md)에 있다.

# 동기

언어는 세상을 바라보는 도구이자 동시에 세상으로부터 물려받은 지식을 반영한다.
LLM은 인터넷의 불특정 대량 정보를 학습해 박식하지만 한 지적 주체로서의 자아가 결여돼 있다. 반면 인간은 태어난 이후 세상의 아주 일부만 학습했지만 그만큼 자신이 바라보는 세계관을 갖는다.

노에마는 한 개인의 머릿속에 숨겨진 언어 지식을 최대한 이끌어내어 데이터로 만들기 편하게 하는 것을 목표로 한다. 단어와 문장을 극도로 잘게 쪼갠 단위로 다루며, 개별 항목보다 **항목들 사이의 연관관계**를 핵심 가치로 삼는다. 세부 기획은 진행하며 구체화한다.

# 형태

웹 클라이언트 단독이며 모든 데이터는 브라우저의 Indexed DB에 있다. 네트워크 요청은 없고 PWA로 설치된다. `packages/server/`는 스텁이다. 백업은 JSON 파일로 주고받는다([설정-백업](./기능/설정-백업.md)).

# 데이터

## 단어(Lexis)

짧은 문자열. 일반적인 뜻과 달리 문법 정보도 뜻의 정의도 없다. 존재하는 것은 다른 개체들과의 관계뿐이다.

ex) 호랑이, strawberry, 確認, かえる

- 중복될 수 없으므로 유니크 키로 쓴다.
- 대소문자가 다르면 다른 단어다. 앞뒤 공백도 다듬지 않는다.
- 기호도, 공백만으로 된 것도 단어가 될 수 있다.
- 저장은 Trie다([단어](./기능/단어.md)).

## 문장(Sentence)

긴 문자열. 1개 이상의 단어로 분해 가능하지만 명시적으로 표현하지는 않는다. 무엇을 단어로 표현할지 문장으로 표현할지는 인간이 정한다. 선택적 출처를 갖는다([문장](./기능/문장.md)).

## 문서(Document)

1개 이상의 문장이 모인 매우 긴 문자열. 하나의 공통된 관심사를 서술하며 구조는 엉망일 수 있다. 제목을 하나 갖는데 제목도 문장이며 관계로 연결된다([문서](./기능/문서.md)).

## 관계(Relation)

두 개 이상의 데이터를 연결하는 레코드. 방향이 의미가 있다. `relations` Store 한 곳에 담기며 `type`으로 갈린다. 수정 개념이 없는 유형은 생성 시각만 갖는다.

| 구분 | 유형 | 뜻 | 만드는 곳 |
| --- | --- | --- | --- |
| 단어 관계 | 단어 설명 `WordExplain` | 단어의 뜻을 문장으로 | 탐색, 알려주기 |
| | 예문 만들기 `WordsUsage` | 단어 n개를 쓴 문장(회피 가능) | 탐색, 알려주기 |
| | 속성 `UnaryProperty` | 단어가 갖는 속성 단어 | 탐색, 알려주기 |
| | 이항 공통점 `BinaryCommon` / 차이점 `BinaryDifference` | 두 단어의 공통점·차이점(단어·문장, 무응답 가능) | 탐색, 알려주기 |
| | 이항 유사성 `BinarySimilarity` | 두 단어의 관련 정도 5단계 | 탐색, 알려주기 |
| | 연상 `BinaryAssociation` | 단어에서 연상되는 단어 | 탐색, 알려주기 |
| | 삼항 격리 `TernaryIsolation` | 세 단어 중 가장 이질적인 것 | 탐색, 알려주기 |
| | 삼항 합성 `TernaryComposition` | `w3 = w1 + w2` | 탐색, 알려주기 |
| | 관계 짓기 `NamedAssociation` | `w1 -w3-> w2`, `w3`이 관계 이름 | 알려주기, 배치, 도구 |
| 추출 관계 | 문장 추출 `DocumentToSentence` | 문서에서 잘라낸 문장 | 문장 추출 |
| | 단어 추출 `SentenceToWord` | 문장에서 잘라낸 단어 | 단어 추출 |
| 제목 | 문서 제목 `DocumentTitle` | 문서의 제목인 문장 | 문서 입력기, 마이그레이션 |
| 태그 | `Tag` | 문장·문서에 붙인 단어 | 태그 입력기 |

- 단어 관계는 선택적 참고사항(`comment`, 단어 또는 문장)을 갖고 수정할 수 있다. 추출 관계·제목·태그는 참고사항이 없고 삭제만 된다. 제목은 문서 입력기에서 문장을 직접 고친다.
- 관계가 관계를 연관짓는 것은 아직 없다. 관계 이름을 갖는 것은 관계 짓기뿐이며, 그 이름도 단어다.
- 항목을 지워도 관계는 남고, 사라진 대상은 `(삭제됨)`으로 보인다. 단어만 예외로, 개명·삭제 시 참조가 다른 단어로 교체된다.
- 내용이 같아도 별개 항목이며 내용 기반 중복 제거를 하지 않는다. 유일한 예외는 삼항 관계의 (w1, w2, w3) 중복 차단이다.

모델의 세부는 [관계](./기능/관계.md), 저장 규약은 [저장-공통](./기능/저장-공통.md).

# 문제와 응답

**문제**는 유형과 주어진 단어 id 목록이다. 저장하지 않으며, 제출하면 관계가 된다. 모든 문제는 풀지 않고 건너뛸 수 있고 그 경우 아무것도 남지 않는다.

**응답**은 문제에 답하는 것이고, 응답으로 만들어진 데이터가 관계다. 모든 응답은 관계로 남아 추후 학습 자료가 된다.

탐색은 시스템이 단어를 뽑아 문제를 내고([탐색](./기능/탐색.md)), 알려주기는 사용자가 유형·단어·답을 직접 지정한다([관계](./기능/관계.md)). 문제 출제기는 현재 무작위이며, "무의미한 무관계 재확인"을 줄이는 출제기는 구상 중이다.
