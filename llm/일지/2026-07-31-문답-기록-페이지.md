# 2026-07-31 문답 기록 페이지

## 문제

`/qna`에서 출제된 문제와 응답을 최근 목록과 같은 UX(기간 검색, 커서 페이지네이션)로 보여줘야 했다.
그러나 recent 모듈은 `RecentEntry {id, value, createdAt, source?}` 고정 형태에 묶여 있어,
관계의 다중 필드(유형, 단어들, 답, 유사도, 선택, 참고)를 담을 수 없었다. 복제하면 커서 로직이 통째로 중복된다.

## 해결

**recent 모듈을 제네릭화했다.** `RecentSource<TEntry, TRow>`로 타입 파라미터를 2단으로 갈랐다.
`TRow`는 커서에서 뽑은 원시 행, `TEntry`는 hydrate 후 표시용이다. 서비스 내부에 고정돼 있던 변환을
`toEntry: (id, stored) => TRow`로 소스의 책임으로 옮기고, 기존 형태는 `toRecentEntry`로 승격해 세 소스가 공유한다.
`RecentListPage`는 `hasSource`/`EntryLink` 대신 `Table: ComponentType<{ entries: TEntry[] }>` 슬롯을 받고,
빈 목록 early return은 `RecentTable`에서 `RecentContent`로 올려 표 구현들이 각자 반복하지 않게 했다.

**표는 relations만 읽는다.** 관계가 문제의 단어 필드를 복사해 가지므로([탐색 Store](../../설계/저장-탐색.md))
`questions`를 조회할 필요가 없고, 관계 없는 문제 잔재는 저절로 빠진다. `qna/hydrateQnaEntries`가
한 페이지의 단어 id(문제 단어 + word형 answer/comment)를 중복 제거해 `getWordValues` 1회로 배치 해석하고,
문장은 `getSentence`를 `Promise.all`로 모은다. 응답 셀은 `QnaAnswer` 태그 유니온(text/skip/similarity/selection)으로
유형별 분기를 hydrate 시점에 끝내, 렌더 컴포넌트는 kind만 본다. 삭제된 대상은 빈 문자열로 해석돼 `(삭제됨)`으로 그린다.
