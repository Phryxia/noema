# 2026-09-04 다이어리 페이지

## 문제

문서 입력기로 긴 글을 쓸 때 마크다운으로 해석된 결과를 볼 수단이 없었다. 최상단 내비게이터에 `/diary`(라벨 `다이어리`, 사용자 확정)를 신설하고, 기존 문서 입력기를 그대로 두되 본문을 오른쪽에 실시간 렌더링하기로 했다. 라이브러리는 markdown-it, DOM 구조는 출력 그대로 쓰고, pico 영향으로 스타일이 깨지지 않아야 했다.

## 해결

- `DocumentWriter`의 draft가 `useWriterForm` 내부에 있어 프리뷰가 본문을 볼 수 없었다. 상태를 페이지로 끌어올리는 대안은 기존 사용처(대시보드, 개별 문서)까지 바꿔야 해서 기각하고, optional prop `onValueChange`를 더해 `useEffect`로 `draft.value` 변화를 올렸다. effect라서 타이핑·파일 드롭·저장 후 리셋(useWriterForm 내부에서 일어남)을 한 경로로 포섭한다.
- markdown-it 옵션은 `html: true`(사용자 지시). 처음 계획은 `html: false`였으나 원문 HTML을 프리뷰에 그대로 렌더하는 쪽으로 확정됐다.
- LaTeX 대책(사용자 지시): `@mdit/plugin-katex` + `katex`. `katex/dist/katex.min.css`를 `MarkdownPreview`에서 import한다. 잘못된 수식은 KaTeX 기본 동작이 `.katex-error`로 그 수식만 표시하고 나머지 본문은 렌더됨을 playwright로 확인했다(`$\frac{$` 뒤 문단 생존).
- KaTeX 폰트(woff2)가 PWA 프리캐시 glob에 없어 오프라인에서 수식 글리프가 폴백으로 깨질 것이라 `vite.config.ts`의 `globPatterns`에 `woff2`를 더했다. 빌드 프리캐시가 123 entries, 1426KiB가 됐다.
- 레이아웃은 CSS Module 2열 grid(`1fr 1fr`, 768px 이하 1열). pico specificity 경쟁이 없는 속성만 써서 `:global(.pico)` 승격이 필요 없었다. grid 자식에 `min-width: 0`을 줘 코드 블록·표가 열을 밀지 않게 했다.
- 프리뷰의 목록 마커는 `global.css`의 `:where(.pico ul) { list-style: square }`가 그대로 살아 square로 보인다. 검증에서 `listStyleType: square`, `documentElement.scrollWidth === innerWidth` 확인.
- diary 청크가 375KB(gzip 126KB)다. markdown-it과 katex가 라우트 청크로 분리되어 다른 페이지에는 영향이 없다.

## 남은 것

- `vite build`를 저장소 루트에서 `--config`로 돌리면 router 플러그인이 `src/routes`를 루트 기준으로 찾아 실패한다. `packages/client`에서 실행해야 한다.
