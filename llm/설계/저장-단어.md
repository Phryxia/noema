# 단어의 경우

- 상위문서: [타입별 Store](./저장-스토어.md)

## Word Meta Store

스토어 이름은 `wordMeta`. Key Path를 가지지 않으며, 정해진 키는 다음과 같다.

- `trieNodeSize`
  - 총 기록된 노드 수 (루트 포함)
  - 기본값 1
  - 노드 삭제 시 감소
- `wordSize`
  - 총 기록된 단어 수
  - 기본값 0 (루트는 단어가 아님)
- `nextNodeId`
  - 다음에 발급할 `nodeId`
  - 기본값 1 (루트가 0을 차지)
  - 노드 생성 시 이 값을 쓰고 1 증가시키며, 삭제해도 되돌아가지 않는다

## Word Store

Store 이름은 `wordNodes`. Key Path로 `nodeId`를 갖는다.

```ts
interface TrieNode {
  // 이 Trie Node를 식별하는 unique한 숫자
  // auto increment
  nodeId: number
  // 이 TrieNode의 부모의 nodeId. 루트이면 undefined.
  parentNodeId?: number
  // parent에서 이 노드로 오는 길이 1의 UTF-8 문자. 루트이면 빈 문자열.
  value: string
  // 길이 1의 UTF-8 문자에 대응되는 자식들의 id
  children: Record<string, number>
  // isEnd를 겸한다. 특정 단어가 주입된 시각을 저장한다.
  createdAt?: Date
  // 단어가 수정(개명)된 시각. 수정된 적 없으면 키 자체가 없다.
  modifiedAt?: Date
}
```

`wordNodes`가 비어있으면 루트노드(`nodeId`는 0, `value`는 빈 문자열, `children`은 빈 객체)를 먼저 넣는다.

`createdAt`에 인덱스가 있다. 이 값이 없는 중간 노드는 인덱스에 들어가지 않으므로, 인덱스를 훑으면 단어인 노드만 추가된 순서로 얻는다.
[최근 목록](../기획/화면/최근-목록.md)의 단어 페이지가 이 순서를 쓴다.

단어 문자열과 `nodeId`는 다음과 같이 오간다. 라우트가 `/word/[:word]`이므로 이 변환은 페이지 진입마다 일어난다.

- 문자열에서 `nodeId`로: 루트에서 시작해 문자를 하나씩 `children`으로 따라 내려간다. 도중에 끊기면 없는 단어다. 길이가 L인 단어라면 L+1번의 `get`이 필요하다.
- `nodeId`에서 문자열로: `parentNodeId`를 루트까지 거슬러 오르며 `value`를 모은 뒤 뒤집는다.
- 접두사 나열(`WordSuggestion`)은 접두사에 해당하는 노드를 찾은 뒤, 거기서 DFS로 내려가며 경로 문자열을 누적한다. `createdAt`이 있는 노드만 단어다.

## 단어 수정 규칙

단어 수정은 Trie 구조상 새 노드 발급이므로 nodeId가 바뀐다. 전 과정은
`wordMeta`, `wordNodes`, `recentWords`, `relations`를 범위로 하는 단일 `readwrite` 트랜잭션이다.

- 개명(수정 결과가 존재하지 않는 단어인 경우)
  1. 새 값의 경로를 삽입하고, 리프에 원본의 `createdAt`을 그대로 옮기며 `modifiedAt`에 현재 시각을 기록한다.
  2. 원본 노드를 _단어 삭제 규칙_ 대로 제거한다. 삽입을 먼저 해야 공유 접두사가 헛되이 지워졌다 재생성되지 않는다.
  3. `relations`와 `questions`의 단어 참조에서 원본 nodeId를 새 nodeId로 교체한다. 절차는 [탐색 Store](./저장-탐색.md)의 삭제 절에 있다.
  4. `recentWords`에 원본이 있으면 그 슬롯의 `nodeId`와 `value`를 제자리에서 고친다. `createdAt`은 유지된다.
  - `wordSize` 순변화가 0이므로 통계는 기록하지 않는다.
- 병합(수정 결과가 이미 있는 단어인 경우)
  - 사용자 확인을 받은 뒤에만 수행한다. 새 경로 삽입이 없고, 참조 교체의 대상이 기존 단어의 nodeId일 뿐 절차는 개명과 같다.
  - `recentWords`에 원본과 대상이 모두 있으면 큐에 같은 nodeId가 중복되므로, 원본 슬롯은 교체 대신 `null`로 비운다.
  - 병합 대상의 `modifiedAt`은 건드리지 않는다. 단어 수가 1 줄므로 통계 감소를 기록한다.
- 같은 값으로의 수정은 아무것도 하지 않는다.

## 단어 삭제 규칙

단어 삭제 시 Trie도 정리한다.

1. 해당 노드의 `createdAt`과 `modifiedAt`을 제거하고 `wordSize`를 1 줄인다.
2. 그 노드에 `createdAt`도 없고 `children`도 비어있으면, 부모의 `children`에서 자신을 지운 뒤 Store에서 제거하고 `trieNodeSize`를 1 줄인다.
3. 부모에 대해 2를 반복한다. 루트노드는 제거하지 않는다.

삭제하려는 단어를 참조하는 관계가 있으면 그냥 지울 수 없다. 사용자가 삭제를 취소하거나, 참조를 대체할 단어를 지정해야 한다.

- 대체 단어가 존재하지 않으면 같은 트랜잭션에서 생성되며, 이때 `recentWords`에도 오른다.
- 참조 교체를 동반한 삭제는 단어 수정과 같은 5개 Store 단일 트랜잭션이다.
- 대체 단어를 새로 만들었으면 통계에 생성과 삭제를 모두 기록하고, 기존 단어면 삭제만 기록한다.

## 최근 추가된 단어

최근에 추가된 단어는 최대 10개까지 보관하는데 이는 별도 Store가 필요하다.
순환 큐처럼 다룬다.

Store 이름은 `recentWords`. Key Path를 가지지 않으며, 정해진 키는 다음과 같다.

- `0` ~ `9`: 추가된 단어 최대 10개에 대응되는 인덱스. 만약 아직 존재하지 않거나 삭제됐으면 값이 `null`일 수 있다.
- `next`: 최초에 `0`. `wordNodes`에 단어가 추가되면 `recentWords[recentWords.next]`에 `RecentWord`를 쓴 뒤 1을 더하고 10으로 나눈 나머지로 갱신한다.

```ts
interface RecentWord {
  // TrieNode의 ID
  nodeId: number
  // 해당 TrieNode가 표현하는 총 문자열 (ex: apple)
  value: string
  // 추가한 시각
  createdAt: Date
}
```

읽을 때는 `next - 1`부터 역방향으로 순회하여 최근 순으로 얻는다. `null`인 칸은 건너뛴다.
