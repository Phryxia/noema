# 2026-08-31 문장 페이지 연관 단어 관계 삭제

## 문제

개별 문장 페이지의 `연관 단어` 표는 조회 전용이라 잘못 추출된 단어 관계 하나를 지우려면 행을 눌러 개별 관계 페이지로 가서 삭제하고 돌아와야 했다. 게다가 관계를 지운 뒤 그 단어가 더 이상 어디에서도 참조되지 않으면 단어 자체도 지우고 싶은 경우가 많은데, 그러려면 다시 단어 페이지로 가야 했다.

요청 범위는 셋이다. 개별 문장 페이지에서만 삭제할 수 있을 것, 표의 맨 오른쪽에 삭제 버튼을 둘 것, 관계 삭제 뒤 단어를 삭제할 수 있는 상태면 `단어도 삭제할까요? (확인 시 삭제)`를 물어 확인 시 단어도 지울 것.

## 해결

- `PairTable`에 선택적 `renderAction` prop을 더해 `날짜` 오른쪽에 열을 하나 더 그린다. `D2sTable`·`TagTable`은 넘기지 않으므로 그대로다. `S2wTable`은 `onDelete`가 있을 때만 `x` 버튼을 그 열에 넣고, `SentenceWords`만 `onDelete`를 넘긴다. 개별 단어 페이지의 `WordSentences`는 같은 표를 쓰지만 버튼이 없다.
- `RelationRow`의 행 클릭 이동 가드를 `closest('a')`에서 `closest('a, button')`로 넓혔다. 버튼 쪽에서 `stopPropagation`을 하는 대신 행이 양보하는 쪽을 택했다. 셀 안에 버튼을 두는 표가 앞으로도 생길 것이고, 행이 "링크와 버튼에는 양보한다"는 한 규칙을 갖는 편이 셀마다 전파를 막는 것보다 낫다.
- 삭제 흐름은 `s2w/SentenceWords/useSentenceWordDeletion.ts`. 관계 삭제 mutation(`deleteRelation`)의 `onSuccess`에서 `invalidateRelationQueries` -> `hasWordReferences(wordId)` -> 참조가 없으면 `window.confirm` -> 확인 시 단어 삭제 mutation(`deleteWord`, `invalidateWordAndQnaQueries`). 저장 계층 코드는 새로 만들지 않았다.
- "단어를 삭제할 수 있는 상태"는 `hasWordReferences`가 거짓인 것으로 정의했다. 이 함수는 단어 인덱스 전부(단어 관계 10종, `SentenceToWord`, `Tag`)를 세므로 다른 문장의 추출 관계나 태그가 남아 있으면 묻지 않는다. `WordSuggestion`·`WordEditor`의 삭제 게이트와 같은 판정이다.
- mutation을 하나로 합쳐 mutationFn 안에서 confirm하는 안은 기각했다. `meta.successMessage`가 정적 문자열이라 관계만 지운 경우와 단어까지 지운 경우를 한 토스트로 구분할 수 없고, `WordEditor`의 병합 confirm처럼 취소해도 토스트가 뜨는 부정확이 재현된다. 둘로 나누면 `관계를 삭제했습니다`와 `단어를 삭제했습니다`가 각각 정확히 뜬다.
- 버튼 스타일은 `WordSuggestion.module.css`의 `.deleteButton`과 같은 여백·테두리 없는 `x`. pico `button`(0-1-1)을 이기려고 `:global(.pico) .root .action button`(0-3-1)로 승격했다. 열은 `width: 1%; text-align: right`로 `날짜` 열과 같은 규칙이다.

playwright(스크래치패드 임시 설치, 개발서버 5173, `corpus.json` 시드)로 확인한 것:

- `x` 클릭 시 관계 페이지로 이동하지 않고 행이 사라지며 `관계를 삭제했습니다` 토스트가 뜬다.
- 단어가 다른 관계에 참조되면 confirm이 뜨지 않는다.
- 참조가 없으면 confirm이 뜨고, 취소하면 단어가 남고, 확인하면 `단어를 삭제했습니다` 토스트가 뜨며 `/word/<값>`이 존재하지 않는 단어가 된다.
- 마지막 관계를 지우면 `단어 추출` 버튼으로 돌아온다.
- 개별 단어 페이지의 `단어를 추출한 문장` 표에는 버튼 열이 없다.

## 남은 것

- `PagedSection`은 마지막 페이지의 유일한 행을 지워도 `currentPage`를 줄이지 않아 빈 표가 남는다. 이번 작업으로 처음 드러나는 경우지만 요청 범위 밖이라 두었다.
