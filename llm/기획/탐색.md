# 탐색

탐색 페이지는 단어, 문장의 관계를 효과적으로 발굴할 수 있도록 질문을 던진다.
화면 사양에 관해선 [이 페이지](./화면/탐색.md) 을 참고하라.
Store 스키마와 조작 절차는 [탐색 Store](../설계/저장-탐색.md)에 있다.

단어가 10개 이상인 경우에만 탐색 탐색을 할 수 있다.
단어가 10개 미만인 경우 `단어가 부족하여 문제를 생성할 수 없습니다`를 출력한다.

## 개념

### 문제(`Question`)

**문제(`question`)** 는 답할 수 있는 질문이다.

```ts
interface Question {
  type: string
  /** Primary Key */
  questionId: number
  /** Index */
  createdAt: Date
}
```

모든 문제는 풀지 않고 다음으로 넘길 수 있다.
이 경우 응답을 생성하지 않는다.

---

### 응답과 관계(`Relation`)

**응답(`answer`)** 은 주어진 문제에 답을 하는 것이다.

**관계(`Relation`)** 는 응답을 통해서 만들어진 데이터다.

모든 질문과 응답은 그 내역을 저장한다.
추후에 다른 형태로 학습자료로 쓸 수 있다.

몇 가지 공용 타입이 있다.

```ts
interface Relation {
  type: string
  /** Primary Key */
  relationId: number
  questionId: number
  /** Index */
  createdAt: Date
  comment?: WordOrSentence
}

interface WordOrSentence {
  type: 'word' | 'sentence'
  id: number
}

interface BinaryRelation extends Relation {
  /** Index */
  word1Id: number
  /** Index */
  word2Id: number
}

interface TernaryRelation extends BinaryRelation {
  /** Index */
  word3Id: number
}
```

---

### 문제유형(`QuestionSchema`)

문제의 유형은 질문이 주어지는 방식과 응답을 결정한다.

#### 단어 설명 문제(`WordExplain`)

1개의 단어가 주어지고 그 뜻을 묻는다.

문구는 `다음 단어의 뜻을 적으세요.`

```ts
interface WordExplainQuestion extends Question {
  type: 'WordExplain'
  wordId: number
}

interface WordExplainRelation extends Relation {
  type: 'WordExplain'
  /** Index */
  wordId: number
  answer: WordOrSentence
}
```

#### 예문 만들기 문제(`WordsUsage`)

랜덤하게 최대 3개의 단어가 주어진다.

단어 수가 1개인 경우 문구는 `다음 단어를 사용하여 문장을 만드세요.`

단어 수가 2개 이상인 경우 문구는 `다음 단어들을 사용하여 문장을 만드세요. 너무 이상해서 만들기가 어려우면 빈 문장을 제출하세요.`

```ts
interface WordsUsageQuestion extends Question {
  type: 'WordsUsage'
  wordIds: number[]
}

interface WordsUsageRelation extends Relation {
  type: 'WordsUsage'
  wordIds: number[]
  /** 말도 안되는 단어 조합이 나와서 응답을 회피한 경우 null */
  answer: WordOrSentence | null
}
```

#### 이항 공통점 문제(`BinaryCommon`)

두 단어의 공통점을 단어 또는 문장으로 서술할 수 있다.
무응답(빈 문자열) 제출을 허용하며, 이 경우 `answer`는 `null`로 저장된다.

문구는 `다음 두 단어의 공통점을 적으세요.`

```ts
interface BinaryCommonQuestion extends Question {
  type: 'BinaryCommon'
  word1Id: number
  word2Id: number
}

interface BinaryCommonRelation extends BinaryRelation {
  type: 'BinaryCommon'
  /** `comment`와 별개임. 무응답인 경우 null */
  answer: WordOrSentence | null
}
```

#### 이항 차이점 문제(`BinaryDifference`)

두 단어의 차이점을 단어 또는 문장으로 서술할 수 있다.
무응답(빈 문자열) 제출을 허용하며, 이 경우 `answer`는 `null`로 저장된다.

문구는 `다음 두 단어의 차이점을 적으세요.`

```ts
interface BinaryDifferenceQuestion extends Question {
  type: 'BinaryDifference'
  word1Id: number
  word2Id: number
}

interface BinaryDifferenceRelation extends BinaryRelation {
  type: 'BinaryDifference'
  /** `comment`와 별개임. 무응답인 경우 null */
  answer: WordOrSentence | null
}
```

#### 이항 유사성 문제(`BinarySimilarity`)

이항 동질성 문제는 랜덤으로 선택된 서로 다른 두 단어가 얼마나 관련이 있는지를 답한다.

문구는 `다음 두 단어는 얼마나 비슷한가요?`

```ts
interface BinarySimilarityQuestion extends Question {
  type: 'BinarySimilarity'
  word1Id: number
  word2Id: number
}

interface BinarySimilarityRelation extends BinaryRelation {
  type: 'BinarySimilarity'
  similarity: Similarity
}

type Similarity = -1 | -0.5 | 0 | 0.5 | 1
```

`Similarity`의 각 값에 대응되는 표시는 순서대로 `매우 반대`, `약간 반대`, `서로 무관`, `약간 비슷`, `매우 비슷`이다.
Eraseable Syntax 제약으로 `enum`을 쓸 수 없어, 값과 표시의 대응은 상수 배열로 둔다.

#### 삼항 격리 문제(`TernaryIsolation`)

삼항 격리 문제는 랜덤으로 선택된 서로 다른 세 단어 중, 가장 이질적인 단어를 고른다.

응답 타입은 범주(객관식의 답)이다.

문구는 `다음 세 단어 중 가장 이질적인 단어를 고르세요.`

```ts
interface TernaryIsolationQuestion extends Question {
  type: 'TernaryIsolation'
  word1Id: number
  word2Id: number
  word3Id: number
}

interface TernaryIsolationRelation extends TernaryRelation {
  type: 'TernaryIsolation'
  /** word1인지 word2인지 word3인지 **/
  selection: 1 | 2 | 3
}
```

### 문제출제기(`QuestionSelector`)

문제 출제기는 탐색 페이지에 존재하는 알고리즘으로, 강화학습으로 좋은 질문을 하는 것에 특화돼 있다.
좋은 질문이란 응답의 유형에 따라 다르지만 "무의미한 응답"을 줄이는 것에 목적이 있다.

단어의 수는 수 천, 수 만 개에 달하는데, 그 모든 단어들이 다 관계가 있을 리가 없다.
데이터에 존재하지 않는 관계는 기본적으로 무관계로 가정한다.
그런데 굳이 사람에게 '무관계'를 재확인할 필요가 없다.

그 구현은 현재 구상중이지만, 반드시 모델이 설명 가능해야 할 필요는 없다.

26년 7월 29일 기준으로는 구현이 완성되기 전에는 무작위로 선택한다.

어떤 단어가 뽑히는지와 별개로, 뽑힌 단어들이 문제에 놓이는 **순서도 항상 무작위여야 한다**.
사람은 먼저 본 것에 끌리므로, 순서가 고정되면 그것이 응답에 섞여 들어간다.
이항과 삼항 문제 모두 해당된다.
