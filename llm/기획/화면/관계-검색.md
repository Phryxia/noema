# 관계 검색

- 상위문서: [페이지 사양](../화면-페이지.md)의 `관계 목록`
- [관계 목록](`/qna`)의 제목 아래에 검색 폼이 있다. 검색 중에는 기간 검색 폼, 시간순 표, 페이지 네비게이터를 통째로 숨긴다.

# 검색 상태와 URL

검색어는 라우트의 query string `q`에 담긴다.

- 검색을 수행하면 `/qna?q=<검색어>`로 이동한다. 취소하면 `q`를 지운다.
- `q`가 있는 채로 들어오면(새로고침, 뒤로가기, 링크) 그 검색어로 자동 검색하고 입력칸을 채운다.
- 표의 행으로 개별 관계에 들어갔다 삭제로 돌아올 때 `q`를 관계 페이지까지 들고 갔다가
  그대로 복귀시켜(`search: true`), 검색 상태가 유지된다.

# 검색 폼

입력칸 하나와 `찾기` 버튼으로 이루어진다.

- 입력이 1자 이상이면 `찾기`가 활성화된다. 공백도 글자로 센다.
- 입력이 1자 이상이고 포커스가 폼 안에 있으면 단어 추천기를 띄운다.
  - 이곳의 추천기에는 삭제(x) 버튼이 없다.
  - 추천 항목을 선택(클릭, Enter)하면 그 단어를 입력만 하고 추천기를 숨긴다. 검색은 하지 않는다.
    이후 문자열이 변경되면 추천기를 다시 띄운다.
  - 단어가 아닌 임의의 문자열도 입력할 수 있다. 단어/문장 모드 구분은 없다.
- 입력칸에서 Enter를 치면 검색을 수행한다. 검색 수행 시에도 추천기를 숨긴다.
- ESC를 누르면 입력을 비우고 검색을 취소한다.
- 입력이 빈 문자열이 되면 그 즉시 검색을 취소한다.
- 검색을 취소하면 히스토리 모드로 돌아간다. 히스토리는 숨겨져 있었을 뿐이므로 보던 페이지와 탐사 상태가 그대로 남아 있다.

# 판정

관계의 여섯 필드를 해석된 문자열로 비교한다.

- 필드: word(`WordExplain`의 `wordId`, `WordsUsage`의 `wordIds` 각 원소), word1, word2, word3, answer, comment
- `BinaryAssociation`의 `word2Id`는 answer가 아니라 word2로 판정한다(저장 필드 기준).
- `BinarySimilarity`의 유사도, `TernaryIsolation`의 `selection`은 판정 대상이 아니다.
- `NamedAssociation`의 `word3Id`(관계 이름)는 word3으로 판정한다.
- 삭제 등으로 값이 빈 문자열이면 항상 불일치다.

두 섹션으로 나눈다. 한 관계는 최대 한 섹션에만 나타난다.

1. `정확히 일치`: 어떤 필드의 값이 검색어와 정확히 같다.
2. `부분 일치`: 정확히 일치가 아니면서, 어떤 필드의 값이 검색어를 연속 부분문자열로 포함한다.
   (abc에서 bc는 부분일치지만, ac는 아니다)

# 정렬

관계마다 가장 우선순위 높은 매치 필드 하나로 정렬한다.

- 필드 순위: word → word1 → word2 → word3 → answer → comment.
  answer와 comment는 단어형이 문장형보다 앞선다.
  즉 word → word1 → word2 → word3 → answer(단어) → answer(문장) → comment(단어) → comment(문장).
- 정확히 일치: 필드 순위 → `createdAt` 내림차순 → `relationId` 내림차순.
- 부분 일치: 매치된 값의 길이 오름차순(정확에 가까울수록 앞) → 값의 사전순(코드유닛) → 필드 순위 → `createdAt` 내림차순 → `relationId` 내림차순.

# 표시

- 각 섹션은 서로 독립인 비동기 조회다. 한쪽이 로딩 중이어도 다른 쪽은 먼저 그려진다.
- 로딩 표시는 화면에 최대 1개만 보인다. 두 섹션이 모두 로딩 중이면 앞 섹션 것만 보인다.
- 비어 있는 섹션은 숨긴다. 두 섹션이 모두 비면 `일치하는 내용이 없습니다.`를 표시한다.
- 각 섹션은 히스토리와 같은 표(유형/문제/응답/참고/날짜)와 같은 페이지 네비게이터를 갖는다.
  전체 결과를 메모리에 두고 10건씩 잘라 보여주되, 탐사형 노출 규칙(뒤쪽 `...`, 순차 `>`)은 동일하다.
  부분문자열 판정은 인덱스를 탈 수 없어 전수 조회가 불가피하므로, 커서 페이징 대신 이 방식을 쓴다.
- 새로 검색하면 두 섹션의 페이징이 1페이지로 초기화된다.
- 표의 문제/응답/참고 칸 텍스트 중 검색어와 같은 부분문자열을 `mark`로 강조한다. 두 섹션 모두 동일하다.
  - 정확히 일치는 값 전체가, 부분 일치는 해당 부분만 강조된다. 한 행에서 일치하는 모든 칸이 강조된다.
  - `(삭제됨)`, `회피`, 유사도 라벨, 유형 라벨은 판정 대상이 아니므로 강조하지 않는다.
  - 문장은 미리보기로 자른 뒤의 텍스트를 기준으로 강조한다. 잘린 부분의 일치는 보이지 않는다.
  - 히스토리 표에는 강조가 없다.
  - [개별 단어](../화면-페이지.md) 페이지의 `연관 관계` 구역도 같은 강조를 쓴다.

# 캐싱

- 검색 결과는 검색어별로 5분간 캐싱한다([최근 목록](./최근-목록.md)의 캐싱과 같은 `PAGE_CACHE_MS`).
  취소 후 5분 내 같은 검색어로 다시 검색하면 즉시 표시된다.
- 단어·관계·문장의 생성/수정/삭제 시 검색 캐시를 무효화한다
  (`invalidateWordAndQnaQueries`, `invalidateRelationQueries`).

# 구현

- 판정·정렬은 순수 함수로 분리되어 vitest 테스트가 있다.
  - `qna/search/collectSearchTargets.ts`: 관계 → 판정 대상 필드 목록
  - `qna/search/compareSearchTargets.ts`: 필드 순위와 부분 일치 비교
  - `qna/search/computeSearchMatches.ts`: 섹션별 필터·정렬
- 전수 조회와 하이드레이션은 `qna/search/qnaSearch.service.ts`, 쿼리는 `useQnaSearch`.
- ESC는 `WordField`의 `onEscape`로 처리되며 IME 조합 중에는 무시된다.
- 강조는 `shared/HighlightedText.tsx`가 맡고, `QnaTable`의 `keyword` prop으로 셀까지 전달된다.
- 개별 단어 페이지의 `연관 관계` 구역은 `word/WordRelations`가 `searchExactQnaEntries`와 `QnaSearchSection`을 재사용한다.
