# 2026-08-30 이관된 제목 문장을 최근 문장 큐에 반영

## 문제

[문서 제목 도입](./2026-08-30-문서-제목-도입.md)의 v12 마이그레이션은 제목 문장을 `sentences`에만 넣고 `recentSentences` 순환 큐는 건드리지 않았다(간결성). 사용자가 홈의 `최근에 추가된 문장`에 이관된 제목 문장이 없는 것을 지적했다. 새로 만든 문서의 제목은 `addSentences`를 타므로 큐에 들어가지만, 이관분 19건은 `/recent/sentences`에만 보였다.

## 해결

- v13 마이그레이션 `mergeTitlesIntoRecentSentences`: `relations` 커서로 `DocumentTitle`의 `sentenceId`를 모아 문장을 읽고, 큐의 기존 칸과 합쳐 `createdAt` 오름차순(같으면 `sentenceId` 순)으로 최신 4개를 칸 0..3에 다시 쓰고 `next = 개수 % 4`로 둔다. 이관 순서대로 밀어 넣지 않은 이유: 큐는 "가장 최근에 만들어진 문장 4개"이고 제목 문장의 `createdAt`은 문서 시각이라 기존 칸과 시각으로 섞여야 맞다. 같은 `sentenceId`는 한 번만 센다(v12 이후 새로 만든 문서의 제목은 이미 큐에 있다).
- 순수 함수 `mergeRecentSentences(existing, added, toSortKey)`를 `db/documentTitle/`에 두고 마이그레이션과 백업 승격이 공유한다. 정렬 키를 문자열로 받는 이유: IDB에서는 `Date`, 승격 시점 백업에서는 `{ "$date": ISO }`라 ISO 문자열로 맞추면 둘 다 사전순 비교가 된다.
- v12 마이그레이션(`migrateDocumentTitles`)도 제목 추가 뒤, 재백필 앞에 같은 병합을 부른다. 그래서 `onupgradeneeded`는 `< 12`면 v12 경로(병합 포함), 아니면 `< 13`이면 병합만 도는 `else if`다. 둘을 모두 걸면 v12 경로의 비동기 제목 추가가 끝나기 전에 v13 병합이 돌아 이관분을 놓친다.
- `RECENT_SENTENCES_SIZE`를 `sentence/consts.ts`에서 `db/consts.ts`로 옮겼다. `db/`가 `sentence/`를 역참조하지 않기 위해서다.
- 백업 승격 `< 13`: `relations`의 `DocumentTitle`로 제목 문장 entry를 찾아 `recentSentences` entries를 `{ key: 0..3 }` + `{ key: 'next' }`로 다시 만든다. 제목 문장이 하나도 없으면 손대지 않는다.
- 12는 사용자 브라우저에서 이미 완전히 실행된 번호라 새 번호 13을 쓴다. 승격 테스트의 v12 케이스는 `DB_VERSION`을 13으로 올리기 전에는 early return으로 실패한다(예상된 실패 1건).

## 남은 것

- 이관된 제목 문장이 큐에 들어가면 그만큼 기존 최근 문장이 밀린다. 문서가 최근 것이면 홈의 최근 문장 4칸이 전부 제목이 될 수 있다.
