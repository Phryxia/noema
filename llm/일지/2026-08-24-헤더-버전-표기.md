# 2026-08-24 헤더 버전 표기

## 문제

배포는 `main` 단일 브랜치의 push마다 자동으로 일어나는데, 화면에는 어느 시점의 코드인지 알 수 있는 표시가 없었다. PWA가 구버전 셸을 서빙하는 상황까지 겹치면 "지금 보고 있는 것이 방금 배포한 것인가"를 판별할 방법이 없었다.

버전 문자열을 손으로 올리는 방식은 올리는 것을 잊는 순간 거짓 정보가 되므로 배제했다. 커밋 수와 해시는 이미 git이 갖고 있으니 빌드 시점에 읽어 넣는다.

## 해결

`packages/client/getBuildRevision.ts`가 `git rev-list --count HEAD`와 `git rev-parse --short=6 HEAD`를 `execSync`로 읽고, `vite.config.ts`가 그 값을 `define`으로 주입한다. 헤더는 `r<커밋수>: <해시6>`(예: `r152: 2b26ae`)을 `h1` 안 `sub`으로 그린다.

- **`define` 대상을 `import.meta.env.VITE_*`로 잡았다.** 라우터 `basepath`가 이미 `import.meta.env.BASE_URL`을 쓰고 있어 앱 코드의 관용과 맞고, `__APP_VERSION__` 같은 전역 식별자와 달리 `declare global` 없이 `vite-env.d.ts`의 `ImportMetaEnv` 확장만으로 타입이 붙는다.
- **앱 코드에서 `import.meta.env`를 구조분해하면 안 된다.** `define`은 텍스트 치환이라 `import.meta.env.VITE_COMMIT_HASH` 전체 표현식에만 걸린다. `const { VITE_COMMIT_HASH } = import.meta.env`로 쓰면 vite가 만든 env 객체를 읽게 되고, 그 객체에는 `.env` 파일에서 온 키만 있어 `undefined`가 된다. 실제로 처음 그렇게 썼다가 되돌렸다.
- **`actions/checkout@v4`는 기본이 shallow(`fetch-depth: 1`)라 커밋 수가 항상 1이 된다.** `.github/workflows/static.yml`에 `fetch-depth: 0`을 넣었다. 이 한 줄이 없으면 기능 전체가 무의미하다.
- **git을 못 읽으면 두 값 모두 빈 문자열을 반환하고 `sub`을 아예 그리지 않는다.** 저장소 바깥에 파일을 복사해 `vite-node`로 호출해 `{"count":"","hash":""}`를 확인했다. 빌드를 깨뜨리는 대신 표시가 사라지는 쪽을 골랐다.
- **`sub`은 `Link` 바깥에 둔다.** 안에 넣으면 밑줄과 포인터가 붙어 누를 수 있는 것처럼 보이는데, 이 표시에는 동작이 없다.
- **pico가 `sub`을 리셋한다.** `.pico sub`가 `font-size: .75em; vertical-align: baseline; bottom: -.25em`이라, 그대로 두면 36px h1 아래에서 27px 굵은 글씨가 되어 두 번째 제목처럼 보였다(스크린샷으로 확인). `__root.module.css`에서 `:global(.pico) .revision`(0-2-0)로 승격해 `0.875rem`, `font-weight: normal`, `--pico-muted-color`를 줬다. 실측 15.75px이고 `bottom: -.25em`은 pico 것을 그대로 쓴다.

dev 서버는 config 로드 시점에 값이 고정되므로 기동 후 커밋해도 갱신되지 않는다. 재기동으로 해소되며 별도 처리는 하지 않았다.

## 검증

빌드 산출물 `docs/assets/index-*.js`에 `r152: 2b26ae` 문자열이 박힌 것, dev 서버 1000px/375px 헤더 스크린샷(375px에서 `scrollWidth - innerWidth`가 0), `sub.closest('a')`가 `null`인 것을 확인했다.
