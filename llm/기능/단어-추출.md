# 단어 추출

문장 본문을 단어 카드로 잘라 사람이 다듬은 뒤 한 번에 제출한다. 단어들이 삽입되고 (문장, 단어) 쌍마다 `SentenceToWord` 관계가 생긴다. 개별 문장 페이지의 `연관 단어` 구역에서 시작한다. [문장-추출](./문장-추출.md)과 카드 편집기를 공유하며 다른 점만 적는다.

## 코드

- 디렉토리: `packages/client/src/extraction/`(편집기·추출), `packages/client/src/s2w/`(관계)
- 분할: `extraction/extractWords/extractWords.ts`(+test), `getCharacterClass.ts`, `consts.ts`(스크립트 목록, 폭 블록, 숫자 리터럴 패턴, `々`·장음)
- 카드: `extraction/WordCard/WordCard.tsx`, `WordExtractor/`, 공용 `cardList.ts`·`useCards.ts`·`computePendingBackspace.ts`·`arrowNavigation.ts`
- 제출: `extraction/submitWordExtraction.ts`, `word/wordTx.ts`의 `addWord`
- 관계: `s2w/s2w.service.ts`, `hydrateS2wEntries.ts`, `types.ts`, `consts.ts`, `utils.ts`(`invalidateS2wQueries`)
- 화면: `s2w/SentenceWords/`(진입·표·편집기 전환, 관계 삭제 `useSentenceWordDeletion.ts`), `s2w/WordSentences/`(개별 단어의 `단어를 추출한 문장`), `s2w/S2wTable.tsx`(`PairTable` 기반, `hiddenColumn`), `s2w/S2wRelationPage/`(`PairRelationPage` 기반), 결과 모달 `shared/ResultDialog`

## 사양

- 진입: `연관 단어` 구역은 이 문장을 가리키는 `SentenceToWord`가 0건일 때만 `단어 추출` 버튼. 누르면 편집기로. 구역은 `isExtracting`을 관계 건수보다 먼저 본다. 제출 성공으로 관계가 생기는 순간 편집기와 결과 모달이 언마운트되면 안 된다. 모달을 닫아야 표로 바뀐다. 이탈 질의 없음.
- 전처리: 개행(`\r\n?`, `\n`) 삭제, 연속 탭을 공백 1개로. 공백은 그대로. 그 밖의 문자는 하나도 잃지 않는다.
- 숫자: ASCII 숫자 자리에서 JS 숫자 리터럴(`0x`/`0b`/`0o`, `[0-9]+(.[0-9]+)?([eE][+-]?[0-9]+)?`)을 먼저 시도해 맞으면 독립 조각. 선행 부호 제외(`+3.1e-4` → `+`/`3.1e-4`). 소수점 뒤 숫자가 없으면 점을 넣지 않는다. BigInt `n`·구분자 `_` 미지원. 전각 숫자는 클래스 규칙.
- 문자 클래스 = 스크립트 + 폭. 이웃 문자의 클래스가 다르면 자른다. 스크립트는 `\p{Script=...}`를 목록 순서로 시도, 어디에도 안 걸리면 `letter`/`number`/`symbol`(기호는 생김새가 달라도 한 덩어리). 폭은 `Fullwidth/Halfwidth Forms` 블록 소속으로 정하고 아니면 중립. 공백은 폭 없는 `space`, 연속 공백은 한 조각.
- 예외 셋: 한자 → 히라가나는 자르지 않는다(현재 클래스가 히라가나로 갱신, 반대 방향은 자름). `々`는 앞 문자 클래스 상속(맨 앞이면 `symbol`). 장음 `ー`·`ｰ`는 언제나 카타카나(`らーめん` → `ら`/`ー`/`めん`). 예시와 경계는 `extractWords.test.ts`.
- 카드: 조작법 `small` 네 줄. `WordField`를 `isInline`으로 그려 flex로 옆으로 나열, `field-sizing: content` + `min-width`. 공백만 든 카드도 보인다. `제출`은 비지 않은 카드가 하나라도 있어야 활성(`trim` 없음).
- 분할: 캐럿 자리에서 Enter로 양분, 뒤 조각을 새 카드로, 뒤 조각 맨 앞 포커스. 조각을 버리지도 `trim`하지도 않아 맨 뒤 Enter는 빈 카드 추가. 선택 영역은 사라진다. keydown `preventDefault`, IME 중 무시.
- 병합·삭제는 문장 카드와 같다(`computePendingBackspace` 공유). 이동은 좌우만(`input`은 시각 행이 없다), 상하는 브라우저에 맡긴다.
- 제출: 빈 카드 제거, 값은 `trim` 없이 원문. 같은 값은 `Set`으로 1회만 삽입(UI 카드는 그대로). `[wordMeta, wordNodes, recentWords, relations]` 단일 트랜잭션, `createdAt` 공유. 값마다 `addWord` → `{ nodeId, isCreated }` → `relations.add`. 값 하나의 예외는 `try`/`catch`로 결과에만 `실패`. 성공 시 `단어 n개를 연결했습니다`(n은 관계 수), 관계·단어·통계 무효화.
- 결과 모달(`ResultDialog`): `단어`/`결과` 두 열. 성공 초록(단어 신규 + 관계), 중복 주황(단어 기존, **관계는 생김**), 실패 빨강(관계 없음). `닫기`로 표 전환.
- 삭제: 개별 문장 페이지의 `연관 단어` 표만 맨 오른쪽 열에 `x` 버튼을 갖는다(`S2wTable`의 `onDelete`, `PairTable`의 `renderAction`). 누르면 관계를 지우고 `관계를 삭제했습니다`. 이어서 그 단어가 어느 관계에서도 참조되지 않으면(`hasWordReferences` 거짓) `단어도 삭제할까요? (확인 시 삭제)`를 묻고 확인 시 `deleteWord`로 지운다(`단어를 삭제했습니다`). 개별 단어 페이지의 `단어를 추출한 문장`과 개별 관계 페이지에는 이 버튼이 없다. 마지막 관계를 지우면 `단어 추출` 버튼으로 돌아간다.
- 관계: `{ type: 'SentenceToWord', sentenceId, wordId, createdAt }`, `comment` 없음, 수정 없음. 새 인덱스·버전 없이 `wordId`·`sentenceId` 인덱스 공유. 결과는 `relationId` 오름차순 = 문장 내 단어 순서. 문장 수정은 관계 영향 질의 건수에 들어가고, 단어 개명·대체·삭제 게이트는 `wordId` 인덱스 덕에 자동으로 따라온다(문서-문장 관계와 다른 점).
- 목록: 유형 라벨 `단어 추출`, 대표 표현은 `extraction` 토큰 `{ child: 단어, parent: 문장 }` 7:3. 관계 검색 모집단에서는 제외.

## 결정 근거와 제약

- 소수점 뒤 숫자를 요구하는 것이 사용자 사양(`JS가 인식하는 형식`)에서 의도적으로 벗어난 유일한 지점이다. `3.`을 삼키면 문장 끝 마침표가 숫자에 붙는다.
- `Fullwidth/Halfwidth Forms` 블록을 폭 기준으로 삼은 이유: 정확히 "폭 변형 짝이 있는 문자"의 집합이라 `０0` 분리와 반각 가나 분리가 한 규칙에서 나온다.
- 공용화를 먼저 하고 기능을 얹었다. `sentenceCardList` → `cardList`, `useSentenceCards` → 제네릭 `useCards`(도착 캐럿 주입). 기존 vitest가 회귀 감시자였다.
- `중복`의 뜻이 배치 모드와 다른 이유: 진입 조건이 관계 0건이라 관계 중복은 생길 수 없고, 사용자가 알고 싶은 것은 단어의 신규 여부다(사용자 확답). 라벨·색은 `relation/batch/getOutcomeLabel.ts`를 그대로 쓴다.
- 한 값의 예외를 삼키는 이유와 `addWord` 추출 경위: [저장개발참고](../참고/저장개발참고.md#트랜잭션).
