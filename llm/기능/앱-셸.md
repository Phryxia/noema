# 앱 셸

공통 헤더와 레이아웃, 기동 순서, 토스트, PWA, 배포. 모든 페이지가 공유한다.

## 코드

- 레이아웃: `packages/client/src/routes/__root.tsx`(헤더, `nav`, `main`, `ToastStack`, 라우터 devtools)
- 기동: `packages/client/src/main.tsx`(`clearLegacyStorage` -> `registerSW` -> `createRouter({ basepath })` -> `QueryClient` + `MutationCache` 콜백 -> 렌더), `global.css`, pico conditional CSS
- 토스트: `packages/client/src/toast/`(`toast.ts`, `ToastStack/`, `consts.ts`, `types.ts`)
- 오류 문구: `utils/getErrorMessage.ts`
- 라우트 트리: `routeTree.gen.ts`(생성 파일, gitignore)
- PWA·빌드: `packages/client/vite.config.ts`, `packages/client/index.html`(SW `<base>` 주입 스크립트), `public/`(아이콘 6종), `vite-env.d.ts`
- 배포: 루트 `package.json`의 `build-gh-page`, `.github/workflows/`
- 서버: `packages/server/`(fastify 스텁. 클라이언트는 네트워크 요청이 0건이다)

## 사양

- 헤더: `h1` `NOEMA System`(대시보드 `/` 링크), 부제 `나만의 말뭉치를 만들자!`, `nav` 링크 `탐색`(`/explore`) / `알려주기`(`/relation/new`) / `관계`(`/relations`) / `도구`(`/tools`) / `설정`(`/settings`). `header`와 `main`에 `pico container`.
- 라우트 13개: `/`, `/explore`, `/relation/new`, `/relation/$relationId`, `/relations`, `/tools`, `/settings`, `/word/$word`, `/sentence/$sentenceId`, `/document/$documentId`, `/recent/{words,sentences,documents}`. 각 페이지의 사양은 `README.md`의 표.
- 토스트: 우측 하단, 5초 잔류, 최대 3개, 오래된 순 위에서 아래, 초과 시 가장 오래된 것 제거. mutation 실패는 전부 error 토스트, 성공은 `meta.successMessage`가 있는 것만. 규약은 [라우팅-쿼리참고](../참고/라우팅-쿼리참고.md#토스트).
- PWA: manifest(`NOEMA System`, standalone, `start_url`/`scope` `./`), SW 프리캐시(`js,css,html,ico,png,svg,webmanifest`), `navigateFallback: index.html`, `autoUpdate` + 즉시 등록. 오프라인에서 모든 깊이의 경로 새로고침이 동작한다. dev에서는 SW 비활성.
- 기동 시 `lab/embedding/` 접두 localStorage 키를 지운다(제거된 실험 기능의 잔재).
- 배포: `npm run build-gh-page`가 `--base=/noema/ --outDir docs`로 빌드하고 워크플로가 `docs/index.html`을 `404.html`로 복사해 GitHub Pages 하위 경로에서 딥링크 새로고침을 받는다. 라우터 `basepath`는 `import.meta.env.BASE_URL`.

## 결정 근거와 제약

- 토스트를 `CustomEvent`로 전달하는 이유: 발신 지점(`MutationCache`)이 React 트리 바깥이라 Context를 쓸 수 없다. 토스트 루트에 `pico` 클래스를 문자열로 병기해야 변수와 카드 스타일을 받는다.
- 토스트 이전에는 mutation 실패가 조용히 묻혀 "입력한 단어가 사라진 느낌"의 원인이었다.
- `base: './'`에서 `'/'`로 바꾼 경위: 자산은 상대 경로로 살았지만 라우터 `basepath`가 없어 `/noema/`에서 Not Found였다. 배포 경로는 빌드 시 한 곳(`--base`)에서 주입한다. 커스텀 도메인 루트로 옮기면 그 플래그만 바꾼다.
- SW fallback 문서의 상대 자산 경로가 깊이 2 이상에서 깨지는 문제를 `index.html` 인라인 `<base>` 주입으로 푼 이유와 남은 preload scanner 로그: [라우팅-쿼리참고](../참고/라우팅-쿼리참고.md#pwa와-배포). injectManifest 커스텀 SW는 유지비용 대비 이득이 없어 하지 않았다.
- 런타임 캐싱 전략이 없는 이유: 네트워크 요청이 없다.
- 아이콘은 `public/favicon.svg`(별자리 눈)에서 playwright 렌더링으로 만든 플레이스홀더다. 같은 파일명으로 덮어쓰면 교체된다.
- PWA 설치는 `navigator.storage.persist()` 승인 확률을 올린다. 영속성 정책은 [plan](../plan.md).
