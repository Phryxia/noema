# 2026-08-30 문서 제목 도입

## 문제

노에마를 Obsidian과 비슷한 메모 관리 방향으로 넓히려는데 문서에는 본문뿐이라 문서를 고르는 수단이 본문 문자열 일치밖에 없었다. 문서가 다른 화면(홈 최근 목록, `/recent/documents`, 연결된 문서 표, 태그 표, `/relations` 대표 표현)에 보일 때도 본문 앞 48~64자를 잘라 보여 같은 문서가 화면마다 다른 길이로 보였다.

요구는 다음과 같이 확정됐다.

- 제목은 문장이다. 문장 입력기 규칙을 따르되 탭·개행은 못 넣는다. 중복은 허용한다.
- 문서 타입은 바꾸지 않는다. 문서 -> 제목 문장 관계로 표현하고, 제목 수정은 그 문장을 직접 고치는 것이다.
- 기존 문서는 공백문자를 뺀 앞 10글자로 제목을 채운다(10 미만이면 있는 만큼).
- 문서가 다른 컴포넌트에 노출되면 제목을 노출한다.

사용자 결정: 제목 문장을 `/sentence/$id`에서 지우는 것을 막지 않는다(문서는 `(제목 없음)`, 다음 저장에서 자가 복구). `DocumentTitle` 관계는 `/relations`에 노출한다. 이관된 제목 문장의 `createdAt`은 문서의 `createdAt`이다.

## 해결

### 모델과 저장

- 새 관계 유형 `DocumentTitle { documentId, sentenceId, createdAt }`. 기존 `documentId`/`sentenceId` 인덱스를 공유해 새 인덱스는 없다. `NonWordRelationTypes`에 넣지 않으면 `loadRelationSnapshot`이 `QuestionSpecs[type]`에서 죽고 검색 모집단에 섞이므로 유형 추가의 첫 편집이 이것이다.
- 제목 문장의 `source`는 `Titled via NOEMA system document, did=<documentId>`. 접두 상수·기본 제목 계산·source 생성은 `db/documentTitle/`에 둔다. 마이그레이션(`db/`)과 백업 승격, 서비스가 같은 순수 함수를 쓰면서도 `db/`가 기능 모듈을 역참조하지 않기 위해서다(2026-08-24 역참조 제거 원칙).
- `createDocument(title, value, source)`는 `[documents, recentDocuments, sentences, recentSentences, relations]` 단일 트랜잭션에서 문서 add -> `addSentences` -> 관계 add. 커밋 후 문서·문장·관계 통계를 각 1건 기록한다.
- 순환 큐 `recentDocuments` 칸에서 `preview`를 없앴다. 제목 문장은 문장 페이지에서도 고쳐지므로 사본을 두면 두 경로를 동기화해야 한다. `getRecentDocuments`가 읽을 때 제목을 해석한다. `updateDocument`는 더 이상 순환 큐를 만지지 않는다.
- `resolveDocumentMap`(본문 전체 반환)을 `resolveDocumentTitleMap`으로 바꿨다. `''`는 문서 삭제됨(기존 `(삭제됨)` 규약), `null`은 문서는 있으나 제목 관계·문장이 없음(`(제목 없음)`). `documents.count`를 먼저 봐야 한다. 문서를 지워도 제목 문장·관계는 남으므로(항목을 지워도 관계는 남는다) 관계만 따라가면 삭제된 문서가 제목 링크로 살아 보인다.
- `saveDocumentTitle(documentId, title)`: 제목 관계·문장이 있으면 값이 다를 때만 `updateSentence`(기존 `source`를 반드시 넘긴다. 빈 문자열이면 키가 지워진다). 없으면 문장 없는 관계를 지우고 새 문장·관계를 만든다. 지운 관계 수만큼 `recordDeletion(relationCount)`를 빠뜨리면 총 보유와 누적이 어긋난다(2026-07-23의 불일치 재발).

### 마이그레이션 v12와 백업 승격

- `migrateDocumentTitles`: `recentDocuments` 칸의 `preview` 제거 -> `documents` 커서로 문서마다 기본 제목 문장(`createdAt`은 문서 것)과 관계 add -> `clearAndBackfillCountLogs`. 문장·관계가 과거 시각으로 늘었으므로 통계 로그를 다시 채워야 누적과 총 보유가 맞는다.
- **기존 `oldVersion < 9` 재백필 블록을 지웠다.** `< 9`는 반드시 `< 12`이므로 v12 끝의 재백필이 포함한다. 둘을 남기면 같은 `versionchange` 트랜잭션에서 두 백필이 동시에 돌고, 제목 문장이 들어가기 전에 `sentences` 커서를 돈 첫 백필의 `put`이 두 번째 백필의 `put` 뒤에 실행될 수 있어 낡은 값이 최종값이 된다. 요청 큐 순서가 문서 수·단어 수에 좌우되는 비결정성이다.
- 재백필을 커서가 끝난 뒤에 부르는 근거: `addDefaultTitles`가 Promise 생성자 안에서 `openCursor`를 동기 발행하고, 커서 `null` 콜백에서 resolve한 continuation이 그 콜백의 마이크로태스크에서 실행되어 트랜잭션이 active다. 문서 하나에서 `sentences.add`를 `cursor.continue()`보다 먼저 걸어야 마지막 문서의 관계 add가 재백필의 `clear`/`openCursor`보다 앞선다.
- `upgradeBackup`에서 `createdAt`은 문서 entry의 값을 그대로 복사한다. `parseBackup`이 `JSON.parse` 직후 `upgradeBackup`을 부르고 `decodeValue`는 `importBackup`에서 돌므로 승격 시점 값은 `{ "$date": ISO }` 객체다. 진짜 `Date`를 넣으면 `decodeValue`의 `checkIsPlainObject`가 `Date`를 plain object로 보고 `{}`로 망가뜨린다.
- 승격 테스트는 `DB_VERSION`을 12로 올리기 전에는 v11 케이스가 early return으로 실패한다. 편집 순서(마이그레이션 코드 -> 승격 -> 서비스·UI -> `DB_VERSION` 마지막)를 지키면서 그 실패 하나만 예상하고 넘어갔다.

### 입력기와 노출

- `TitleField`: `word/WordField`(input + 공백 에코)를 감싼다. `writer/`에 두면 `writer -> word -> writer` 순환이라 `document/DocumentWriter/` 아래에 뒀다. `onChange`에서 `[\t\r\n]`을 제거하고, Enter는 `preventDefault`(폼 암묵 제출 차단), `Ctrl+Enter`만 저장. group 밖 pico `input`의 `margin-bottom`이 `.inputWrapper`를 키워 에코가 밀리는 것을 `.field input { margin-bottom: 0 }`으로 막았다. 실측: input과 에코 top 549.22, 높이 56.25로 일치.
- `useWriterForm`에 `checkIsComplete` 옵션(기본 `!!draft.value`). 문서는 제목과 본문이 모두 있어야 저장할 수 있다. dirty 판정은 `initialDraft`의 키를 순회하므로 `title`이 자동 포함된다.
- 제목만 바뀐 저장은 문장만 `updateSentence`하고 문서 레코드·`modifiedAt`은 건드리지 않는다(태그만 바뀐 저장이 본문 update를 건너뛰는 것과 같은 원칙).
- 문서 페이지의 제목 쿼리는 `gcTime: 0`. 문장 페이지에서 제목 문장을 고친 뒤 돌아오면 캐시된 옛 제목으로 `initialDraft`가 잡혀 dirty가 되고 옛 값을 되쓰는 사고를 막는다. 세 쿼리가 모두 끝난 뒤 `DocumentWriter`를 마운트한다.
- 노출: `DocumentTitleLabel`(`null` -> 회색 `(제목 없음)`, 문자열 -> 48자 절단)을 `D2sCells.DocumentCell`(연결된 문서·태그 표·개별 관계 페이지), 홈 최근 문서, `/recent/documents`(`RecentDocumentSource`의 `hydrate`), 대표 표현(`ResolvedRefToken.isUntitled`)에서 쓴다.
- `/relations`에 `문서 제목` 라벨. 대표 표현은 문장 추출과 같은 `extraction` 토큰이라 `[제목 문장] from [문서 제목]`로 같은 글자가 두 번 보인다. 라벨 열이 유형을 구분하므로 받아들였다. 개별 관계 페이지는 `D2sRelationPage`를 재사용하고 둘째 행 라벨만 `제목`이다.

### 검증

`corpus.json`(v9)을 이전 커밋 빌드로 가져와 v11 DB를 만든 뒤 새 빌드로 열었다. 문장 328 -> 347, 관계 2386 -> 2405, 문서 19건 전부 관계 1건, `createdAt` 일치, `dayAcc` 마지막 값이 실제 수와 일치. 홈·`/recent/documents`·`/relations`·개별 관계·문서 페이지 제목 수정(문장 `modifiedAt` 갱신, 문서 `modifiedAt` 불변)·신규 작성(탭 제거, Enter 무동작, `Ctrl+Enter` 저장)·제목 문장 삭제 후 `(제목 없음)`과 자가 복구·v9 백업 가져오기 승격까지 확인했다.

함정: preview 서버를 구빌드에서 새 빌드로 바꿔도 PWA 서비스워커가 구빌드를 서빙해 마이그레이션이 돌지 않았다. `launchPersistentContext`에 `serviceWorkers: 'block'`을 주고 등록 해제·캐시 삭제 후 진행했다. `pkill -f "vite preview"`는 자기 셸까지 죽인다(`[v]ite` 패턴으로 피한다).

## 남은 것

- 제목 문장 페이지에 "문서 X의 제목"을 보이는 구역이 없다. `SentenceDocuments`는 `DocumentToSentence`만 조회한다.
- `SourceField`의 Enter는 암묵 제출(저장)이고 제목 칸의 Enter는 무동작이라 두 한 줄 칸의 동작이 다르다.
- 문서 제목으로 검색하는 UI는 없다. 관계 검색 모집단은 단어 관계뿐이다.
- 파일 드롭 시 파일명을 제목 기본값으로 넣지 않는다.
- 마이그레이션 직후 `/recent/sentences`에 제목 문장이 문서 시각으로 섞여 보인다.
