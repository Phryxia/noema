# 개요

페이지의 라우트와 구성을 서술한다.

- 상위문서: [화면](./화면.md)
- 페이지가 배치하는 컴포넌트의 동작은 [재사용 컴포넌트](./화면-컴포넌트.md)에 있다.
- 페이지가 읽고 쓰는 데이터의 스키마는 [타입별 Store](../설계/저장-스토어.md)에 있다.

# 공통 규칙

이 구획의 2-depth 헤더의 내용은 하단의 페이지별 기획에서 각 호를 언급할 때 적용된다.

## 미저장 수정 이탈 질의

- 값은 수정돼 있는데 수정 버튼을 누르지 않은 상태로 이탈을 시도할 경우
  - 표준 프롬프트 화면으로 `수정된 내용을 저장할까요?` 물어보며 확인
  - confirm인 경우 수정 반영. 해당 페이지에 _관계 영향 질의_가 있으면 그 질의를 먼저 통과해야 한다
  - cancel인 경우 수정 없이 그대로 이탈

## 관계 영향 질의

- 수정 대상을 참조하는 관계가 1건 이상이면, 수정 반영 직전에
  표준 confirm으로 `연결된 n건의 관계도 수정됩니다. 계속하시겠습니까?` 물어보며 확인
  - `n`은 참조하는 관계의 중복 없는 개수 (한 관계가 문제와 답으로 이중 참조해도 1건)
  - cancel인 경우 아무것도 바꾸지 않는다
- 참조하는 관계가 없으면 묻지 않는다
- 개별 관계 페이지의 수정에는 적용되지 않는다. 그쪽은 그 관계의 참조만 바꾸기 때문이다

## 관계 목록

- 라우트: `/relations`
- 공통 헤더의 `관계` 링크로 들어간다.
- 단어 관계와 추출 관계(`DocumentToSentence`, `SentenceToWord`)를 가리지 않고 `relations`의 모든 관계를 한 표에 `createdAt` 내림차순으로 보여준다.
  관계 없는 문제 잔재는 나타나지 않는다.
- 열은 ID / 유형 / 대표 표현 / 생성 시각
  - ID: `relationId`. 링크이며 누르면 _개별 관계_ 페이지로 간다. 행의 다른 곳을 눌러도 이동하지 않는다
  - 유형: 문제 유형 라벨(`단어 설명`, `관계 짓기` 등). `DocumentToSentence`는 `문장 추출`, `SentenceToWord`는 `단어 추출`
  - 대표 표현: 아래 표. 단어/문장/문서 링크는 각각 개별 단어/문장/문서 페이지로 간다
  - 생성 시각: `createdAt`을 `YY-MM-DD HH:mm`(24시간제)으로
- 기간 검색 폼, 페이지 네비게이터, 캐싱 규약은 _최근 목록_과 같다.
- 제목 아래에 문자열 검색 폼이 있다. 사양은 [관계 검색](./화면/관계-검색.md)에 있다.

### 대표 표현

관계 하나를 한 줄의 인라인 표기로 나타낸다. 저장하지 않고 화면에서 유형별로 만든다.
`[w1]`은 `word1Id` 단어 링크, `[답]`은 `answer`가 단어면 단어 링크, 문장이면 문장 링크, `null`이면 회색 `(답변 회피)`다.

| 유형 | 표기 |
| --- | --- |
| 단어 설명 | `[w1]: [답]` |
| 예문 만들기 | 답 문장 자체를 링크로 두되, 문장 안의 대상 단어를 기울임·굵은 단어 링크로 바꾼다(아래 설명) |
| 속성 | `[w1] - [w2]` |
| 이항 공통점 | `[w1] ∩ [w2] = [답]` |
| 이항 차이점 | `[w1] ↔ [w2] = [답]` |
| 이항 유사성 | `\|[w1] - [w2]\| = 정도 라벨` |
| 연상 | `[w1] ~ [w2]` |
| 삼항 격리 | `[비선택], [비선택] ↔ [선택]` |
| 삼항 합성 | `[w3] = [w1] + [w2]` |
| 관계 짓기 | `[w1] ──[w3]─→ [w2]` (word3이 관계 이름. 최초 요청 원문의 `-[w2]→ [w3]`은 저장 의미와 어긋나 채택하지 않았다) |
| 문장 추출 | `[문장]` 영역 70% + `from [문서]` 영역 30% (아래 설명) |
| 단어 추출 | `[단어]` 영역 70% + `from [문장]` 영역 30%. 문장 추출과 같은 토큰을 쓰며 두 참조만 바뀐다 |

- 참고사항(`comment`)은 대표 표현에 넣지 않는다.
- 문장 링크의 라벨은 문장 전체, 문서 링크의 라벨은 앞 48자 미리보기다. 둘은 같은 모양이다.
- 폭이 모자라면 문장/문서 링크가 줄어들며 줄임표로 잘린다. 최소 폭은 없다. 단어 링크와 기호는 줄지 않으며, 단어 링크만으로 칸을 넘치면 줄임표 없이 잘린다.
- 삭제된 대상은 링크 없이 회색 `(삭제됨)`으로 표시한다.
- 예문 만들기: 대상 단어를 따로 나열하지 않는다. 답 문장을 왼쪽부터 훑어 대상 단어와 같은 부분 문자열을 모두 기울임·굵은 단어 링크로 바꾸고,
  나머지 조각은 전부 같은 문장으로 가는 링크다. 같은 위치에서 겹치면 긴 단어, 앞선 위치가 우선이며 같은 단어가 여러 번 나오면 모두 링크한다.
  예) 단어 {매타작, 각오, 개수}, 문장 "틀린 개수만큼 매타작이니까 각오해라." → `[틀린 ][개수][만큼 ][매타작][이니까 ][각오][해라.]`
  전체가 한 덩어리로 줄어들며 줄임표로 잘린다.
  답이 문장이 아니면 `(답변 회피)`(회색) 또는 `[단어 답]`, 문장이 삭제됐으면 `(삭제됨)`(회색) 뒤에 `, 원 단어: [w1], [w2]`를 잇는다.
- 문장 추출: 대표 표현 칸을 7:3으로 나눠 앞 70%에 문장 링크, 뒤 30%에 `from ` + 문서 링크를 둔다.
  문장이 짧아도 70% 영역은 그대로라 `from`의 위치가 행마다 같다. 각 영역 안에서 링크가 줄어들며 줄임표로 잘린다.

## 개별 관계

- 라우트: `/relation/[:relationId]`
- _관계 목록_의 ID 링크로 들어간다.
- `DocumentToSentence`면 수정 없이 메타 정보, 문서·문장 링크, 삭제 버튼만 그린다(`D2sRelationPage`).
  이하는 단어 관계의 경우다.
- [알려주기](./화면/알려주기.md)와 같은 구성을 그린다. 지시문, 대상 단어 칸, 답안란, 참고사항의 동작이 모두 같다.
- 유형 라디오는 그대로 보이되 비활성이다. 유형이 바뀌면 다른 관계가 되기 때문이다.
- `MetaFields`로 `relationId`, `questionId`, `createdAt`, `modifiedAt` 표시
- 수정 버튼
  - 알려주기의 제출 버튼과 같은 조건에서 활성화되며 라벨만 `수정`이다
  - 누를 시 수정 반영. 입력은 비우지 않고 그대로 둔다
- 삭제 버튼
  - 누를 시 삭제 반영 기다린 후 관계 목록으로 이동
  - 관계를 낳은 문제도 함께 지운다. 대상 단어와 답안/참고사항의 단어·문장은 지우지 않는다
- 없는 `relationId`면 `존재하지 않는 관계: <relationId>`를 표시한다.
- 저장 규약은 [탐색 Store](../설계/저장-탐색.md)의 수정/삭제 절차에 있다.

## 설정

- 라우트: `/settings`
- 공통 헤더의 `설정` 링크로 들어간다.
- 데이터 백업 구역
  - `내보내기`: 전체 DB를 JSON 파일 하나로 내려받는다. 파일명은 `noema-backup-<연월일시분>.json`
  - `가져오기`: 파일을 고르면 표준 프롬프트로 확인을 받고, 기존 내용을 무시한 채 파일의 내용으로 덮어쓴다
  - 두 버튼 아래에 성공 문구 또는 실패 사유를 표시한다
  - 작업 중에는 두 버튼 모두 비활성화한다
- 파일 형식과 덮어쓰기 규약은 [저장 공통 규약](./저장-공통.md)에 있다.

## 개별 단어

- 라우트: `/word/[:word]`
- `WordEditor`에 해당 단어 입력돼 있음
- `MetaFields`로 `nodeId`, `parentNodeId`, `createdAt`, `modifiedAt` 표시
- 수정 버튼
  - 폼의 수정 사항이 있을 때만 활성화
  - 누를 시 _관계 영향 질의_ 후 수정 반영, 결과 단어의 페이지로 이동 (수정 시 `nodeId`가 바뀐다)
  - 수정은 전역 개명이다. 이 단어를 참조하는 모든 관계가 새 단어를 가리키게 된다
  - 수정 결과가 이미 있는 단어면 표준 confirm으로 병합 여부 확인. 거부 시 아무것도 바꾸지 않음
- 삭제 버튼
  - 참조하는 관계가 없으면 삭제 후 메인 페이지로 이동
  - 참조하는 관계가 있으면 `WordReplaceDialog`로 삭제 취소 또는 대체 단어 입력을 받음
  - 최근에 추가된 단어에 해당 단어 있으면 삭제
- _미저장 수정 이탈 질의_ 적용
- `WordEditor` 아래에 `연관 관계` 구역(`WordRelations`)
  - [관계 검색](./화면/관계-검색.md)에서 이 단어로 검색했을 때의 `정확히 일치` 결과와 판정·정렬·페이지 네비게이터·하이라이트가 같다.
    표만 유형/문제/응답/참고/날짜의 `QnaTable`이다(관계 목록의 대표 표현 표가 아니다).
  - 비어 있으면 제목 아래 `연관된 관계가 없습니다.`를 표시한다.
  - 단어별로 10분간 캐싱한다(`WORD_RELATIONS_CACHE_MS`, 키 `[wordRelations, 단어]`).
    단어·관계의 생성/수정/삭제 시 무효화한다(`invalidateWordAndQnaQueries`, `invalidateRelationQueries`).

## 개별 문장

- 라우트: `/sentence/[:sentenceId]`
- 문장 내용 표시
- `MetaFields`로 `sentenceId`, `createdAt`, `modifiedAt` 표시
- 수정 버튼
  - 폼의 수정 사항이 있을 때만 활성화
  - 누를 시 _관계 영향 질의_ 후 수정 반영
- 삭제 버튼
  - 누를 시 삭제 반영 기다린 후 메인 페이지로 이동
- _미저장 수정 이탈 질의_ 적용
- `연결된 문서` 구역(`SentenceDocuments`). 비어 있으면 숨긴다.
- `연관 단어` 구역(`SentenceWords`)
  - 이 문장을 가리키는 `SentenceToWord` 관계 표. 열은 단어 / 날짜이며 행을 누르면 개별 관계 페이지로 간다.
  - 0건이면 표 대신 `단어 추출` 버튼을 보인다. 사양은 [단어 추출](./화면/단어-추출.md)에 있다.

## 개별 문서

- 라우트: `/document/[:documentId]`
- 문서 내용 표시
- `MetaFields`로 `documentId`, `createdAt`, `modifiedAt` 표시
- 수정 버튼
  - 누를 시 수정 반영
  - 관계가 문서를 참조하는 경로는 없으므로 _관계 영향 질의_는 적용되지 않는다
- 삭제 버튼
  - 누를 시 삭제 반영 기다린 후 메인 페이지로 이동
- _미저장 수정 이탈 질의_ 적용
