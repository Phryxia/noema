순수 탐색 사양 정의(문제·응답·관계의 개념과 유형)는 [탐색 문서](../탐색.md)를 확인한다.
저장 스키마와 제출 절차는 [탐색 Store](../../설계/저장-탐색.md)에 있다.

알려주기 페이지의 라우팅은 `/relation/new` 이다. 공통 헤더의 `알려주기` 링크로 들어간다.
이미 만든 관계를 고치는 [개별 관계](../화면-페이지.md) 페이지가 이 페이지의 구성을 그대로 쓴다.

# 개요

탐색이 시스템 출제에 수동적으로 답하는 것이라면, 알려주기는 사용자가 아는 관계를 능동적으로 넣는 것이다.
사용자가 문제 유형, 대상 단어, 답을 모두 직접 지정해 제출하며, 탐색과 동일하게 문제(`Question`)와 관계(`Relation`)로 모두 저장된다.

# 구성요소

## 문제유형 선택

최상단에 **라디오**로 만들 문제의 유형을 하나 고른다. 탐색의 체크박스와 달리 단일 선택이다.
선택은 localStorage(`teach/type`)에 유지되어 재방문 시 복원된다.
유형을 바꾸면 대상 단어 입력칸 수가 조정되고(공통 앞부분 유지) 답안은 초기화된다.

## 대상 단어 입력

유형별 입력칸 수는 다음과 같다.

| 유형 | 칸 수 | 최소 입력 |
| ---- | ---- | ---- |
| 단어 설명 | 1 | 1 |
| 예문 만들기 | 2에서 시작, 동적 | 1 |
| 이항 공통점/차이점/유사성 | 2 | 2 |
| 연상 | 1 | 1 |
| 삼항 격리 | 3 | 3 |
| 관계 짓기 | 3 | 3 |

관계 짓기(`NamedAssociation`)는 `word1`에서 `word2`로 향하는 유향 관계에 `word3`이라는 이름을 붙인다.
지시문은 `두 단어와 둘을 잇는 관계를 나타내는 단어를 적으세요.`이며, 탐색에는 출제하지 않는다.

- 세 칸을 한 줄에 `단어 1 ── 관계 ──▶ 단어 2` 순으로 놓아 유향임을 드러낸다.
  저장 순서는 word1, word2, word3(관계 이름)이지만, 화면과 포커스 순서는 word1 → word3 → word2다.
- 답안란이 없다. 세 단어 모두가 관계의 구성요소이기 때문이다. 참고사항만 남는다.
- 세 단어가 모두 차 있을 때(공통 규칙대로 서로 달라야 한다) 참고사항에서 Enter를 치면 제출된다.
  참고사항은 비어 있어도 된다. 단어 칸의 Enter는 공통 규칙대로 다음 칸으로 포커스만 옮기므로,
  word3에서 Enter를 쳐도 제출되지 않고 word2로 넘어간다.
- 관계 목록에서는 문제 열에 word1, word2를, 응답 열에 word3을 표시한다.
- 동일한 (word1, word2, word3) 조합의 관계 짓기가 이미 있으면 제출을 막고
  `이미 있는 관계입니다` error 토스트를 띄운다. [저장 공통 규약](../저장-공통.md)의
  "내용 기반 중복 제거를 하지 않는다" 원칙에 대한 관계 짓기 한정 예외다.
  - 참고사항은 비교에서 제외한다. 참고사항만 다른 재제출도 차단된다.
  - 유향 관계이므로 word1과 word2를 뒤집은 조합은 별개의 관계로 저장할 수 있다.
  - 관계 수정 페이지에도 같은 규칙이 적용되되, 자기 자신은 중복으로 치지 않는다.
    참고사항만 고치는 수정은 허용된다.

예문 만들기만 칸 수를 동적으로 조절한다.

- 처음에는 2칸이며, 두 번째 이후의 placeholder에만 `(optional)`이 붙는다.
- 마지막 칸이 비지 않은 상태로 포커스가 칸 밖으로 나가면(blur) 다음 칸을 추가한다.
  - 마지막 칸에서 Enter나 추천 선택으로 확정한 경우, 포커스는 새로 추가된 칸으로 간다.
  - Tab이나 클릭으로 나간 경우에는 포커스를 옮기지 않는다.
- k번째(k > 1) 칸이 **이미 빈 상태에서** 백스페이스를 눌렀다 release하면,
  포커스를 k-1번째 입력기 맨 끝으로 옮기고 k번째 칸을 삭제한다.
  - 백스페이스로 마지막 글자를 지운 그 release로는 삭제되지 않는다(한 번 더 눌러야 한다).
  - 첫 칸은 삭제할 수 없으므로 칸은 항상 1개 이상이다.
- 관계 수정 페이지도 같은 동작을 따르며, 초기 칸 수는 `max(관계의 단어 수, 2)`다.

- 각 칸은 대시보드의 단어 입력기(`WordField`)와 자동완성(`WordSuggestion`)을 쓴다.
- 각 칸 오른쪽에 주사위(🎲) 버튼이 있다. 누르면 DB의 랜덤 단어(`getRandomWords`)를 그 칸에 채운다.
  - 다른 칸에 이미 있는 단어와 현재 칸의 단어는 뽑지 않는다. 채울 후보가 없으면(DB 단어 부족) 아무 일도 하지 않는다.
  - 버튼은 탭 순서에서 제외된 마우스/터치 전용 편의 기능이다. 아래의 키보드 동작 명세를 바꾸지 않기 위함이다.
  - 알려주기 전용이며, 같은 구성을 쓰는 관계 수정 페이지에는 없다.
- DB에 없는 새 단어도 입력할 수 있다. 제출 시 `createWord`로 만들어지며, 이미 있으면 기존 단어를 재사용한다.
- 비어있지 않은 단어들은 서로 달라야 제출할 수 있다. 같은 단어끼리의 관계는 퇴화 관계이기 때문이다.
- 단어는 **입력한 순서 그대로** 저장한다. 탐색의 순서 무작위화는 기계 출제의 선입견 편향을 막는 규칙이므로,
  사용자가 명시적으로 지정하는 알려주기에는 적용하지 않는다.
- 필수가 아닌 칸은 placeholder에 `(optional)`을 넣는다.
- 대상 단어 칸에서 Enter를 눌러도 폼을 제출하지 않는다.
  무응답이 허용되는 유형에서는 단어만 채워도 제출 가능 상태가 되므로, 브라우저 기본 동작대로면
  단어 입력 중 Enter가 의도치 않은 회피 제출로 이어지기 때문이다.
  Enter 제출은 관계의 설명(답안)과 참고사항 입력에서만 동작한다.
- 대상 단어 칸의 키보드 동작은 다음과 같다. 한 칸은 입력칸과 추천 목록을 합친 단위로 다룬다.
  - 추천 목록은 칸 안에 포커스가 있는 동안 열려 있다. Tab으로 입력칸에서 목록 항목으로 넘어가도 닫히지 않는다.
  - 입력칸에서 ArrowDown을 누르면 목록의 첫 항목으로 포커스가 이동한다. 목록 안에서는
    ArrowDown/ArrowUp으로 항목 간을 오가며, 마지막 항목에서 ArrowDown을 누르면 첫 항목으로
    순환한다. 첫 항목에서 ArrowUp을 누르면 입력칸으로 돌아간다. 삭제(x) 버튼은 화살표
    순회에서 제외되고 Tab으로만 접근한다.
  - 입력칸에서 Enter를 누르면 입력한 값을 그대로 확정하고, 목록을 닫고, 포커스를 다음 요소로 넘긴다.
  - 목록 항목에서 Enter를 누르거나 항목을 클릭하면 그 단어로 값을 채우고, 목록을 닫고, 포커스를 다음 요소로 넘긴다.
  - 포커스가 칸 밖으로 나가면 현재 값을 그대로 두고 목록만 닫는다.
  - 다음 요소는 문서 순서상 그 칸 뒤에 오는 첫 포커스 가능 요소다. 마지막 칸이면 답안란으로 이어진다.
  - 포커스 단위와 화살표 동작은 `WordField`+`WordSuggestion`을 쓰는 모든 곳(대시보드,
    개별 단어 페이지, 답안 단어 모드, 단어 대체 모달)에 공통 적용된다(`useSuggestionFocus`).

## 지시문과 답안란

지시문(`getQuestionPrompt`)을 대상 단어 입력칸 위에 표시한다.
답안란은 [탐색 화면](./탐색.md)의 답안란 규칙을 그대로 따른다. 무응답 허용 유형, 참고사항, 범주형의 숫자키/Enter 동작 모두 같다.

- 삼항 격리는 대상 단어가 준비되기 전에는 선택지 대신 `대상 단어를 먼저 입력하세요`를 표시한다.
  선택지 라벨이 입력 중인 단어를 실시간으로 따라간다.

## 탐색과 다른 점

- 건너뛰기 버튼이 없다. 출제된 문제가 없으므로 건너뛸 것도 없다.
- 최소 단어 수(`MIN_WORD_COUNT`) 가드가 없다. 단어를 사용자가 직접 공급하기 때문이다.
- 지시문부터 답안란까지의 높이 고정 규칙을 적용하지 않는다. 유형 변경이 연속 출제가 아니라 의도적 조작이기 때문이다.

## 제출

- 제출 절차는 [탐색 Store](../../설계/저장-탐색.md)의 제출 절차와 같되, 대상 단어를 가장 먼저 `createWord`로 확보한 뒤 문제를 적재한다.
- 알려주기에서 만들어지는 문장의 `source`는 `Taught via NOEMA system teaching, qid=<questionId>`이다.
- 제출 성공 시 대상 단어, 답안, 참고사항을 비운다. 선택된 유형은 유지한다.
