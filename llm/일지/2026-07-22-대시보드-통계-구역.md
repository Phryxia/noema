# 2026-07-22 대시보드 통계 구역

## 문제

총 보유 수와 증가 추이를 보여줘야 하는데, 추이를 매번 전수 스캔으로 계산하면 데이터가 늘수록 대시보드가 느려진다.
추가 시점에 bin별로 누산해두는 방식은 세 가지가 걸린다.

1. Store 6개(`hourDelta`/`hourAcc`/`dayDelta`/`dayAcc`/`weekDelta`/`weekAcc`)가 새로 필요하다. DB 버전을 올려야 한다.
2. 설계상 통계 기록은 단어/문장/문서 저장을 붙잡지 않아야 한다(`await` 금지).
   그런데 저장 직후 `invalidateQueries`가 조회를 띄우므로, 기록이 조회보다 늦으면 방금 넣은 값이 안 보인다.
3. 누적 모드에서 레코드가 없는 bin의 값이 기획에 명시되지 않았다.

## 해결

**1. 마이그레이션.** `DB_VERSION`을 2로 올리고 `switch (event.oldVersion)`에 `case 1`을 얹었다.
`break`가 없으므로 신규 사용자(`oldVersion` 0)는 `case 0`을 지나 `case 1`까지 실행된다.
Key Path는 `beginDate`(`Date`)다. Indexed DB는 `Date`를 유효한 키로 다루고 시간순 정렬도 그대로 되므로 별도 인덱스가 필요 없다.

**2. 순서 보장.** `recordCreation(db, kind)`을 `async`가 아닌 **동기 함수**로 만들었다.
호출되는 즉시 `readwrite` 트랜잭션을 열고, 실제 쓰기는 `void`로 흘려보낸다.
`createWord`는 자기 트랜잭션이 커밋된 직후 이것을 호출하므로, 트랜잭션 생성 순서가 확정된다.
Indexed DB는 범위가 겹치는 트랜잭션을 생성 순서대로 실행하므로 이후 어떤 조회도 이 기록 뒤에 놓인다.
`async`로 두면 `openNoemaDB()`를 `await`하는 사이 조회 트랜잭션이 먼저 열릴 수 있어 경합이 생긴다.

기록 트랜잭션 범위에 `wordMeta`/`sentences`/`documents`도 넣었다. `acc`에 쓸 총 보유량을 같은 트랜잭션에서 읽어야 하기 때문이다.

**3. 결측 bin.** `delta`는 0, `acc`는 직전 값 이어받기로 정했다. 근거는 [통계 구역 설계](../../설계/화면-대시보드-통계구역.md)에 적었다.
`acc`는 노출 구간 시작 이전의 마지막 레코드가 초기값으로 필요해서, `upperBound(시작bin, true)`에 `prev` 커서로 1건을 더 읽는다.

**그 외.** Chart.js는 v4라 `LineController` 등 필요한 요소만 `Chart.register`했다.
`useGrowthChart`가 인스턴스 수명(생성/파괴)과 데이터 갱신을 각각 다른 `useEffect`로 나눠 들고 있어, 필터를 바꿔도 차트를 다시 만들지 않는다.
단어/문장/문서 세 계열의 라벨과 색은 `CountSeriesList` 하나에서 나오며, 총 보유 수 표시도 같은 상수를 쓴다.
