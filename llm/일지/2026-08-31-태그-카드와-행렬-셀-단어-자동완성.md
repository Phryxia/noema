# 2026-08-31 태그 카드와 행렬 셀 단어 자동완성

## 문제

문장 입력기 tags, 문서 입력기 tags, 도구의 다국어 매핑, 일본어 매핑에서 단어 검색(추천 목록)이 없었다. 일반 단어 입력기처럼 접두사 추천이 뜨고 항목 선택 시 값이 채워져야 했다(제출 제외). 사용자 결정으로 행렬에서는 추천 목록이 떠 있을 때만 ArrowDown이 목록 진입이고, 4곳 모두 x(단어 삭제) 버튼은 없다.

## 해결

코드 지점은 2곳이었다. 태그 카드는 `extraction/WordCard`(문장·문서 입력기가 `TagEditor`로 공유), 행렬 셀은 `tools/i18n/MatrixField/MatrixCell`(두 도구가 공유).

- 공용 래퍼는 뽑지 않았다. `WordField + WordSuggestion + useSuggestionFocus` 결선이 이미 6곳 반복이지만, 이번 2곳은 요구가 이질적이었다(인라인 카드의 분할/병합 키 vs 행렬 키 배분과 position 콜백). 래퍼를 만들면 `WordField` props 전부를 터널링해야 해 이득이 없다고 판단했다. 기존 6곳 리팩터링은 요청 범위 밖이라 하지 않았다.
- `WordCard`에 opt-in `hasSuggestion` prop을 더했다. `WordExtractor` 호출부는 미전달이라 무변경이고 `TagEditor`만 켠다. ArrowDown 슬롯이 비어 있어 `WordField.onArrowDown`으로 목록 진입을 받았다. `computeHorizontalNavigation`이 좌우만 판정하므로 카드의 `onKeyDown`과 이중 발화가 없다.
- `MatrixCell`은 `onArrowDown`을 쓰지 않고 자체 keydown에서 배분했다. `WordField`가 `onKeyDown`을 먼저 부르고 `onArrowDown` 분기를 별도로 타므로, 둘을 같이 주면 목록 진입과 아래 행 이동이 이중 발화한다. 목록 가시 판정은 `suggestionRef.current !== null` 런타임 검사다. `WordSuggestion`이 안 보일 조건이면 `return null`이라 ref가 null이 되므로, 새 상태·prop 없이 keydown 시점에 "목록이 실제로 떠 있는가"를 안다.
- 헤더 행은 자동완성에서 제외했다(`!isFixedHeader && !!rowIndex`). 다국어의 편집형 헤더는 언어 이름 칸이라 단어 추천이 어울리지 않고, 일본어 헤더는 애초에 `<strong>`이다.
- x 버튼 제거는 `isDeletable={false}`로 충분했다. `requestDelete`가 불릴 수 없어 `WordReplaceDialog`(내부 input) 경로가 막히고, `focusCell`의 `querySelectorAll('input')` 평면 인덱스도 안전하다(목록 항목은 button).
- 인스턴스 비용 완화로 `keyword={isFocused ? value : ''}`를 넘겼다. `enabled: !!throttledKeyword`라 미포커스 카드·셀의 쿼리가 꺼진다. mutation 훅 마운트는 남지만 셀 수십 개 수준에서 수용했다.
- 목록 폭: 인라인 카드·좁은 셀에서 앵커 폭이 좁아 목록이 찌그러지므로 `WordSuggestion.module.css`의 `.root`에 `min-width: max-content`를 더했다. absolute의 left/right over-constrained 규칙으로 right가 무시되어 오른쪽으로 자란다. 기존 소비처는 내용이 필드보다 좁으면 변화가 없다.
- 스크롤러 잘림: `.scroller`의 `overflow-x: auto`가 `overflow-y`를 auto로 강제해 셀 안 절대배치 목록이 잘렸다. `.scroller:focus-within { overflow-x: visible }`로 포커스 동안만 클리핑을 해제했다. 기각 대안: 포털/`position: fixed`(프로젝트 전례 없음), 셀 포커스 상태를 `MatrixField`로 리프트해 클래스 토글(배관이 커서 보류. focus-within이 문제 되면 이 대안으로).
- 추천 선택은 `focusField()` 먼저, `onChange` 나중이다(포커스가 상태 갱신보다 먼저 규칙). 행렬 선택은 `onChange(position, word)`로 `applyCellChange`(sanitize) 경로를 그대로 탄다.

검증: vitest 164개 무손상(=Enter/Tab/ArrowDown 폴스루 의미 보존), tsc·eslint·prettier 통과. playwright로 21개 항목 확인 — 4곳 모두 목록 표시·선택 치환·포커스 복귀, x 버튼 부재, 태그 카드의 Enter 분할 유지, 행렬의 목록 유무에 따른 ArrowDown 배분, Tab 이동 유지, 헤더 행 추천 없음, 마지막 행 목록 비잘림(`elementFromPoint` 판정).

## 남은 것

- 행렬이 뷰포트보다 넓어 가로 스크롤된 상태에서 셀 포커스 시 overflow가 풀려 레이아웃이 흔들릴 수 있다. 통상 열 수(2~3열)에서는 스크롤이 없어 관찰되지 않았다.
- `WordSuggestion`은 `isDeletable={false}`여도 삭제용 useMutation 2개와 `useGuardedWordDeletion`을 마운트한다. 인스턴스가 훨씬 많아지면 삭제 관련 훅 분리를 검토한다.
