# 통계

대시보드 통계 구역. 총 보유 수 4종(단어·문장·문서·관계)과 시간 단위별 증가 추이 차트. 추이는 매번 전수 스캔하지 않고 추가·삭제 시점에 bin별로 누산한다.

## 코드

- 저장 계층: `packages/client/src/db/countLog/`(`types.ts`: `CountKind`·`TimeUnit`·`ChartMode`·`CountLog`, `consts.ts`: `CountKinds`·`CountStores`, `binning.ts`: `getBinDate`·`shiftBin`·`createLog`, `backfill.ts`: `clearAndBackfillCountLogs`)
- 화면 계층: `packages/client/src/statistic/`(`statistic.service.ts`: `getTotals`·`recordCreation`·`recordDeletion`·`getCountLogs`, `consts.ts`: 노출 bin 수·라벨·계열 색·`CountSeriesList`, `utils.ts`: `createBins`·`formatBinLabel`·`invalidateStatisticQueries`, `types.ts`: `CountSeries`)
- 컴포넌트: `statistic/Statistic/`, `TotalCounts/`, `GrowthChart/`(`GrowthChart`가 조회 1회, `CountChart` 4개가 나눠 씀, `useCountChart.ts`)
- 마이그레이션 훅: `db/openNoemaDB.ts`의 `RELATION_COUNT_VERSION` 분기

## 사양

- 총 보유: 단어는 `wordMeta.wordSize`, 나머지는 `count`. 관계는 `relations` 전체다. 갱신은 각 항목 추가·삭제 시와 접속 시.
- 추이 Store: `hourDelta`/`hourAcc`, `dayDelta`/`dayAcc`, `weekDelta`/`weekAcc`. Key Path는 bin 시작 시각 `beginDate`(`Date`, 시간은 00~23시, 일은 0시, 주는 일요일, 브라우저 시간대). 레코드는 `beginDate` + 종류별 수.
- `delta`는 bin의 **순증감**(추가 +1, 삭제 -1, 음수 가능), `acc`는 bin에서 마지막으로 관측된 총 보유량 스냅샷(삭제 직후에도 덮어써 총 보유와 어긋나지 않는다). 존재하지 않는 항목의 삭제 시도는 기록하지 않는다(`count(key)`로 확인).
- 기록은 원래 조작의 트랜잭션이 커밋된 직후 동기적으로 열고 결과를 기다리지 않는다(`recordCreation(db, kind, amount)`, `recordDeletion`). 기록 트랜잭션 범위에 원본 Store도 포함해 `acc`용 총 보유량을 같은 트랜잭션에서 읽는다.
- 백필: v1→2와 v9 미만(`relationCount` 필드 추가분) 업그레이드에서 통계 Store를 비우고 `versionchange` 트랜잭션 안에서 재백필한다. 네 Store를 커서로 전수 순회해 `createdAt`을 bin에 집계하고 누적합으로 `acc`를 만든다. 레코드 없는 bin은 쓰지 않는다. 이미 삭제된 항목은 세지 않으므로 과거 `delta`는 실제보다 작을 수 있으나 `acc`의 마지막 값은 현재 총 보유와 일치한다.
- 결측 bin: `delta`는 0, `acc`는 직전 값 이어받기(시작 bin 미만을 역방향 커서로 1건 더 읽음), 없으면 0.
- 차트: Chart.js v4(필요 요소만 `register`), 선형 보간 선 차트. 시간 단위 `select`(1시간 24개 / 1일 28개 / 1주 52개)와 모드 `select`(변화량 / 누적)를 네 차트가 공유. 종류별 차트 4개를 한 행에(`flex-wrap`, `flex: 1 1 14rem`), 종횡비 `2 / 1.3`. 변화량은 `증가`(양수부)·`삭제`(음수의 절댓값) 두 계열, 누적은 `보유` 한 계열. 관계는 `hasDeletion`이 거짓이라 `증가`만. `증가`/`보유`는 종류별 색, `삭제`는 공통 붉은색.

## 결정 근거와 제약

- 삭제를 무시하던 원래 사양은 누적 마지막 값과 총 보유가 벌어져 무너졌다. 순증감 + `acc` 스냅샷이 Store를 늘리지 않고 삭제를 반영하는 값이다. 같은 bin의 추가 3, 삭제 1은 `delta` 2로만 남는다.
- 관계 모집단이 `relations`인 이유: 문제는 저장하지 않고, 목록 화면도 `relations`를 본다.
- `recordCreation`이 동기 함수인 이유, `void` 백필의 순서 보장, `getAll` 대신 커서: [저장개발참고](../참고/저장개발참고.md#트랜잭션).
- `RELATION_COUNT_VERSION = 9`(8이 아님): 8은 개발서버 HMR로 재백필 없이 소모된 번호다. [저장개발참고](../참고/저장개발참고.md#마이그레이션)
- 결측 `acc`를 0으로 떨어뜨리면 톱니가 되어 누적의 정의에 어긋난다. 기획의 "없는 값은 0"은 데이터 시작 이전 구간에 대한 규정으로 읽는다.
- 한 차트에 네 종류를 겹치면 단어가 나머지를 바닥에 누른다. 세로로 쌓으면 화면 세 개 분량이라 한 행 배치. `flex-basis`는 18rem에서 14rem으로 줄여 한 줄 4개, 종횡비 2는 세로가 답답해 1.3배.
- 저장 계층 지식을 `db/countLog/`로 내린 이유: `openNoemaDB`가 `statistic/`을 값 import 해 `db <-> statistic` 양방향이었다. `CountKinds`는 `db/countLog/consts`가 리터럴로 갖고 `statistic/consts`가 `Record<CountKind, CountSeries>`로 파생한다. `migrations/`로 옮기지 않은 이유는 `types`/`consts`/`binning`을 상시 경로가 쓰기 때문. 전이 의존자 수는 줄지 않았다([분석/의존성-병목](../분석/의존성-병목.md)).
- `rebuildCountLogs`는 커밋되지 않은 로컬 버튼을 전제로 남은 유령 함수였다. 커밋되지 않은 코드를 전제로 한 할 일은 체크 시 코드를 확인한다.

## 알려진 함정

- flex 자식 `min-width: 0`이 없으면 canvas가 줄어들지 않는다. `.pico h3` specificity. [UI개발참고](../참고/UI개발참고.md#레이아웃-함정)
- 백필 경로는 `DB_VERSION`을 올리지 않으면 실행되지 않아 런타임에서 검증할 수단이 없다. 마이그레이션 검증은 [검증참고](../참고/검증참고.md#브라우저-검증-playwright).
