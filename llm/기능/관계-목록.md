# 관계 목록

`/relations`. 모든 관계를 한 표에 시간순으로 보이고, 문자열 검색(`q`)과 유형 필터(`types`)로 좁힌다. 공통 헤더의 `관계` 링크로 들어간다. 유형/문제/응답/참고/날짜 표(`QnaTable`)는 개별 단어의 `연관 관계`와 배치 결과 표가 쓴다.

## 사양

- 표: 단어 관계·추출 관계·문서 제목·태그를 가리지 않고 `createdAt` 내림차순. 열은 ID(개별 관계 링크, 행의 다른 곳은 이동 없음) / 유형 라벨(`문장 추출`, `문서 제목`, `단어 추출`, `태그` 포함) / 대표 표현 / 생성 시각(`YY-MM-DD HH:mm`). 기간 폼·네비게이터·`from`/`to`/`page`·캐싱은 [최근-목록](./최근-목록.md)과 같다.
- **대표 표현**: 저장하지 않고 유형별 토큰으로 만든다. `[w1]: [답]`(단어 설명), `[w1] - [w2]`(속성), `[w1] ∩ [w2] = [답]`(공통점), `[w1] ↔ [w2] = [답]`(차이점), `|[w1] - [w2]| = 정도 라벨`(유사성), `[w1] ~ [w2]`(연상), `[비선택], [비선택] ↔ [선택]`(삼항 격리), `[w3] = [w1] + [w2]`(삼항 합성), `[w1] ──[w3]─→ [w2]`(관계 짓기), 문장 추출·문서 제목·단어 추출은 `[자식]` 70% + `from [부모]` 30%(문서 제목은 `[제목 문장] from [문서 제목]`이라 같은 글자가 두 번 보인다), 태그는 `[문장/문서]` 30% 고정 + ` ~ [단어]`. 예문 만들기는 답 문장 전체를 링크로 두고 문장 안의 대상 단어를 기울임·굵은 단어 링크로 바꾼다(같은 위치는 긴 단어·앞선 위치 우선, 모두 링크). 답이 문장이 아니면 `(답변 회피)` 또는 `[단어 답]`, 삭제된 문장은 `(삭제됨)` 뒤에 `, 원 단어: [w1], [w2]`.
- `[답]`은 단어/문장 링크, `null`이면 회색 `(답변 회피)`. 삭제된 대상은 링크 없이 회색 `(삭제됨)`. 참고사항은 넣지 않는다. 문서 링크 라벨은 제목 앞 48자이고 제목이 없는 문서는 링크 안에 회색 `(제목 없음)`(`ResolvedRefToken.isUntitled`). 문장/문서 링크만 줄어들며 줄임표, 단어 링크와 기호는 줄지 않는다.
- **포함 유형**: 라벨 뒤에 고른 유형마다 `select` 뱃지 + `x`, 끝에 `유형 추가` 빈 `select`(14종 다 고르면 숨김). 고른 유형은 다른 `select`에 안 나온다. 뱃지는 초안이며 `찾기`/`검색`으로 적용되어 `?types=A,B`로 쓰인다. 알 수 없는 유형은 무시, 중복은 한 번, 잘못된 값도 URL에 둔다. 뒤로가기로 `types`가 바뀌면 초안도 따라온다. `q` 검색 중에도 보이고 결과에도 걸린다. `찾기`로 유형이 바뀌면 `page`를 지운다. 필터가 걸린 히스토리는 커서를 `advance` 없이 걸으며 통과 행만 센다.
- **검색**: 제목 아래 입력칸 + `찾기`. 검색 중에는 기간 폼·표·네비게이터를 `hidden`으로 숨긴다(언마운트 아님). `q`는 URL에, `from`/`to`/`page`/`types`와 공존. `q`가 있는 채 진입하면 자동 검색. 1자 이상이면 활성(공백도 글자), 포커스 중 추천기(삭제 버튼 없음, 선택은 입력만 채우고 검색 안 함), Enter 검색, ESC 취소, 빈 문자열이면 즉시 취소. 개별 관계로 갔다 삭제로 돌아올 때 `q`를 들고 갔다 복귀(`search: true`).
- **판정**: word(`wordId`, `wordIds` 원소)·word1·word2·word3·answer·comment를 해석된 문자열로 비교. 연상·속성의 답은 word2, 삼항 합성의 답은 word1/word2로 판정(저장 필드 기준). 유사도·`selection`은 제외, 빈 문자열은 불일치. `정확히 일치`와 `부분 일치`(연속 부분문자열) 두 섹션, 서로소.
- **정렬**: 필드 순위 word → word1 → word2 → word3 → answer(단어) → answer(문장) → comment(단어) → comment(문장). 정확: 순위 → `createdAt` 내림차순 → `relationId` 내림차순. 부분: 매치 값 길이 오름차순 → 사전순 → 순위 → 이하 같음.
- **표시**: 두 섹션은 독립 조회, 로딩 표시는 1개만, 빈 섹션 숨김, 둘 다 비면 `일치하는 내용이 없습니다.`. 전체 결과를 메모리에 두고 10건씩 탐사형 네비게이터. 새 검색·`types` 변경 시 1페이지로. 대표 표현의 단어/문장 링크 라벨에서 검색어 부분을 `mark`. 히스토리 표에는 강조 없음. 검색 결과는 검색어별 5분 캐시, 유형은 메모리에서 거른다.
- 개별 단어의 `연관 관계`는 같은 검색의 정확히 일치 결과를 `QnaTable`(유형/문제/응답/참고/날짜)로 보인다([단어](./단어.md)).

## 결정 근거와 제약

- 대표 표현을 두 단계(토큰 생성은 순수, 해석은 id를 모아 일괄)로 나눈 이유: 어떤 id가 필요한지를 토큰 한 곳만 안다. `usage`·`extraction`·`tag`가 합성 토큰인 이유: 낱개 토큰으로 풀면 각 조각이 flex 아이템으로 따로 줄어든다. 태그가 `extraction` 토큰을 재활용하지 않은 이유: 배치(30% 고정 + `~`)가 다르다.
- 판정이 표시용 헬퍼(`getRelationAnswer`)가 아니라 저장 필드를 직접 보는 이유: 연상의 word2가 표시상 응답이어도 word2로 판정해야 한다.
- 부분문자열 판정은 인덱스를 탈 수 없어 전수 조회 + 메모리 페이징이다. 참고사항으로만 일치한 결과는 강조가 보이지 않는다(규칙은 유지, 문서에 명시).
- `types`를 URL에 쓰되 `/word`에서는 쓰지 않는 것은 사용자 확정이다. 검색 결과 캐시를 검색어별로 두고 유형을 메모리에서 거르는 것도 같다.
- 행 클릭 이동(`RelationRow`)을 쓰지 않고 ID 셀만 링크인 이유: 셀 안에 단어/문장 링크가 많다.
