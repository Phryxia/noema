# 2026-08-16 `/qna` 이관과 문장 반자동 추출

## 문제

관계 목록을 `/relations/w2w`로 옮기고, 문서 페이지에서 본문을 문장 카드로 잘라 다듬은 뒤 일괄 제출하는 편집기가 필요했다.
문서가 길 수 있어 카드 상태를 배열 splice로 다루지 않기로 했고(사양: 연결 리스트),
카드 사이 병합·3연속 개행 분할·빈 카드 삭제 뒤에 포커스와 캐럿을 정확한 자리에 놓아야 했다.
문서/문장 페이지의 관계표와 `/relations/d2s` 히스토리는 기존 `QnaTable` 계열과 열이 달라 그대로 쓸 수 없었다.

## 해결

- 라우트 파일을 `git mv routes/qna.tsx routes/relations.w2w.tsx`로 옮기고 `createFileRoute`/`getRouteApi`/헤더 링크/삭제 후 복귀 경로를 바꿨다.
  `routeTree.gen.ts`는 개발서버가 꺼져 있어 `@tanstack/router-generator`의 `Generator`를 직접 돌려 재생성했다(플러그인과 동일 출력).
- 카드 상태는 `sentenceCardList.ts`의 순수 함수(`createSentenceCardList`/`listCards`/`updateCardValue`/`mergeWithPrevious`/`splitCard`/`removeCard`)로,
  `{ headId, nodes: Map<id, {id, value, prevId, nextId}>, nextId }`를 불변으로 다룬다. id가 안정적이라 React key로 쓰고 `SentenceCard`는 `memo`,
  훅(`useSentenceCards`)의 핸들러는 `listRef`를 읽는 `useCallback`이라 값이 바뀐 카드만 다시 그린다. vitest로 검증했다.
- 포커스 이동은 `SubjectWordFields.removeWord`처럼 `flushSync` 뒤 ref Map의 textarea에 `focus()`+`setSelectionRange()`.
  Backspace는 `WordField`처럼 keydown에서 `'merge' | 'remove'`를 판정해 keyup에서 실행한다(IME 조합 중 무시).
- 분할은 `onChange` 값이 `\n\n\n`을 품으면 그 자리에서 쪼갠다. 사양의 "포커스 시점 값과 비교"는 카드가 3연속 개행을 품은 채 남지 않으므로 `includes`와 같다.
  사용자 확답으로 뒤 조각이 비면 앞 조각만 즉시 trimming하고 새 카드는 만들지 않는다.
- `SentenceField`에 `rows`(있으면 CSS `compact`로 `min-height` 해제)·`textareaRef`·`onKeyDown`/`onKeyUp`/`onFocus`를 더해 카드가 재사용하게 했다.
  대시보드 입력기와 공백 시각화·탭 삽입이 같아진다.
- 관계표는 `QnaSearchSection`을 `shared/PagedSection`(`renderTable` 주입)으로 일반화해 `WordRelations`/`QnaSearchResults`/`DocumentSentences`/`SentenceDocuments`가 함께 쓰고,
  "링크가 아닌 곳을 누르면 관계 페이지로" 행 로직은 `relation/RelationRow`로 뽑아 `QnaTable`과 `D2sTable`이 공유한다.
- 최초 분할 정규식은 `.`이 `\r`을 줄바꿈으로 봐서 CRLF 문서의 본문을 통째로 잃는 것을 테스트로 발견해, 매칭 전에 `\r\n?`을 `\n`으로 정규화했다.

## 남은 것

- `/relations/d2s`에는 문자열 검색이 없다.
- 개별 문장 페이지의 `연결된 문서` 구역은 비어 있으면 숨긴다. 단어 페이지의 `연관된 관계가 없습니다.`와는 다른 선택이다.
- 같은 날 후속: 카드 사이 `병합` 버튼은 보기 좋지 않아 지우고 키보드 병합만 남겼다. 조작법을 헤더 아래 `small`로 적고, 카드 높이는 CSS `field-sizing: content`로 내용에 맞춘다(`rows=1` 최소, JS 없음).
