# 입력기

단어·문장·문서 입력기가 공유하는 폼 로직, 출처 입력기, 공백 에코, 버튼 행, 메타 정보 그리드. 개별 입력기의 사양은 [단어](./단어.md), [문장](./문장.md), [문서](./문서.md)에 있다.

## 코드

- 디렉토리: `packages/client/src/writer/`, `packages/client/src/meta/`
- 폼 훅: `writer/useWriterForm.ts`(draft, dirty 판정, 저장·삭제 mutation, 이탈 질의, `confirmSave`, `onSaved`, `resetKey`)
- 부품: `writer/SourceField`, `writer/WhitespaceEcho`, `writer/WriterActions`(저장/수정/삭제 버튼 행), `writer/insertTabIfPressed.ts`, `writer/checkIsBodyChanged.ts`
- 모드: `writer/types.ts`, `writer/consts.ts`(`WriterModes`, `TextWriterModes`, `SentenceOnlyModes`, `WordOnlyModes`)
- 메타: `meta/MetaFields/MetaFields.tsx`
- 관계 영향 질의: `relation/confirmRelationImpact.ts`, `relation/countReferencingRelations.ts`
- 입력 원자: `word/WordField`, `sentence/SentenceField`([입력-포커스참고](../참고/입력-포커스참고.md#공용-부품))

## 사양

- 모든 입력기의 폰트는 고정폭이다. 전각 문자의 폭이 일정하고 반각은 그 절반이어야 공백 에코가 정렬된다.
- `useWriterForm`: draft는 `{ value: string }`을 포함하는 레코드(문장 `{ value, source, tags }` 등). `canSave`는 편집 가능 + 완성 판정(`checkIsComplete`, 기본 `value` 비어 있지 않음, 문서는 제목까지) + 초기 draft와 다름(배열은 원소별 비교) + 저장 중 아님. 생성 모드는 저장 성공 시 draft를 초기화하고 `resetKey`를 올린다. 수정 모드는 유지한다.
- **미저장 수정 이탈 질의**: 수정 모드에서 `canSave`인 채 이탈하면 `수정된 내용을 저장할까요?` confirm. 확인이면 저장 후 이탈, 취소면 그대로 이탈한다. 어느 쪽이든 이탈은 허용한다(`shouldBlockFn`이 항상 `false`). 삭제 성공 후 메인으로 나갈 때는 묻지 않는다.
- **관계 영향 질의**: 수정 대상을 참조하는 관계가 1건 이상이면 저장 직전에 `연결된 n건의 관계도 수정됩니다. 계속하시겠습니까?`. `n`은 중복 없는 관계 수(한 관계가 문제와 답으로 이중 참조해도 1건). 취소면 아무것도 바꾸지 않고 성공 토스트도 없다. 단어(항상), 문장(수정 모드, 본문·출처가 바뀐 경우)에 적용하고 문서와 개별 관계 페이지에는 적용하지 않는다. `confirmSave` 옵션이 수정 버튼과 blocker 양쪽 저장 직전을 거른다.
- `WriterActions`: 저장/수정·삭제 버튼 행. `form`의 마지막 자식이며 `position: sticky; bottom: 0`이라 폼 아래쪽이 화면 밖이면 화면 bottom에 떠 있고, 자연 위치가 보이면 제자리, 위로 지나가면 내용과 함께 올라간다. 카드 배경색을 갖고 앞 형제의 1rem 여백을 padding으로 흡수한다. z-index 층위는 [UI개발참고](../참고/UI개발참고.md#레이아웃-함정).
- `SourceField`: 한 줄 `input`, 선택 입력, 빈 값은 저장 시 키를 지운다. `isEditable`로 읽기 전용.
- `WhitespaceEcho`: 입력칸 위 절대배치 오버레이. 공백은 마커, 나머지는 `color: transparent`로 자리만 차지. `scrollLeft`를 `translateX`로 동기화. `/([ \t])/` 캡처 split이라 결합 문자·서로게이트 페어가 span 경계에서 갈라지지 않는다. `aria-hidden`.
- `MetaFields`: `{ label, value }[]`를 `label` + `input[readOnly]` 그리드(`repeat(auto-fit, minmax(12rem, 1fr))`)로. `Date`는 `ko-KR`, `undefined`는 `없음`. 값은 드래그 복사 가능.
- 모드 선택: 대시보드는 `단어`/`문장`/`문서`, 탐색·알려주기 답안은 `TextWriterModes`에서 유형이 허용하는 부분집합(`SentenceOnlyModes`, `WordOnlyModes`). `shared/RadioGroup`을 쓰고 한 화면에 그룹이 둘이면 `name`을 달리 준다.

## 결정 근거와 제약

- Field(표현)와 Writer(저장 로직)를 가른 이유: 탐색 답안란이 같은 입력칸을 쓰되 저장 버튼·중복 검사는 필요 없었다. `WordSuggestion`도 Field 밖에 둔다. `WordWriter`의 `fieldset[role=group]` 배치가 깨지기 때문이다.
- 이탈 질의가 이탈을 항상 허용하는 이유: 확인이든 취소든 이탈 자체는 막지 않는 것이 기획이다.
- 관계 영향 질의가 생긴 경위: 단어 페이지의 미저장 수정 + 이탈 승인이 전역 개명을 실행했고, 그 병합 confirm이 관계 화면 전환 시점에 떠서 관계 수정 사고처럼 보였다. 질의는 mutation 시작 전에 거른다.
- `useWriterForm`의 `setDraft`가 `Dispatch<SetStateAction>`인 이유: 태그 카드처럼 자식이 함수형 갱신을 올려야 루프 없이 정규화된 값을 전달할 수 있다.
- 태그만 바뀐 저장이 관계 영향 질의를 건너뛰는 판정은 `checkIsBodyChanged`다. 본문·출처가 그대로면 update도 건너뛰어 `modifiedAt`을 건드리지 않는다.
- 개별 관계 페이지에는 이탈 질의가 없다. 관계 입력은 단어 배열 + 답안 + 참고사항으로 갈라져 `{ value }` draft 전제에 맞지 않는다.
